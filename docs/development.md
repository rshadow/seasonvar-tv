# Локальная разработка

Приложение содержит «Сегодня», «Обновления», «Топ», «Новинки», «Лучшие сериалы», «Настройки» с группой «Сеть» и «О программе». Для публичных списков нужен доступ к Seasonvar; компьютерный сервер, аккаунт и подключение к приставке не требуются.

Все команды запускаются из корня проекта через [Makefile](../Makefile).

Совместимость библиотек описана в [ADR-0060](adr/0060-compatible-dependency-updates.md), переход на AGP 9.5.0, встроенный Kotlin, SDK 37.0 и Build Tools 36.0.0 — в [ADR-0061](adr/0061-agp9-built-in-kotlin-and-sdk37.md). Wrapper пересоздаётся командой `make wrapper` для закреплённой в `gradle-wrapper.properties` версии Gradle. Classpath сборки показывает `make build-environment`; полный граф всех конфигураций создаёт `make dependency-report`, а `make check-resolved-dependencies` проверяет в нём исправленные версии Bouncy Castle, JDOM и обеих разновидностей Guava и входит в `make check`; ограничения исправленных криптобиблиотек описаны в [ADR-0062](adr/0062-patched-build-crypto-dependencies.md), Guava — в [ADR-0063](adr/0063-patched-guava-dependencies.md), JDOM — в [ADR-0065](adr/0065-patched-build-jdom.md). В каждом PR Android CI также выполняет `make build-profile` и сохраняет оптимизированный APK как артефакт `seasonvar-tv-profile` для установки в эмулятор.

После обновления зависимостей выполнять `make check`, `make ci-lint`, `make codeql-build` и `make build BUILD_TYPE=release`; обновлять версии и контрольные суммы соответствующих артефактов в `toolchain.lock.json`.

## Подготовка другого компьютера

Требуются Python 3.12+, make и curl. Для локального эмулятора также нужна доступная аппаратная виртуализация.

~~~bash
make bootstrap
make licenses
make deps
make avd
~~~

`make bootstrap` скачивает зафиксированные инструменты в `.tools`. Это игнорируемые локальные файлы; системный JDK и SDK не заменяются. Архивы берутся из Google и Eclipse Adoptium и проверяются по размерам и контрольным суммам из [toolchain.lock.json](../toolchain.lock.json).

`make licenses` нужен, если лицензии SDK ещё не приняты. При наличии ранее принятых лицензий в пользовательском SDK bootstrap переиспользует их на этом же компьютере.

Подготовлены наборы для macOS Apple Silicon, macOS Intel и Linux x86_64. На Linux могут дополнительно потребоваться системные библиотеки графики/звука и доступ к KVM; их состав зависит от дистрибутива. Windows-разработка отдельно не настроена.

Загрузка занимает примерно 1,5–2 ГБ; распакованные инструменты и образ требуют дополнительного места. Кэш архивов по умолчанию — `~/.cache/seasonvar/downloads`; его можно указать через `BOOTSTRAP_CACHE`:

~~~bash
make bootstrap BOOTSTRAP_CACHE=/path/to/download-cache
~~~

## Посмотреть приложение

В первом терминале:

~~~bash
make emulator
~~~

Откроется окно Android TV. После загрузки во втором терминале:

~~~bash
make run
~~~

По умолчанию используется `emulator-5554`. Если эмуляторов несколько, выбрать нужный из `make devices`:

~~~bash
make devices
make run DEVICE=emulator-5556
~~~

Управление: щёлкнуть в окно эмулятора, затем использовать Enter/OK для выбора. Кнопки приложения также реагируют на клик мышью. В меню стрелки сразу показывают выбранный раздел; OK или стрелка вправо переводят фокус в его содержимое. В ленте стрелки перемещают фокус, OK открывает описание сериала. В полном описании стрелки вверх/вниз прокручивают текст. Esc и «Назад» пульта закрывают описание сериала и возвращают фокус на выбранную карточку в ленте. Из ленты или настроек они возвращают фокус в меню текущего раздела. Два нажатия в пределах 500 мс закрывают приложение; удержание клавиши не считается двойным нажатием. Другая клавиша отменяет ожидание второго нажатия. Стрелка влево из настроек переводит фокус в меню; в «О программе» OK или стрелка вправо выбирают кнопку «Проект на GitHub». Она открывает репозиторий через установленный браузер или другое подходящее приложение. Влево или Esc/«Назад» возвращают фокус в меню; если открыть ссылку невозможно, адрес остаётся видимым для открытия на другом устройстве.

`make avd` настраивает аппаратную клавиатуру и сенсорный ввод для кликов мышью; `make emulator` применяет эту настройку перед запуском. Значения закреплены в `toolchain.lock.json`. Команда запуска также включает `-use-keycode-forwarding`: эмулятор получает коды физических клавиш напрямую. Раскладку для ввода текста в этом режиме выбирают внутри Android. Если окно уже открыто со старой конфигурацией, перезапустить его:

~~~bash
make emulator-restart
~~~

После загрузки в другом терминале выполнить `make run`. Данные эмулятора при перезапуске сохраняются.

Программная имитация пульта:

~~~bash
make key KEY=DPAD_CENTER
make key KEY=BACK
make key KEY=ESCAPE
make key-double KEY=BACK
make key KEY=BACK KEY_ARGS=--longpress
make tap X=400 Y=670
~~~

## Сборка и проверки

| Команда | Назначение |
| --- | --- |
| `make help` | Доступные команды |
| `make doctor` | Версии JDK, Gradle и ADB |
| `make deps` | Подготовка зависимостей и первая сборка |
| `make build` | Debug APK |
| `make release` | Оптимизированный APK с постоянной подписью из `secrets.env` в корне проекта |
| `make release-package` | APK с версией в имени и SHA256SUMS в `build/release` |
| `make ci-prepare` | Инструменты для сборки без эмулятора, принятие SDK-лицензий и зависимости |
| `make ci-lint` | Проверка workflow закреплённым actionlint |
| `make test` | Задача unit-тестов Gradle |
| `make lint` | Android Lint |
| `make check` | Сборка, задача unit-тестов и Lint |
| `make restart` | Перезапуск установленного приложения без сборки |
| `make clean` | Удаление результатов сборки через Gradle |

APK: `app/build/outputs/apk/debug/app-debug.apk`.

В `make test` и `make check` входят 284 JVM-теста парсеров, кэша, сети, моделей состояния и прогресса и 34 автономных Python-теста загрузчика, разбора видеоссылок и упаковки релиза. Интернет и аккаунт им не нужны. Управление и реальную сеть проверяем отдельно в эмуляторе.

При проверке навигации выбрать «Настройки» в меню: сетевые параметры должны появиться сразу. Стрелка вправо или OK переводит фокус на галочку обхода; вниз — на выбор DNS, вверх — обратно. Подзаголовок «Сеть» не должен получать фокус. Аппаратная кнопка «Назад» и стрелка влево из параметров возвращают фокус на «Настройки» в меню без открытия «Сегодня». Отдельно проверить вход мышью, возврат из диалога DNS и переключение разделов стрелками в меню. Одиночные Esc/Back из описания должны восстанавливать фокус на выбранной карточке и позицию ленты, из окна DNS — возвращать в меню настроек; быстрые двойные нажатия — закрывать приложение даже при переходе из диалога в главное окно.

В «Обновлениях» долистать до последней карточки и несколько раз нажать вправо: фокус должен остаться на ней. Вверх переводит фокус на «Обновить», влево с последней карточки — на предыдущую, а влево с первой — в меню раздела. Это общее правило ленты для «Сегодня», «Обновления», «Топ» и «Новинки».

В «Топе» проверить AJAX-выдачу, обновление, метки новинок и описание. После переключения между «Обновлениями» и «Топом» должны сохраняться отдельные выбранные карточки и позиции. После восстановления позиции проверить дальнейшую прокрутку до конца и остановку фокуса на последней карточке. В проверке 2026-11-02 все 49 позиций кэша приложения совпали с отдельно загруженным AJAX-ответом.

В «Новинках» проверить отдельную позицию ленты после перехода через «Топ» и «Обновления», возврат из описания, обновление и остановку на последней карточке. Бейдж определяется меткой сайта: у первой карточки проверенного снимка его нет. В проверке 2026-11-02 все 50 позиций кэша приложения совпали с отдельным AJAX-ответом.

В «Лучших сериалах» проверить отдельную выдачу, количество сезонов вместо номера сезона и краткое описание во время загрузки полного. В проверке 2026-11-02 все 100 позиций кэша приложения совпали с отдельно полученной страницей; проверены описание, Esc, обновление и восстановление позиции после смены раздела.

Меню использует пункты высотой 40dp с промежутком 4dp и прокрутку списка разделов. Проверить доступность всех пунктов стрелками, появление раздела по фокусу, вход вправо и возврат в выбранный пункт. Общие кнопки должны оставаться прямоугольными со скруглением 5dp и не увеличиваться в фокусе. Параметры — в теме по [ADR-0023](adr/0023-compact-rectangular-menu.md).

В ленте проверить соседние короткое и длинное названия: рамки карточек одинаковой высоты, под заголовок отведены две строки, подписи серий выровнены. Миниатюра показывает русское название; панель и полное описание сохраняют также дополнительное название. Высота настраивается через `seasonvar_card_height` в теме — [ADR-0019](adr/0019-fixed-series-cards.md).

Бейдж «новинка» показывается на миниатюре и большом постере только у карточек с меткой сайта. Он не должен получать фокус или мешать открытию описания. В сохранённом AJAX-снимке 10 таких карточек; они также должны сохранять метку при загрузке из кэша.

Для подробного вывода Gradle:

~~~bash
make build GRADLE_ARGS=--info
~~~

## Проверка сохранения прогресса аккаунта

Автоматическая политика описана в [ADR-0056](adr/0056-automatic-account-playback-marks.md). make check проверяет порог 90%, паузу/завершение, ожидание реального просмотра, буферизацию, повтор отправки, смену аккаунта и подтверждение записи автономными фикстурами. Он не выполняет запросов изменения реального аккаунта.

Ручная проверка на выбранном эмуляторе с уже выполненным входом:

~~~bash
make devices
make mark-probe DEVICE=emulator-5554
make mark-probe DEVICE=emulator-5554 MARK_PROBE_MODE=roundtrip
~~~

Первый режим только читает структуру отметки существующей записи «На чём остановились». Второй временно меняет время существующей отметки, подтверждает его чтением и восстанавливает исходное значение; если другой клиент успел изменить отметку, его новое значение не перезаписывается. Инструмент выводит только имена полей/типы и булевы результаты, не личные данные. Неуспешный probe завершает команду с ошибкой. Тестовый APK и runner не входят в публикуемый APK, аккаунт и сеть нужны только для этой явно вызванной проверки.

После изменений плеера отдельно проверить реальное изображение и его движение, паузу, перемотку, переходы между сериями и возврат из плеера. Для диагностики синхронизации debug-тег SeasonvarMark содержит только фазы position_queued/completed_queued/write_verified/already_current/retry_pending/save_failed; в них нет пользователя, серии, позиции, cookie или видеоссылок.

Проверка 2026-11-04: `make check` — 284 JVM-теста, 22 Python-теста, Android Lint; `make build-profile` — успешная оптимизация R8. В авторизованном эмуляторе Android TV API 34 проверены движущееся изображение, пауза, перемотка, следующая/предыдущая серия и возврат к кнопке «Продолжить». Фазы `position_queued → write_verified` и `completed_queued → write_verified` подтвердили сохранение времени на паузе и отметки завершения после 90%; отдельный roundtrip подтвердил POST/чтение и восстановил исходную отметку.

## Проверка удаления из личных списков

Поведение — [ADR-0057](adr/0057-remove-account-list-marks.md). В `make check` входят автономные проверки POST/повторного чтения, отказов и истечения сессии, конфликтов с очередью автосохранения, удержания OK и выбора соседа после удаления. В эмуляторе проверить короткое OK, удержание OK, отпускание без открытия сериала, общий диалог, первый фокус на «Отмена», Назад/Esc и возврат фокуса к миниатюре/кнопке карточки.

Для ручной обратимой сетевой проверки с уже выполненным входом:

```bash
make mark-probe DEVICE=emulator-5554 MARK_PROBE_MODE=delete-roundtrip
```

Этот режим действительно удаляет существующую отметку аккаунта, проверяет отсутствие в личных подборках и восстанавливает исходную отметку. Значение хранится только в памяти Android-процесса; прерывание процесса или сеть могут помешать восстановлению. Если другой клиент изменил отметку во время теста, его значение не перезаписывается. Проверка не входит в CI. Флаги `post_verified`, `removed_from_lists` и `original_restored` должны быть истинными. 2026-11-04 проверка успешно выполнена.

Проверка ADR-0057 от 2026-11-04: `make check` — 284 JVM-теста, 22 Python-теста и Lint без ошибок; `make build-profile` — успешно. В эмуляторе проверены меню, кнопка, подтверждение и отмена, возврат фокуса, движущееся видео и локальное продолжение. Успешный выбор соседа после удаления покрыт автономными тестами.

## Подписанный APK

~~~bash
make release
~~~

Команда собирает оптимизированный `release`, подписывает его и проверяет схемы APK Signature v2/v3 и соответствие сертификата выбранному ключу. Результат: `app/build/outputs/apk/release/app-release.apk`. Отдельный `make build BUILD_TYPE=release` только собирает неподписанный APK; для распространения нужен `make release`.

Секреты подписи берутся только из `secrets.env` в корне проекта, права доступа — `0600`. Файл исключён из Git; перенос на другой компьютер выполняется отдельно от клонирования репозитория — [ADR-0049](adr/0049-project-local-secrets.md). Файл содержит четыре параметра: `SEASONVAR_SIGNING_KEYSTORE_BASE64` (PKCS12 в Base64), `SEASONVAR_SIGNING_STORE_PASSWORD`, `SEASONVAR_SIGNING_KEY_PASSWORD` и `SEASONVAR_SIGNING_KEY_ALIAS`. Поддерживаются строки `KEY=value`, необязательные `export` и внешние кавычки; shell-код и подстановки не исполняются. Генерация ключа — отдельная разовая операция, без цели Makefile. Хранилище загружается в память; отдельный файл ключа не создаётся. Используется библиотека `apksig` из закреплённого Android SDK Build Tools, без новых зависимостей.

При ошибке подписания выходной APK удаляется; секреты и текст исключений не печатаются. Обычные debug/profile-сборки не читают `secrets.env` в корне проекта. Подробности — [ADR-0048](adr/0048-release-apk-signing.md).

Для всех обновлений приложения нужен тот же ключ. Сохранять защищённую резервную копию корневого `secrets.env` отдельно от проекта. Release-подпись отличается от debug/profile: первая установка поверх прежней отладочной версии невозможна без её удаления с потерей локальных данных. Команда `make release` ничего не устанавливает и не меняет данные устройств.

## Автосборка и выпуск на GitHub

Workflow [android.yml](../.github/workflows/android.yml) запускается при push в `main`, pull request, push тега `v*` и вручную через вкладку Actions → Android build → Run workflow. Обычный запуск выдаёт debug APK; `main`, теги и ручные запуски также выдают подписанный `seasonvar-tv-release`. Артефакты доступны на странице запуска в течение 14 дней. Только тег публикует GitHub Release. Принцип — [ADR-0050](adr/0050-github-actions-builds-and-releases.md).

Для первоначальной настройки владелец добавляет один repository secret `SEASONVAR_SIGNING_ENV` в Settings → Secrets and variables → Actions. Значение — четыре параметра подписи из локального `secrets.env`; содержимое не публикуется в репозитории. В CI файл создаётся только на время подписи и удаляется после неё. Для публикации используется встроенный `GITHUB_TOKEN`; личный токен в CI не нужен.

Для выпуска обновить `versionName` и увеличить `versionCode` в `app/build.gradle.kts`, затем проверить локально:

~~~bash
make ci-lint
make check
make release-package
~~~

Результат — `build/release/seasonvar-tv-<versionName>-universal.apk` и `build/release/SHA256SUMS`. После коммита отправить изменения и тег, совпадающий с версией, например для версии `0.3.0`:

~~~bash
git push
git tag v0.3.0
git push origin v0.3.0
~~~

Релизный тег создаётся и отправляется только по явной команде пользователя — [ADR-0053](adr/0053-explicit-release-tag-command.md). Просьба закоммитить изменения или проверить автосборку сама по себе не запускает выпуск.

GitHub соберёт и проверит приложение, подпишет APK и создаст Release с APK и контрольной суммой. Несовпадение тега и `versionName` останавливает выпуск. Теги с суффиксом, например `v0.3.0-beta.1`, помечаются prerelease. Уже опубликованные теги не заменяются; исправление выпускается новой версией.

CI использует закреплённые JDK/SDK из `toolchain.lock.json`; `make ci-prepare` пропускает эмулятор и системный образ. `make ci-lint` загружает actionlint с проверкой размера и SHA256. GitHub Actions закреплены SHA, кэшируются только инструменты и Gradle; `secrets.env` в кэш и артефакты не входит. Проверка видео выполняется отдельно по правилам проекта.

## Логи и отладчик

~~~bash
make logs
make logs LOG_ARGS=-d
make debug
make layout
~~~

`make logs` показывает только процесс приложения, `LOG_ARGS=-d` выводит накопленные записи и завершает команду. `make debug` пробрасывает JDWP на локальный порт 8700 и позволяет подключить JDK-отладчик командой `make attach`.

Для удобной пошаговой отладки можно открыть проект в Android Studio: выбрать Gradle JDK `.tools/jdk` и SDK `.tools/android-sdk`, затем использовать Attach debugger to Android process для `ru.seasonvar.tv`. Android Studio для сборки и работы окна эмулятора не обязателен.

Снимок экрана:

~~~bash
make screenshot OUT=/path/to/menu.png
~~~

## Настройка интерфейса

Цвета, отступы и размеры компонентов задаются в [themes.xml](../app/src/main/res/values/themes.xml). Роли цветов Compose, набор стилей текста и типизированные размеры — в [SeasonvarTheme.kt](../app/src/main/java/ru/seasonvar/tv/ui/theme/SeasonvarTheme.kt). После изменения выполнить `make run`. ## Сеть приложения

Формат пунктов настроек — [ADR-0015](adr/0015-settings-item-format.md): название и пояснение слева, галочка или выбранное значение справа; OK или клик переключает галочку либо открывает список опций.

На общем экране «Настройки» под текстовым подзаголовком «Сеть» расположены две независимые настройки: галочка «Обход блокировок» (по умолчанию включена) и DNS («Системный» / «Quad9 DoH», по умолчанию Quad9 DoH). Они хранятся в приватных SharedPreferences `network`: ключ `dpi_bypass` и строковый `dns_provider` (`system` / `quad9_doh`). Если ключ DNS ещё отсутствует, используется Quad9 DoH; сохранённая галочка остаётся прежней.

Выбор применяется к новым запросам HTML и Coil, а уже открытые списки обновляются. При ошибке сети показывается предупреждение: для «Сегодня» допускается только кэш текущего дня, для «Обновления» — не старше 24 часов. Сертификаты проверяются во всех сочетаниях; детали — [ADR-0011](adr/0011-network-bypass-setting.md) и [ADR-0012](adr/0012-dns-provider-setting.md). Для добавления провайдера расширить `DnsProvider`, UI-название и соответствующий резолвер в `NetworkClients`.

## Получение страниц сайта

`make site-fetch` сохраняет публичную главную Seasonvar в `build/site/index.html` с использованием проверенной DPI-стратегии и Quad9 DoH. `make site-updates` получает подборку «Обновления» отдельным AJAX POST в `build/site/updates.html`, без открытия главной. `make site-top` получает «Топ» через AJAX `mode=pop` в `build/site/top.html`. `make site-newest` получает «Новинки» через `mode=newest` в `build/site/newest.html`. `make site-best` получает отдельную страницу `/?mode=top` в `build/site/best.html`. `make site-scripts` скачивает официальный JavaScript в `build/site/main.js` для проверки запросов подборок; версию можно указать через `SITE_SCRIPT_VERSION` (по умолчанию `25.4.1`). Параметры загрузчика, поиск и результаты проверки — в [docs/api/access.md](api/access.md). Проверки загрузчика запускаются через `make site-test` и входят в `make test` и `make check`.

## Проверка отзывчивости на приставке

~~~bash
make devices
make run-profile DEVICE=<serial>
make profile-navigation DEVICE=<serial> PROFILE_OUT=build/performance/run
make profile-navigation DEVICE=<serial> PROFILE_OUT=build/performance/cpu PROFILE_ARGS='--sample --rounds 1'
~~~

Экран приставки должен быть активен; при необходимости `make key DEVICE=<serial> KEY=WAKEUP`. Для эмулятора использовать его serial, но оценку скорости проводить на целевом устройстве. `profile` — release-конфигурация с R8, читаемыми именами, `debuggable=false`, shell-профилированием и локальной debug-подписью. Она обновляет ту же тестовую установку, сохраняя данные. Для обычной отладки остаётся `make run`. Подход соответствует [рекомендациям Android](https://developer.android.com/studio/profile/build-run-manually).

Сценарий перезапускает только приложение, проходит шесть пунктов вниз и шесть вверх и повторяется три раза. Интервал клавиш и частота CPU-сэмплирования закреплены в `toolchain.lock.json`. Сохраняются запуск, app-only `gfxinfo framestats` и JSON-сводка. При `--sample` дополнительно сохраняется метод-трасса для Android Studio; показатели кадров этого запуска не сравнивать с обычными замерами. Бинарные трассы не коммитить. Сеть остаётся настоящей; при сравнении учитывать кэш, состояние сайта и прогрев. Число кадров в выгрузке может ограничиваться системным буфером, поэтому сводка отдельно содержит `frame_stats_count`.

Первый проход после перезапуска и повторные проходы оценивать отдельно. Распределение появления карточек уменьшает длинные кадры, но увеличивает число промежуточных кадров; доля jank сама по себе не описывает отзывчивость меню. Постоянные 60 fps этим изменением не подтверждены. Поведение и альтернативы — [ADR-0025](adr/0025-responsive-section-switching.md).

После изменения проверить на пульте каждый каталог, вход в ленту, открытие описания и возврат на ту же карточку; затем настройки, поиск и сохранение позиции после смены раздела. Эти сценарии проверены на Ugoos X5M 2026-11-02.

Замер 2026-11-02, Ugoos X5M / Android 14, одинаковый сценарий без CPU-сэмплирования. До изменения уже использовалась оптимизированная профильная сборка; первый проход — после перезапуска приложения с существующим дисковым кэшем.

| Проход | p90 кадра до → после | Максимум до → после | Кадры >100 мс до → после |
| --- | --- | --- | --- |
| Первый | 150 → 77 мс | 242,8 → 128,0 мс | 13 → 2 |
| Повторный 1 | 121 → 44 мс | 157,2 → 93,0 мс | 9 → 0 |
| Повторный 2 | 113 → 36 мс | 143,5 → 79,8 мс | 9 → 0 |

Сравнение не означает улучшения каждой метрики: в последнем проходе число кадров выросло с 81 до 111, медиана — с 9 до 22 мс, число отмеченных системой janky frames — с 13 до 26. Работа распределена по промежуточным кадрам ради уменьшения длинных остановок. Это длительности кадров приложения, а не прямой замер задержки клавиши до изображения. Первая загрузка всё ещё тяжелее повторной. Сборка profile с R8, debug-сборка, 61 JVM-тест, 13 Python-тестов и Android Lint прошли проверку.

## Индикация обновления

Во время загрузки вращается только значок кнопки обновления; сообщение загрузки над описанием не появляется. Статусы ошибки/кэша занимают существующую строку заголовка. Правила — [ADR-0026](adr/0026-refresh-indicator-in-button.md).

Для проверки медленного ответа в эмуляторе: `make emulator-network-delay NETWORK_DELAY=1000`, затем обновить каталог и проверить неподвижность описания и ленты, сохранение фокуса и остановку вращения после ответа. После проверки вернуть исходную задержку: для стандартного эмулятора `make emulator-network-delay NETWORK_DELAY=none`. Эти команды относятся к сети эмулятора, не к системному DNS или приставке.

Проверка 2026-11-02: при задержке сети эмулятора 1000 мс вращение подтверждено последовательными снимками; координаты заголовка выбранного сериала и карточек совпали до и во время обновления, фокус остался на кнопке, видимой строки «Обновляем список…» нет. После завершения запроса последовательные снимки стали идентичны — анимация остановилась. Задержка возвращена к исходным 0 мс.

## Диагностика карточек и плеера на приставке

Сначала `make devices`, затем для диагностики `make run DEVICE=<serial>` и `make logs DEVICE=<serial> LOG_ARGS='-d -s SeasonvarDetails SeasonvarPlayback SeasonvarNetwork'`. Подробные теги доступны в debug-сборке; оптимизированная `profile` их не пишет. В диагностике есть классы причин, HTTP-статус и код Media3, но нет текста исключений, cookie и временных ссылок.

При наличии внешнего ByeByeDPI можно оставить внутренний обход выключенным; DNS приложения — отдельный выбор. Проверять и фиксировать фактические параметры, не считать выключенный внутренний обход признаком неправильной настройки сети.

У первого сезона «Экстрасенсы. Реванш» сайт возвращает явное ограничение страны. Проверить текст причины в карточке, отсутствие неработающего «Смотреть», повторный запрос через «Обновить данные», выбор другого сезона и возврат в исходную ленту. Автономная фикстура очищена от скриптов плейлиста. Обычное открытие карточки использует кэш, явное обновление всегда запрашивает страницу заново.

Регрессия видео: `make site-video-probe SITE_URL=https://seasonvar.ru/serial-15615--Boruto_Novoe_Pokolenie_pscevnu-0-sezon.html` должна вернуть HTTP 206 / MP4. Полный путь видео может содержать скобки, запятые и пробелы; не разбивать его по этим символам. На Ugoos прежняя сборка для первой серии «Боруто» дала `ERROR_CODE_IO_BAD_HTTP_STATUS`, HTTP 404; исправленный разбор проверяется реальным первым кадром, паузой и перемоткой. Сеть приставки: внешний ByeByeDPI, внутренний обход выключен, DNS системный.

Итог проверки 2026-11-02: на Ugoos открыты карточки и запущено видео из «Обновлений», «Топа» и «Лучших сериалов»; проверены стандартный перевод, субтитры и именованный трейлер «Игры престолов». Исправленный «Боруто» показывает изображение в debug- и profile-сборках, реагирует на паузу и перемотку и продолжает с локальной позиции. Ограниченный сезон показывает причину сайта, обновляет данные и позволяет перейти на доступный сезон с воспроизведением. Управление проверено ADB-клавишами. Прошли `make check` (109 JVM-тестов, 17 Python-тестов и Lint) и R8-сборка. На приставку установлена итоговая profile-сборка; внутренний обход выключен, DNS системный.

## Аккаунт и личный список

~~~bash
make account-test
make check
make run DEVICE=<serial>
~~~

Кнопка человека находится справа от поиска. С «Сегодня»: вверх → поиск → вправо → аккаунт → OK. В форме поля логина и скрытого пароля используют штатную IME. Next переводит к паролю, Done отправляет форму; после закрытия IME работают стрелки между полями. Пароль очищается при отправке и уходе с формы, в сохранённое состояние экрана не попадает.

Личные данные вводить непосредственно в приложении. Во время ввода не снимать экран, не выгружать UI-дерево и широкие логи. Cookie и пароль не передавать CLI-параметрами. Настоящие ответы аккаунта не сохранять в фикстуры; для тестов используется синтетический `account-resume.html`.

После входа проверить аватар (или штатную иконку при его отсутствии), все пять личных пунктов меню, загрузку/обновление каждого списка и открытие карточки с возвратом на неё. Затем перезапуск приложения без повторного ввода пароля, отключение сети, восстановление сети и выход: все личные разделы и аватар должны исчезнуть, поздние ответы не должны восстановить сессию. Проверять истёкшую сессию отдельно от пустого аккаунта. Положительный сценарий требует своей учётной записи, автоматические тесты — нет.

Сессия хранится шифрованным блоком в приватных SharedPreferences `account-session`, ключ — Android Keystore. Пароль и логин не записываются. Сайт получает cookie только в пределах исходного домена/пути и HTTPS; медиадоменам они не отправляются. При авторизованной сессии общий дисковый HTML-кэш отключён, личный список живёт в памяти. Локальная позиция видео по ADR-0031 и отметки сайта пока не синхронизируются.

Для аккаунта прошли общий `make check` (138 JVM-тестов, 17 тестов Python, Lint) и R8-сборка. Реальный вход подтверждён пользователем, аватар и личный список проверены на Ugoos; отказ на вымышленные данные проверен в эмуляторе.

2026-11-03 после входа пользователя на Ugoos проверены восстановление сессии без повторного пароля и успешная загрузка аватара. Личный список адаптирован к настоящим `.pgs-marks-el` в `marks-new`/`marks-nonew` по ADR-0034: старого `.pgs-marks-bn` в ответе не было. Для диагностики debug-тег `SeasonvarAccount` показывает только структуру, количество элементов и статус загрузки аватара; личные тексты, значения атрибутов, URL и cookie не выводятся. Синтетическая фикстура `account-resume-current.html` повторяет структуру без данных аккаунта. Прошли `make check` (138 JVM-тестов, 17 Python-тестов, Lint) и `make build-profile` с R8.

В текущем личном списке проверены открытие карточки и возврат Esc на ту же карточку с восстановлением фокуса. Итоговая profile-сборка установлена на Ugoos; вход сохранился после обновления.

Регрессия имени аккаунта: при `alt="avatar"` и видимом имени в раскрывающемся меню страница должна показывать имя; при его отсутствии — «Аккаунт Seasonvar». Пояснение аккаунта относится ко всем личным разделам, без привязки к одному списку. Правило — ADR-0035.

Личные вкладки по ADR-0036 имеют независимые состояния и позиции ленты. `make account-test` проверяет парсеры, сессию, приватный кэш и модели личных списков на синтетических данных. Полный `make check`: 149 JVM-тестов, 17 Python-тестов и Android Lint; `make build-profile` проверяет оптимизацию R8.

2026-11-03 в авторизованном эмуляторе API 34 проверены все пять личных списков, прокрутка меню до нижнего пункта, открытие карточки и возврат Esc, независимый выбор при переключении списков и обновление без исчезновения карточек. Вход сохранён после установки обновления.

Для ADR-0037 прошёл `make check` (151 JVM-тест, 17 Python-тестов, Lint). В эмуляторе проверены отсутствие отметок на миниатюрах, подписанные поля в большой и открытой карточке и возврат Esc на ту же миниатюру.

Для истории просмотров по ADR-0039 прошли `make check` (168 JVM-тестов, 17 Python-тестов, Android Lint) и `make build-profile` с R8. В авторизованном эмуляторе проверены совпадение числа записей с сайтом, сезон и серия на миниатюрах, дата в большой и открытой карточке, обновление, прокрутка меню, переключение разделов и возврат Esc на выбранную карточку. В текущем аккаунте одна страница; несколько страниц, повторы, ошибка и повтор подгрузки, обновление и выход во время запроса проверены синтетическими тестами.

Для ADR-0040–0042 прошёл `make check`: 195 JVM-тестов, 17 Python-тестов и Android Lint. Проверены контекст из истории, главной, AJAX и личных отметок; приоритет источника над локальным продолжением; совпадение ID и названий; стандартная озвучка при несовпадении; недоступная серия; неполные данные; ручной выбор и повтор; поздние ответы для разных записей одного сезона. Исходная модель списка остаётся неизменной.

В авторизованном эмуляторе подтверждены выбор серии из записи истории, автоматический откат к стандартной озвучке при несовпадении названия, переход фокуса к выбранному эпизоду и возврат Esc на исходную карточку. `make build-profile` с R8 также прошёл. Debug-диагностика `selectionContext` выводит только булевы признаки наличия и сопоставления параметров, без номеров серий, названий озвучек и данных аккаунта.

Для ADR-0043 прошли `make check` (211 JVM-тестов, 17 Python-тестов и Android Lint) и `make build-profile` с R8. Проверены сезон отметки вместо числа полностью просмотренных сезонов, отсутствие неизвестных значений, противоречивые записи, смена сезона, загрузка в фоне без сброса ручного выбора и отмена позднего ответа. В эмуляторе API 34 после `make run DEVICE=emulator-5554` проверены оба значения в конце блока управления, единственная подпись прогресса, отсутствие точки фокуса на ней и возврат на карточку ленты через Esc. При длинном названии озвучки прогресс естественно переносится на следующую строку без обрезания. Данные аккаунта и их значения в отчёт не сохранялись.

Для ADR-0045 прошёл `make check`: 216 JVM-тестов, 17 Python-тестов и Android Lint. Через `make run`, `make restart`, `make key` и `make layout` в эмуляторе проверены сохранение первого раздела, отмена выбора, личный раздел после проверки аккаунта и системный раздел после появления личной группы. Пункты остаются видимыми и доступны с D-pad; сетевые настройки сохраняют прежнее управление.

Для ADR-0046 прошли `make check` (225 JVM-тестов, 17 Python-тестов и Android Lint) и `make build-profile` с R8. После `make run DEVICE=emulator-5554` в API 34 проверены реальные серии 1–3: предыдущая/следующая штатными кнопками, управление D-pad, медиаклавиши, быстрые переходы, первая граница, пауза, перемотка и возврат последней серии в карточку. Для безопасной диагностики кнопок debug-событие `SeasonvarPlayback controls` выводит только доступность направлений и тип элемента управления, без сведений аккаунта и видеоссылок.

После любых изменений плеера обязательно открыть реальное видео и визуально проверить видимые кадры, их изменение во времени, паузу, перемотку и возврат. Для кнопок серий проверить изображение после следующей и предыдущей. События `STATE_READY`/`first-frame` не заменяют просмотр: в регрессии ADR-0047 декодирование работало за чёрной заглушкой. Основная проверка выполняется в эмуляторе; приставку используем в рамках запроса пользователя.

Для ADR-0047 прошли `make check` (284 JVM-теста, 17 Python-тестов и Android Lint) и `make build-profile`. В эмуляторе визуально проверены реальные кадры серий 1 и 2 после переходов и смена кадров во время воспроизведения; это проверка изображения, а не только событий декодера. На Ugoos исправление установлено, но последующая проверка остановлена по просьбе пользователя.

## Проверки безопасности GitHub

Конфигурация и ручное включение серверных настроек описаны в [github-security.md](github-security.md), решение — [ADR-0058](adr/0058-github-security-checks.md). `make ci-tools` подготавливает закреплённый инструментарий без предварительной компиляции, `make ci-export-env` передаёт пути JDK/SDK следующему шагу Actions, `make codeql-build` повторно компилирует приложение и Java-утилиту подписи без чтения секретов. `make ci-prepare` сохраняет прежнее поведение подготовки инструментов и зависимостей. Для проверки YAML workflow — `make ci-lint`. Версии новых Actions закреплены в toolchain.lock.json.

Автослияние готовых PR владельца — [ADR-0059](adr/0059-owner-pull-request-auto-merge.md). Политика покрыта автономными тестами make site-test, входящими в make check. После слияния workflow явно запускает проверки main через workflow_dispatch, чтобы сохранить артефакты и граф зависимостей.
