# Локальная разработка

Приложение содержит «Сегодня», «Обновления», «Топ», «Новинки», «Лучшие сериалы», «Настройки» с группой «Сеть» и «О программе». Для публичных списков нужен доступ к Seasonvar; компьютерный сервер, аккаунт и подключение к приставке не требуются.

Все команды запускаются из корня проекта через [Makefile](../Makefile).

Совместимость библиотек описана в [ADR-0060](adr/0060-compatible-dependency-updates.md), переход на AGP 9.5.0, встроенный Kotlin, SDK 37.0 и Build Tools 36.0.0 — в [ADR-0061](adr/0061-agp9-built-in-kotlin-and-sdk37.md). Wrapper пересоздаётся командой `make wrapper` для закреплённой в `gradle-wrapper.properties` версии Gradle. Classpath сборки показывает `make build-environment`; полный граф всех конфигураций создаёт `make dependency-report`, а `make check-resolved-dependencies` проверяет в нём исправленные версии Bouncy Castle, JDOM, jose4j, Apache HttpClient, Commons Lang и обеих разновидностей Guava и входит в `make check`; ограничения исправленных криптобиблиотек описаны в [ADR-0062](adr/0062-patched-build-crypto-dependencies.md), Guava — в [ADR-0063](adr/0063-patched-guava-dependencies.md), JDOM — в [ADR-0065](adr/0065-patched-build-jdom.md), jose4j — в [ADR-0066](adr/0066-patched-build-jose4j.md), HttpClient — в [ADR-0067](adr/0067-patched-build-httpclient.md), Commons Lang — в [ADR-0068](adr/0068-patched-build-commons-lang.md). В каждом PR Android CI также выполняет `make build-profile` и сохраняет оптимизированный APK как артефакт `seasonvar-tv-profile` для установки в эмулятор.

После обновления зависимостей выполнять `make check`, `make ci-lint`, `make codeql-build` и `make build BUILD_TYPE=release`; обновлять версии и контрольные суммы соответствующих артефактов в `toolchain.lock.json`.

## Подготовка другого компьютера

Требуются Python 3.12+, make и curl. Для локального эмулятора также нужна доступная аппаратная виртуализация.

~~~bash
make bootstrap
make licenses
make deps
make avd
~~~

`make bootstrap` скачивает зафиксированные инструменты в `.tools`. Это игнорируемые локальные файлы; системный JDK и SDK не заменяются. Архивы берутся из Google и Eclipse Adoptium и проверяются по размерам и контрольным суммам из [toolchain.lock.json](../toolchain.lock.json).

`make licenses` нужен, если лицензии SDK ещё не приняты. При наличии ранее принятых лицензий в пользовательском SDK bootstrap переиспользует их на этом же компьютере.

Подготовлены наборы для macOS Apple Silicon, macOS Intel и Linux x86_64. На Linux могут дополнительно потребоваться системные библиотеки графики/звука и доступ к KVM; их состав зависит от дистрибутива. Windows-разработка отдельно не настроена.

Загрузка занимает примерно 1,5–2 ГБ; распакованные инструменты и образ требуют дополнительного места. Кэш архивов по умолчанию — `~/.cache/seasonvar/downloads`; его можно указать через `BOOTSTRAP_CACHE`:

~~~bash
make bootstrap BOOTSTRAP_CACHE=/path/to/download-cache
~~~

## Посмотреть приложение

В первом терминале:

~~~bash
make emulator
~~~

Откроется окно Android TV. После загрузки во втором терминале:

~~~bash
make run
~~~

По умолчанию используется `emulator-5554`. Если эмуляторов несколько, выбрать нужный из `make devices`:

~~~bash
make devices
make run DEVICE=emulator-5556
~~~

Управление: щёлкнуть в окно эмулятора, затем использовать Enter/OK для выбора. Кнопки приложения также реагируют на клик мышью. В меню стрелки сразу показывают выбранный раздел; OK или стрелка вправо переводят фокус в его содержимое. В ленте стрелки перемещают фокус, OK открывает описание сериала. В полном описании стрелки вверх/вниз прокручивают текст. Esc и «Назад» пульта закрывают описание сериала и возвращают фокус на выбранную карточку в ленте. Из ленты или настроек они возвращают фокус в меню текущего раздела. Два нажатия в пределах 500 мс закрывают приложение; удержание клавиши не считается двойным нажатием. Другая клавиша отменяет ожидание второго нажатия. Стрелка влево из настроек переводит фокус в меню; в «О программе» OK или стрелка вправо выбирают кнопку «Проект на GitHub». При входе автоматически проверяется последний стабильный выпуск GitHub; для новой версии появляется кнопка «Скачать и установить». Стрелки вверх/вниз переключают её и ссылку GitHub. Ссылка открывает репозиторий через установленный браузер или другое подходящее приложение. Влево или Esc/«Назад» возвращают фокус в меню; если открыть ссылку невозможно, адрес остаётся видимым для открытия на другом устройстве.

`make avd` настраивает аппаратную клавиатуру и сенсорный ввод для кликов мышью; `make emulator` применяет эту настройку перед запуском. Значения закреплены в `toolchain.lock.json`. Команда запуска также включает `-use-keycode-forwarding`: эмулятор получает коды физических клавиш напрямую. Раскладку для ввода текста в этом режиме выбирают внутри Android. Если окно уже открыто со старой конфигурацией, перезапустить его:

~~~bash
make emulator-restart
~~~

После загрузки в другом терминале выполнить `make run`. Данные эмулятора при перезапуске сохраняются.

Программная имитация пульта:

~~~bash
make key KEY=DPAD_CENTER
make key KEY=BACK
make key KEY=ESCAPE
make key-double KEY=BACK
make key KEY=BACK KEY_ARGS=--longpress
make tap X=400 Y=670
~~~

## Сборка и проверки

| Команда | Назначение |
| --- | --- |
| `make help` | Доступные команды |
| `make doctor` | Версии JDK, Gradle и ADB |
| `make deps` | Подготовка зависимостей и первая сборка |
| `make build` | Debug APK |
| `make release` | Оптимизированный APK с постоянной подписью из `secrets.env` в корне проекта |
| `make release-package` | APK с версией в имени и SHA256SUMS в `build/release` |
| `make ci-prepare` | Инструменты для сборки без эмулятора, принятие SDK-лицензий и зависимости |
| `make ci-lint` | Проверка workflow закреплённым actionlint |
| `make test` | Задача unit-тестов Gradle |
| `make lint` | Android Lint |
| `make check` | Сборка, задача unit-тестов и Lint |
| `make restart` | Перезапуск установленного приложения без сборки |
| `make clean` | Удаление результатов сборки через Gradle |

APK: `app/build/outputs/apk/debug/app-debug.apk`.

В `make test` и `make check` входят 341 JVM-тест парсеров, кэша, сети, моделей состояния и прогресса и 39 автономных Python-тестов загрузчика, разбора видеоссылок и упаковки релиза. Интернет и аккаунт им не нужны. Управление и реальную сеть проверяем отдельно в эмуляторе.

При проверке навигации выбрать «Настройки» в меню: сетевые параметры должны появиться сразу. Стрелка вправо или OK переводит фокус на галочку обхода; вниз — на выбор DNS, вверх — обратно. Подзаголовок «Сеть» не должен получать фокус. Аппаратная кнопка «Назад» и стрелка влево из параметров возвращают фокус на «Настройки» в меню без открытия «Сегодня». Отдельно проверить вход мышью, возврат из диалога DNS и переключение разделов стрелками в меню. Одиночные Esc/Back из описания должны восстанавливать фокус на выбранной карточке и позицию ленты, из окна DNS — возвращать в меню настроек; быстрые двойные нажатия — закрывать приложение даже при переходе из диалога в главное окно.

В «Обновлениях» долистать до последней карточки и несколько раз нажать вправо: фокус должен остаться на ней. Вверх переводит фокус на «Обновить», влево с последней карточки — на предыдущую, а влево с первой — в меню раздела. Это общее правило ленты для «Сегодня», «Обновления», «Топ» и «Новинки».

В «Топе» проверить AJAX-выдачу, обновление, метки новинок и описание. После переключения между «Обновлениями» и «Топом» должны сохраняться отдельные выбранные карточки и позиции. После восстановления позиции проверить дальнейшую прокрутку до конца и остановку фокуса на последней карточке. В проверке 2026-11-02 все 49 позиций кэша приложения совпали с отдельно загруженным AJAX-ответом.

В «Новинках» проверить отдельную позицию ленты после перехода через «Топ» и «Обновления», возврат из описания, обновление и остановку на последней карточке. Бейдж определяется меткой сайта: у первой карточки проверенного снимка его нет. В проверке 2026-11-02 все 50 позиций кэша приложения совпали с отдельным AJAX-ответом.

В «Лучших сериалах» проверить отдельную выдачу, количество сезонов вместо номера сезона и краткое описание во время загрузки полного. В проверке 2026-11-02 все 100 позиций кэша приложения совпали с отдельно полученной страницей; проверены описание, Esc, обновление и восстановление позиции после смены раздела.

Меню использует пункты высотой 40dp с промежутком 4dp и прокрутку списка разделов. Проверить доступность всех пунктов стрелками, появление раздела по фокусу, вход вправо и возврат в выбранный пункт. Общие кнопки должны оставаться прямоугольными со скруглением 5dp и не увеличиваться в фокусе. Параметры — в теме по [ADR-0023](adr/0023-compact-rectangular-menu.md).

В ленте проверить соседние короткое и длинное названия: рамки карточек одинаковой высоты, под заголовок отведены две строки, подписи серий выровнены. Миниатюра показывает русское название; панель и полное описание сохраняют также дополнительное название. Высота настраивается через `seasonvar_card_height` в теме — [ADR-0019](adr/0019-fixed-series-cards.md).

Бейдж «новинка» показывается на миниатюре и большом постере только у карточек с меткой сайта. Он не должен получать фокус или мешать открытию описания. В сохранённом AJAX-снимке 10 таких карточек; они также должны сохранять метку при загрузке из кэша.

Для подробного вывода Gradle:

~~~bash
make build GRADLE_ARGS=--info
~~~

## Проверка сохранения прогресса аккаунта

Автоматическая политика описана в [ADR-0056](adr/0056-automatic-account-playback-marks.md). make check проверяет порог 90%, паузу/завершение, ожидание реального просмотра, буферизацию, повтор отправки, смену аккаунта и подтверждение записи автономными фикстурами. Он не выполняет запросов изменения реального аккаунта.

Ручная проверка на выбранном эмуляторе с уже выполненным входом:

~~~bash
make devices
make mark-probe DEVICE=emulator-5554
make mark-probe DEVICE=emulator-5554 MARK_PROBE_MODE=roundtrip
~~~

Первый режим только читает структуру отметки существующей записи «На чём остановились». Второй временно меняет время существующей отметки, подтверждает его чтением и восстанавливает исходное значение; если другой клиент успел изменить отметку, его новое значение не перезаписывается. Инструмент выводит только имена полей/типы и булевы результаты, не личные данные. Неуспешный probe завершает команду с ошибкой. Тестовый APK и runner не входят в публикуемый APK, аккаунт и сеть нужны только для этой явно вызванной проверки.

После изменений плеера отдельно проверить реальное изображение и его движение, паузу, перемотку, переходы между сериями и возврат из плеера. Для диагностики синхронизации debug-тег SeasonvarMark содержит только фазы position_queued/completed_queued/write_verified/already_current/retry_pending/save_failed; в них нет пользователя, серии, позиции, cookie или видеоссылок.

Проверка 2026-11-04: `make check` — 284 JVM-теста, 22 Python-теста, Android Lint; `make build-profile` — успешная оптимизация R8. В авторизованном эмуляторе Android TV API 34 проверены движущееся изображение, пауза, перемотка, следующая/предыдущая серия и возврат к кнопке «Продолжить». Фазы `position_queued → write_verified` и `completed_queued → write_verified` подтвердили сохранение времени на паузе и отметки завершения после 90%; отдельный roundtrip подтвердил POST/чтение и восстановил исходную отметку.

## Проверка фильтров личных списков

`make personal-filters-probe DEVICE=emulator-5554 PERSONAL_FILTERS_PROBE_OUT=<каталог-сессии>/personal-filters` проверяет после входа GET `/resume` и POST жанра/страны: варианты, структуру фрагмента, выбор вкладок, соответствие выдачи без ограничений и неизменность обычного чтения после фильтра. Проверка не пишет отметки, не запускает видео, не входит в `make check`/CI и запрещена для физической приставки. Полные ответы аккаунта и cookie не попадают в отчёт.

В `make run-profile DEVICE=emulator-5554` открыть личный список, перейти к кнопке «Фильтры» в заголовке. Проверить пультом выбор жанра/страны, «Назад» без применения, применение, сброс и пустую выдачу; после закрытия фокус должен вернуться на кнопку. Смена списка не переносит условия. Перезапуск сохраняет успешный выбор. Сеть, HTTP, невалидный фрагмент, отмену, независимость разделов и смену владельца проверяют автономные тесты. Архитектура — [ADR-0118](adr/0118-shared-list-filter-panel.md).

## Проверка записи истории

`make history-probe DEVICE=emulator-5554 HISTORY_PROBE_OUT=<каталог-сессии>/history-probe` — отдельная живая проверка с существующей сессией эмулятора. Она действительно добавляет просмотр «Наруто», первого сезона, первой серии, озвучки 2x2 в историю аккаунта; запускать только в рамках разрешённой пользователем записи истории. Проверка не входит в `make check` или CI и не работает на физической приставке.

Проверяются HTTP-успех через ревизию истории, отсутствие повторного события на паузе и перемотке, возврат и неизменность ревизии постоянных отметок. Локальная позиция восстанавливается; запись истории остаётся на сайте. PNG из каталога результата нужно визуально просмотреть: состояния плеера не доказывают наличие изображения. Переходы серий и сезонов проверяются отдельно через `make player-probe`: сценарий останавливает фоновые задачи приложения в своём тестовом процессе, чтобы домашние ленты не восстановили аккаунт посреди гостевой проверки. Сохранённая сессия остаётся на устройстве; следующий обычный запуск использует новый процесс. Архитектура — [ADR-0117](adr/0117-playback-history-sync.md).

## Проверка удаления из личных списков

Поведение — [ADR-0057](adr/0057-remove-account-list-marks.md). В `make check` входят автономные проверки POST/повторного чтения, отказов и истечения сессии, конфликтов с очередью автосохранения, удержания OK и выбора соседа после удаления. В эмуляторе проверить короткое OK, удержание OK, отпускание без открытия сериала, общий диалог, первый фокус на «Отмена», Назад/Esc и возврат фокуса к миниатюре/кнопке карточки.

Для ручной обратимой сетевой проверки с уже выполненным входом:

```bash
make mark-probe DEVICE=emulator-5554 MARK_PROBE_MODE=delete-roundtrip
```

Этот режим действительно удаляет существующую отметку аккаунта, проверяет отсутствие в личных подборках и восстанавливает исходную отметку. Значение хранится только в памяти Android-процесса; прерывание процесса или сеть могут помешать восстановлению. Если другой клиент изменил отметку во время теста, его значение не перезаписывается. Проверка не входит в CI. Флаги `post_verified`, `removed_from_lists` и `original_restored` должны быть истинными. 2026-11-04 проверка успешно выполнена.

Проверка ADR-0057 от 2026-11-04: `make check` — 284 JVM-теста, 22 Python-теста и Lint без ошибок; `make build-profile` — успешно. В эмуляторе проверены меню, кнопка, подтверждение и отмена, возврат фокуса, движущееся видео и локальное продолжение. Успешный выбор соседа после удаления покрыт автономными тестами.

## Подписанный APK

~~~bash
make release
~~~

Команда собирает оптимизированный `release`, подписывает его и проверяет схемы APK Signature v2/v3 и соответствие сертификата выбранному ключу. Результат: `app/build/outputs/apk/release/app-release.apk`. Отдельный `make build BUILD_TYPE=release` только собирает неподписанный APK; для распространения нужен `make release`.

Секреты подписи берутся только из `secrets.env` в корне проекта, права доступа — `0600`. Файл исключён из Git; перенос на другой компьютер выполняется отдельно от клонирования репозитория — [ADR-0049](adr/0049-project-local-secrets.md). Файл содержит четыре параметра: `SEASONVAR_SIGNING_KEYSTORE_BASE64` (PKCS12 в Base64), `SEASONVAR_SIGNING_STORE_PASSWORD`, `SEASONVAR_SIGNING_KEY_PASSWORD` и `SEASONVAR_SIGNING_KEY_ALIAS`. Поддерживаются строки `KEY=value`, необязательные `export` и внешние кавычки; shell-код и подстановки не исполняются. Генерация ключа — отдельная разовая операция, без цели Makefile. Хранилище загружается в память; отдельный файл ключа не создаётся. Используется библиотека `apksig` из закреплённого Android SDK Build Tools, без новых зависимостей.

При ошибке подписания выходной APK удаляется; секреты и текст исключений не печатаются. Обычные debug/profile-сборки не читают `secrets.env` в корне проекта. Подробности — [ADR-0048](adr/0048-release-apk-signing.md).

Для всех обновлений приложения нужен тот же ключ. Сохранять защищённую резервную копию корневого `secrets.env` отдельно от проекта. Release-подпись отличается от debug/profile: первая установка поверх прежней отладочной версии невозможна без её удаления с потерей локальных данных. Команда `make release` ничего не устанавливает и не меняет данные устройств.

## Автосборка и выпуск на GitHub

Workflow [android.yml](../.github/workflows/android.yml) запускается при push в `main`, pull request, push тега `v*` и вручную через вкладку Actions → Android build → Run workflow. Обычный запуск выдаёт debug APK; `main`, теги и ручные запуски также выдают подписанный `seasonvar-tv-release`. Артефакты доступны на странице запуска в течение 14 дней. Только тег публикует GitHub Release. Принцип — [ADR-0050](adr/0050-github-actions-builds-and-releases.md).

Для первоначальной настройки владелец добавляет один repository secret `SEASONVAR_SIGNING_ENV` в Settings → Secrets and variables → Actions. Значение — четыре параметра подписи из локального `secrets.env`; содержимое не публикуется в репозитории. В CI файл создаётся только на время подписи и удаляется после неё. Для публикации используется встроенный `GITHUB_TOKEN`; личный токен в CI не нужен.

Для выпуска обновить `versionName` и увеличить `versionCode` в `app/build.gradle.kts`, затем проверить локально:

~~~bash
make ci-lint
make check
make release-package
~~~

Перед выпуском добавить `docs/releases/<versionName>.md`: список на русском, максимально краткое предложение в каждом пункте; около 10 слов — ориентир, а не жёсткий лимит, без технических подробностей. Принцип — [ADR-0069](adr/0069-short-release-notes.md). `make release-package` проверяет формат и переносит описание в `build/release/NOTES.md`; GitHub публикует его как текст релиза.

Результат — `build/release/seasonvar-tv-<versionName>-universal.apk`, `build/release/SHA256SUMS` и `build/release/NOTES.md`. После коммита отправить изменения и тег, совпадающий с версией, например для версии `0.3.1`:

~~~bash
git push
git tag v0.3.1
git push origin v0.3.1
~~~

Релизный тег создаётся и отправляется только по явной команде пользователя — [ADR-0053](adr/0053-explicit-release-tag-command.md). Просьба закоммитить изменения или проверить автосборку сама по себе не запускает выпуск.

GitHub соберёт и проверит приложение, подпишет APK и создаст Release с APK и контрольной суммой. Несовпадение тега и `versionName` останавливает выпуск. Теги с суффиксом, например `v0.3.0-beta.1`, помечаются prerelease. Уже опубликованные теги не заменяются; исправление выпускается новой версией.

CI использует закреплённые JDK/SDK из `toolchain.lock.json`; `make ci-prepare` пропускает эмулятор и системный образ. `make ci-lint` загружает actionlint с проверкой размера и SHA256. GitHub Actions закреплены SHA, кэшируются только инструменты и Gradle; `secrets.env` в кэш и артефакты не входит. Проверка видео выполняется отдельно по правилам проекта.

Скачанный из GitHub APK устанавливается без пересборки и с сохранением данных:

~~~bash
make devices
make install-apk DEVICE=<serial> APK=build/release/seasonvar-tv-0.3.1-universal.apk
make restart DEVICE=<serial>
~~~

## Сеть приложения

Формат пунктов настроек — [ADR-0015](adr/0015-settings-item-format.md): название и пояснение слева, галочка или выбранное значение справа; OK или клик переключает галочку либо открывает список опций.

На общем экране «Настройки» под текстовым подзаголовком «Сеть» расположены две независимые настройки: галочка «Обход блокировок» (по умолчанию включена) и DNS («Системный» / «Quad9 DoH», по умолчанию Quad9 DoH). Они хранятся в приватных SharedPreferences `network`: ключ `dpi_bypass` и строковый `dns_provider` (`system` / `quad9_doh`). Если ключ DNS ещё отсутствует, используется Quad9 DoH; сохранённая галочка остаётся прежней.

Выбор применяется к новым запросам HTML и Coil, а уже открытые списки обновляются. При ошибке сети показывается предупреждение: для «Сегодня» допускается только кэш текущего дня, для «Обновления» — не старше 24 часов. Сертификаты проверяются во всех сочетаниях; детали — [ADR-0011](adr/0011-network-bypass-setting.md) и [ADR-0012](adr/0012-dns-provider-setting.md). Для добавления провайдера расширить `DnsProvider`, UI-название и соответствующий резолвер в `NetworkClients`.

## Получение страниц сайта

## Проверка отзывчивости на приставке

~~~bash
make devices
make run-profile DEVICE=<serial>
make profile-navigation DEVICE=<serial> PROFILE_OUT=build/performance/run
make profile-navigation DEVICE=<serial> PROFILE_OUT=build/performance/cpu PROFILE_ARGS='--sample --rounds 1'
~~~

Экран приставки должен быть активен; при необходимости `make key DEVICE=<serial> KEY=WAKEUP`. Для эмулятора использовать его serial, но оценку скорости проводить на целевом устройстве. `profile` — release-конфигурация с R8, читаемыми именами, `debuggable=false`, shell-профилированием и локальной debug-подписью. Она обновляет ту же тестовую установку, сохраняя данные. Для обычной отладки остаётся `make run`. Подход соответствует [рекомендациям Android](https://developer.android.com/studio/profile/build-run-manually).

Сценарий перезапускает только приложение, проходит шесть пунктов вниз и шесть вверх и повторяется три раза. Интервал клавиш и частота CPU-сэмплирования закреплены в `toolchain.lock.json`. Сохраняются запуск, app-only `gfxinfo framestats` и JSON-сводка. При `--sample` дополнительно сохраняется метод-трасса для Android Studio; показатели кадров этого запуска не сравнивать с обычными замерами. Бинарные трассы не коммитить. Сеть остаётся настоящей; при сравнении учитывать кэш, состояние сайта и прогрев. Число кадров в выгрузке может ограничиваться системным буфером, поэтому сводка отдельно содержит `frame_stats_count`.

Первый проход после перезапуска и повторные проходы оценивать отдельно. Распределение появления карточек уменьшает длинные кадры, но увеличивает число промежуточных кадров; доля jank сама по себе не описывает отзывчивость меню. Постоянные 60 fps этим изменением не подтверждены. Поведение и альтернативы — [ADR-0025](adr/0025-responsive-section-switching.md).

После изменения проверить на пульте каждый каталог, вход в ленту, открытие описания и возврат на ту же карточку; затем настройки, поиск и сохранение позиции после смены раздела. Эти сценарии проверены на Ugoos X5M 2026-11-02.

Замер 2026-11-02, Ugoos X5M / Android 14, одинаковый сценарий без CPU-сэмплирования. До изменения уже использовалась оптимизированная профильная сборка; первый проход — после перезапуска приложения с существующим дисковым кэшем.

| Проход | p90 кадра до → после | Максимум до → после | Кадры >100 мс до → после |
| --- | --- | --- | --- |
| Первый | 150 → 77 мс | 242,8 → 128,0 мс | 13 → 2 |
| Повторный 1 | 121 → 44 мс | 157,2 → 93,0 мс | 9 → 0 |
| Повторный 2 | 113 → 36 мс | 143,5 → 79,8 мс | 9 → 0 |

Сравнение не означает улучшения каждой метрики: в последнем проходе число кадров выросло с 81 до 111, медиана — с 9 до 22 мс, число отмеченных системой janky frames — с 13 до 26. Работа распределена по промежуточным кадрам ради уменьшения длинных остановок. Это длительности кадров приложения, а не прямой замер задержки клавиши до изображения. Первая загрузка всё ещё тяжелее повторной. Сборка profile с R8, debug-сборка, 61 JVM-тест, 13 Python-тестов и Android Lint прошли проверку.

## Индикация обновления

Во время загрузки вращается только значок кнопки обновления; сообщение загрузки над описанием не появляется. Статусы ошибки/кэша занимают существующую строку заголовка. Правила — [ADR-0026](adr/0026-refresh-indicator-in-button.md).

Для проверки медленного ответа в эмуляторе: `make emulator-network-delay NETWORK_DELAY=1000`, затем обновить каталог и проверить неподвижность описания и ленты, сохранение фокуса и остановку вращения после ответа. После проверки вернуть исходную задержку: для стандартного эмулятора `make emulator-network-delay NETWORK_DELAY=none`. Эти команды относятся к сети эмулятора, не к системному DNS или приставке.

Проверка 2026-11-02: при задержке сети эмулятора 1000 мс вращение подтверждено последовательными снимками; координаты заголовка выбранного сериала и карточек совпали до и во время обновления, фокус остался на кнопке, видимой строки «Обновляем список…» нет. После завершения запроса последовательные снимки стали идентичны — анимация остановилась. Задержка возвращена к исходным 0 мс.

## Диагностика карточек и плеера на приставке

Сначала `make devices`, затем для диагностики `make run DEVICE=<serial>` и `make logs DEVICE=<serial> LOG_ARGS='-d -s SeasonvarDetails SeasonvarPlayback SeasonvarNetwork'`. Подробные теги доступны в debug-сборке; оптимизированная `profile` их не пишет. В диагностике есть классы причин, HTTP-статус и код Media3, но нет текста исключений, cookie и временных ссылок.

При наличии внешнего ByeByeDPI можно оставить внутренний обход выключенным; DNS приложения — отдельный выбор. Проверять и фиксировать фактические параметры, не считать выключенный внутренний обход признаком неправильной настройки сети.

У первого сезона «Экстрасенсы. Реванш» сайт возвращает явное ограничение страны. Проверить текст причины в карточке, отсутствие неработающего «Смотреть», повторный запрос через «Обновить данные», выбор другого сезона и возврат в исходную ленту. Автономная фикстура очищена от скриптов плейлиста. Обычное открытие карточки использует кэш, явное обновление всегда запрашивает страницу заново.

Регрессия видео: `make site-video-probe SITE_URL=https://seasonvar.ru/serial-15615--Boruto_Novoe_Pokolenie_pscevnu-0-sezon.html` должна вернуть HTTP 206 / MP4. Полный путь видео может содержать скобки, запятые и пробелы; не разбивать его по этим символам. ## Аккаунт и личный список

~~~bash
make account-test
make check
make run DEVICE=<serial>
~~~

Кнопка человека находится справа от поиска. С «Сегодня»: вверх → поиск → вправо → аккаунт → OK. В форме поля логина и скрытого пароля используют штатную IME. Next переводит к паролю, Done отправляет форму; после закрытия IME работают стрелки между полями. Пароль очищается при отправке и уходе с формы, в сохранённое состояние экрана не попадает.

Личные данные вводить непосредственно в приложении. Во время ввода не снимать экран, не выгружать UI-дерево и широкие логи. Cookie и пароль не передавать CLI-параметрами. Настоящие ответы аккаунта не сохранять в фикстуры; для тестов используется синтетический `account-resume.html`.

После входа проверить аватар (или штатную иконку при его отсутствии), все пять личных пунктов меню, загрузку/обновление каждого списка и открытие карточки с возвратом на неё. Затем перезапуск приложения без повторного ввода пароля, отключение сети, восстановление сети и выход: все личные разделы и аватар должны исчезнуть, поздние ответы не должны восстановить сессию. Проверять истёкшую сессию отдельно от пустого аккаунта. Положительный сценарий требует своей учётной записи, автоматические тесты — нет.

Сессия хранится шифрованным блоком в приватных SharedPreferences `account-session`, ключ — Android Keystore. Пароль и логин не записываются. Сайт получает cookie только в пределах исходного домена/пути и HTTPS; медиадоменам они не отправляются. Публичная и приватная выдача сохраняется общим механизмом HTML-кэша в отдельных областях; приватная область принадлежит подтверждённому текущему аккаунту. При выходе приватный HTML и личная часть данных карточек удаляются, общие данные сохраняются по ADR-0129. Локальная позиция видео по ADR-0031 и отметки сайта пока не синхронизируются.

## Проверка обновления приложения

Поведение экрана и установки — [ADR-0074](adr/0074-in-app-github-updates.md). Обычные сборка и тесты: `make check`; отдельно автономные проверки обновлений: `make update-test`.

- `make update-probe DEVICE=emulator-5554` — чтение актуального GitHub Release и загрузка APK с проверкой размера, SHA-256 и имени пакета, без установки.
- `make update-preview DEVICE=emulator-5554` — локальная имитация нового выпуска с настоящим тестовым APK и настоящим установщиком Android. Доступные `UPDATE_PREVIEW_SCENARIO`: `new`, `current`, `network`, `signature`, `notes-network`. В `new` показаны длинные описания новых и установленного выпусков для проверки прокрутки пультом, в `current` — только установленного; `notes-network` оставляет сохранённое описание при ошибке истории и доступной установке. Сценарий `signature` намеренно отклоняет файл, чтобы проверить сообщение и отсутствие запуска установщика.
- Подтверждение установки в Android действительно обновляет тестовую сборку. После проверки выполнить `make update-restore BUILD_TYPE=profile DEVICE=emulator-5554` и `make restart DEVICE=emulator-5554`. Возвращается обычная тестовая версия с сохранением данных; APK не удаляется. Это также завершает тестовую подмену экрана.

Preview использует только локальные данные из androidTest; исходная версия проекта и GitHub не меняются. Обычный экран всегда читает настоящий GitHub API. Диагностические команды ограничены эмулятором и не используют аккаунт Seasonvar. Полную проверку обновления публичной подписью выполняют между настоящими релизами; релизный тег создаётся только по явной команде пользователя.

«Настройки → Плеер → Следующая серия автоматически» включена по умолчанию. Следующая серия запускается сразу после завершения видео, в пределах сезона и озвучки. Промежуточной панели и отсчёта нет. Проба запускает отдельный процесс без восстановления аккаунта, не пишет серверные отметки и восстанавливает локальную позицию проверенного сезона и настройку автоперехода. ## Личные списки и статусы

`make site-scripts` загружает публичные main.js и pg.marks.js. `make check` проверяет формы статусов, подтверждение записи, неизменность существующего прогресса при выборе «Смотрю», смену аккаунта, повтор операции и согласование с автосохранением.

`make status-probe DEVICE=emulator-5554` — явная сетевая проверка на вошедшем аккаунте эмулятора: она берёт существующую отметку, проверяет четыре статуса и чтение вкладок, затем восстанавливает исходную серию, озвучку и время. Команда выводит обезличенные признаки подтверждения и восстановления; настоящие cookie и страницы не сохраняются. Не входит в make check.

В `make run-profile DEVICE=emulator-5554` проверить закладку и корзину в карточке, подписи фокуса, удержание OK в публичной и личной подборке, отметку текущего статуса, сохранение/ошибку, отмену через Esc/Назад и возврат фокуса. Корзина должна сначала показывать подтверждение; отмена не удаляет отметку. После смены статуса связанные списки и метка «Смотрю» обновляются. Проверить реальное видео, паузу, перемотку и возврат, поскольку ручная запись использует общую очередь с прогрессом плеера.


## История поиска

История хранится локально отдельно от сессии аккаунта: до 20 запросов в search-history. `make check` проверяет порядок и дубли, ограничения, JSON, повтор, очистку, поздние операции, ошибки и сохранение после пересоздания хранилища. Новых сетевых эндпоинтов нет.

В `make run-profile DEVICE=emulator-5554` найти сериал, открыть карточку и вернуться. Открыть поиск повторно: первая строка истории в фокусе, клавиатура скрыта. Одно OK должно выполнить поиск и выбрать первую карточку, а не открыть клавиатуру. Стереть весь текст: история должна появиться под полем, сохраняя фокус ввода и клавиатуру; вниз переводит к запросам. Проверить вверх к полю, вправо к очистке и возврат в список, остановку на последней строке. После `make restart DEVICE=emulator-5554` запросы должны сохраниться. Очистить историю и повторить перезапуск: старые запросы не возвращаются; новый поиск снова сохраняется.


## Представление каталога

`make check` проверяет отдельное сохранение вида для каждого списка, восстановление выбора и границы сетки, включая неполный последний ряд и изменение числа столбцов. `make run-profile DEVICE=emulator-5554` собирает и запускает оптимизированную тестовую версию без удаления данных.

В эмуляторе проверить переключатель перед обновлением: кнопки квадратные, иконки по центру, фокус остаётся на переключателе. Вниз переводит к выбранной карточке. Убедиться, что лента и сетка показывают одинаковый порядок, а выбранный сериал остаётся видимым при смене вида. Открыть сериал и вернуться Esc; перейти в другой раздел и обратно: карточка и прокрутка должны восстановиться. Удержание OK открывает прежние действия аккаунта, отмена возвращает фокус.

В сетке проверить движение по строкам, переход в меню с левого края, к переключателю с верхнего ряда и остановку на правом/нижнем краю, включая неполный ряд. Проверить общие списки, личные списки, результаты поиска, пустое состояние и подгрузку истории просмотров. История поисковых запросов остаётся вертикальным списком. Назначить «Обновлениям» сетку, а «Топу» ленту; после `make restart DEVICE=emulator-5554` каждый список должен сохранить собственный вид. На экранах разной ширины число столбцов подстраивается, пропорции постеров и единый размер карточек сохраняются; последние карточки не растягиваются на всю строку.

При запуске эмулятора с дополнительными аргументами сохранять `-use-keycode-forwarding` из `toolchain.lock.json`: без него Esc на физической клавиатуре может не дойти до Android, хотя `make key KEY=ESCAPE` работает. Штатный `make emulator` уже передаёт этот параметр.


Общие размеры каталога рассчитывает `CatalogCardMetrics.kt` по `seasonvar_catalog_min_card_width`, отступам и пропорциям из темы и измеренным стилям текста. После `make run-profile DEVICE=emulator-5554` сравнить полную ширину/высоту одной карточки и её постера в обоих видах. Размеры должны совпадать также между разделами и у одно-/двухстрочных названий. Изменение ширины окна и системного масштаба текста должно пересчитать геометрию, а переключение вида — сохранить её. После изменения размеров проверить перемещение пультом и возврат Esc на выбранный сериал. Физическая приставка для этого сценария не используется.


## Локальная сборка для проверки на приставке

По явному запросу владельца можно проверить локальную release-сборку с тем же постоянным ключом, что и GitHub Releases, согласно [ADR-0086](adr/0086-local-dev-release-signature.md):

```bash
make release-dev
make devices
make install-apk APK=app/build/outputs/apk/release/app-release.apk DEVICE=<serial>
```

В «О программе» будет `0.3.1-dev<короткий хеш коммита>`. Перед сборкой сохранить изменения коммитом, чтобы хеш соответствовал исходникам. В экспортированной рабочей копии доступен явный `DEV_COMMIT=<хеш>`. Обычный `make release` сохраняет публичный номер. До установки проверить совпадение сертификата с установленным APK и совместимость `versionCode`; данные и приложение не удалять. Идентификатор приложения и постоянная подпись прежние. Эта команда не публикует релиз и не создаёт тег.


## Плоское меню долгого OK

`make check` проверяет автоматическое чтение статуса при открытии, блокировку выбора до чтения, прямое сохранение из плоского меню, отмену запоздалого чтения при смене аккаунта и переходе к удалению, а также прежнее подтверждение и повтор операций. Протокол записи не меняется.

В `make run-profile DEVICE=emulator-5554` открыть отмеченную карточку долгим OK: сразу видны четыре статуса и удаление, без «Открыть сериал» и промежуточного «Личный список». Отпускание OK не выбирает пункт. В шапке каталога нет подсказки об удержании. Проверить начальный фокус на текущем статусе, доступность нижнего пункта, подтверждение удаления с фокусом на отмене и возврат Esc на ту же миниатюру без записи. На неотмеченной карточке удаление не предлагается. Закладка в полной карточке по-прежнему открывает четыре статуса напрямую; её Esc возвращает на закладку. Не менять реальные отметки ради проверки верстки.


## Геометрия и фокус меню отметок

```bash
make mark-menu-probe DEVICE=emulator-5554
make run-profile DEVICE=emulator-5554
```

Первая команда устанавливает тестовую debug-сборку и запускает автономные состояния отдельной debug-активности: загрузка, ответ с отметкой и без неё, сохранение, ошибка и подтверждение удаления. Она не восстанавливает аккаунт и не делает HTTP-запросов. Пиксельные границы пунктов сравниваются автоматически, фокус проверяется после ответов и ошибок. Проверяется также удержанное на неактивном пункте OK, отпущенное после загрузки: оно не должно выполнять действие. Результат и PNG — в `build/mark-menu-probe` (путь задаётся `MARK_MENU_PROBE_OUT`); изображения нужно просмотреть.

Вторая команда возвращает обычную оптимизированную сборку с прежней тестовой подписью. На реальном меню проверить вращение постоянной кнопки справа в заголовке, возврат к последнему пункту и отмену Esc. Строка удаления и место ошибки не исчезают; неактивные пункты сохраняют фокус, но ничего не выполняют. Никакие данные эмулятора не удаляются. См. ADR-0088.


## Проверка умного продолжения

`make smart-continue-probe DEVICE=emulator-5554` читает отметки и историю существующей сессии в эмуляторе. `SMART_PROBE_SEASON=<id>` дополнительно проверяет наличие нужного сезона и выбранные серию/позицию. Вывод содержит только счётчики, признаки результата и публичные идентификаторы; HTML аккаунта, имена и cookie не сохраняются. Запросов записи отметок нет. Для «Продолжить» выводятся `smart_mark_count`, число запросов отметок/истории/сезонов, `smart_total_requests`, `smart_request_peak` и `smart_duration_ms`. Это измерение построения списка; предварительное восстановление сессии, постеры и описания не учитываются. Эта проверка требует сети и входа и не входит в CI.

Для плеера `make player-probe DEVICE=emulator-5554` дополнительно проверяет запуск с явно заданной позиции, затем паузу, перемотку, смену эпизода и возврат. Просмотр сохранённых PNG обязателен. Проба работает без восстановления аккаунта, не пишет его отметки и восстанавливает тестируемую локальную позицию.

После проверок вернуть обычную сборку: `make run-profile DEVICE=emulator-5554`. Данные и тестовая подпись сохраняются.


## Проверка перехода к следующему сезону

`make player-probe DEVICE=emulator-5554` дополнительно использует `PLAYER_PROBE_SEASON_PAGE`: точную ссылку страницы с доступным следующим сезоном. Проверка запускает последний эпизод, подтверждает остановку при выключенной настройке, затем переход при включённой, первое видео нового сезона, паузу, перемотку и возврат. Исходные значения обеих настроек и позиции затронутых сезонов восстанавливаются; аккаунт не восстанавливается, отметки не записываются.

Результат и кадры — в `PLAYER_PROBE_OUT`. Просмотреть пары `14-next-season-a.png` / `15-next-season-b.png`, паузу `16-season-paused.png`, перемотку `17-season-seek.png` / `20-season-after-seek.png` и видео предыдущего сезона `18-previous-season-a.png` / `19-previous-season-b.png`, дополнительно к прежним кадрам проверки плеера. После проверки — `make run-profile DEVICE=emulator-5554`; в настройках проверить две независимые галочки и переход фокуса вниз к сети. См. ADR-0093. Заголовок на паузе должен содержать фактические сезон и серию после перехода; проверка возвращает `season_title_verified=true` по ADR-0094.

## Большие постеры и проверка разных экранов

Крупный постер над лентой использует `SeriesEntry.largePosterUrl` и общий Coil. Область тянется по высоте оставшегося пространства; ширина зависит от пропорций обложки. Максимальная доля ширины задаётся `seasonvar_preview_poster_max_width_percent` в `themes.xml`. Размер карточек ленты не меняется. См. [ADR-0097](adr/0097-adaptive-large-preview-poster.md).

Для воспроизведения более просторного ТВ-интерфейса в локальном эмуляторе:

```bash
make emulator-display DEVICE=emulator-5554 DISPLAY_SIZE=1920x1080 DISPLAY_DENSITY=240
make run DEVICE=emulator-5554
```

Перед изменением сохранить свои переопределения размера и плотности, если они есть. Команда разрешена только для эмулятора. После проверки стандартного AVD без исходных переопределений вернуть физические параметры:

```bash
make emulator-display DEVICE=emulator-5554
make run-profile DEVICE=emulator-5554
```

Проверить «Новинки» с разными пропорциями постеров: верх совпадает с верхом информации, низ подходит к ленте с общим отступом, изображение целиком и не растянуто. Переключить серии и разделы, затем вернуться; список и фокус работают как прежде.

В debug-сборке источник готового изображения и размер декодирования выводятся отдельным тегом, без URL и данных аккаунта:

```bash
make logs DEVICE=emulator-5554 LOG_ARGS='-d -s SeasonvarPoster:D'
```

Первое открытие может дать `NETWORK`, повторное — `MEMORY_CACHE`. После `make restart DEVICE=emulator-5554` выбрать тот же сериал: `DISK` подтверждает чтение сохранённого большого файла новым процессом. Кэш миниатюры и большого файла разделён по URL. `make check` проверяет преобразование URL, включая `small`, уже большой адрес и неизвестные домены/пути.

## Общий движок списков и предзагрузка

Настройка «Подготавливать списки заранее» включена по умолчанию и сохраняет прежний ключ `image_prefetch`. Общий `SeriesListEngine` подготавливает содержимое карточек, описания и изображения по одному окну: видимая область и до двух экранов начиная с выбранной карточки, без дополнительной загрузки серверных страниц выдачи. В ленте экран равен числу колонок, в плитке учитываются ряды. Все полученные `SeriesEntry` остаются в памяти. Описания и метаданные читаются из общего кэша Kotlin-объектов на 5000 сезонов, затем из подходящей публичной или приватной HTML-выдачи сроком до суток, затем с сайта. Активное окно удерживает нужные записи; переключение списков не очищает разобранные данные. Приватный HTML работает после сетевого подтверждения аккаунта; без устойчивого ID аккаунта его чтение и запись отключены. После выхода общие описания остаются, личная часть объектов и приватный HTML удаляются. Общий лимит описаний и фоновых изображений — три. Готовый текст доступен при выборе без задержки 180 мс. Файлы больших обложек сохраняются на диск без декодирования в крупный bitmap; миниатюры подготавливаются под размер карточки. См. [ADR-0127](adr/0127-shared-list-preparation-window.md), [ADR-0128](adr/0128-description-preparation-window.md), [ADR-0129](adr/0129-shared-card-data-cache.md).

Автономная проверка производственного компонента на 33 000 синтетических записей:

```bash
make series-list-probe DEVICE=emulator-5554
```

Команда обновляет debug-приложение и тестовый APK с прежней подписью, не меняет аккаунт и сохранённую настройку. Проверяет ленту и плитку, дальнее перемещение, дописывание страниц, границы подготовки, фокус и галочку. Результат и снимки — в `build/series-list-probe` либо `SERIES_LIST_PROBE_OUT`. Просмотреть снимки, затем вернуть оптимизированную сборку командой `make run-profile DEVICE=emulator-5554` и измерить меню через `make profile-navigation DEVICE=emulator-5554`. Эмулятор не подтверждает производительность Ugoos; на приставку новая локальная сборка устанавливается только по явному запросу согласно ADR-0086.

Проверка первоначального движка без предзагрузки описаний 09.11.2026: `make check` — 587 JVM-тестов, 39 Python-тестов, debug-сборка и lint без ошибок; `make series-list-probe` и `make ui-screens-probe` прошли, снимки просмотрены. `make build-profile` и запуск в Android TV API 34 прошли с сохранением данных. В отдельном замере без параллельной сборки `make profile-navigation` дал максимум 265,7 мс в первом проходе и 68,7 / 85,5 мс в повторных; кадров дольше 100 мс в повторных проходах — 0. Это измерение меню эмулятора, без сравнения с прежним движком; ускорение и производительность большого списка на Ugoos не подтверждены.

`make check` проверяет план окна и очередь герметичными тестами. В `make run DEVICE=emulator-5554` открыть список, перейти вправо на несколько карточек и сменить раздел. Проверить оба представления и переключение галочки с пульта. Значение должно пережить `make restart DEVICE=emulator-5554`. После выключения дополнительная очередь не запускается; обычные видимые картинки продолжают загружаться. После проверки вернуть галочку во включённое состояние и обычную сборку через `make run-profile DEVICE=emulator-5554`.

После добавления описаний по ADR-0128: прошли 595 JVM-тестов и 39 Python-тестов, `make check`, повторный lint, сборка profile, `make series-list-probe` и `make ui-screens-probe`; снимки просмотрены. В реальном списке эмулятора проверен переход к соседней карточке с готовым описанием. Отдельный прогон `make profile-navigation` дал максимумы 33,8 / 18,0 / 45,8 мс, без кадров дольше 100 мс. Это текущие условия эмулятора и кэша, а не сравнение скорости с прежней версией и не замер Ugoos.

После общего кэша по ADR-0129 (2026-11-10) прошли 618 JVM-тестов, 39 Python-тестов, `make check`, profile-сборка, `make shared-card-cache-probe` и `make ui-screens-probe`. Снимки проверены; в обычном авторизованном приложении проверены описание, открытие сериала и возврат. Профильное перемещение по меню: максимумы 33,7 / 22,6 / 21,4 мс, без кадров дольше 100 мс. Приставка не использовалась.

Лимит данных карточек задаётся в одном месте: [`CacheSettings.CARD_DATA_CAPACITY`](../app/src/main/java/ru/seasonvar/tv/data/settings/CacheSettings.kt), сейчас 5000 сезонов. В интерфейсе настройки нет; кэш и сценарии проверки читают эту константу.

Проверка общего кэша и отдельный замер памяти:

```bash
make shared-card-cache-probe DEVICE=emulator-5554
make cache-memory-probe DEVICE=emulator-5554
make run-profile DEVICE=emulator-5554
```

Первая команда использует синтетические выдачи: А → Б → А без повторных запросов и с тем же объектом описания, изоляция приватного HTML, очистка только приватной части и защита от позднего ответа, вытеснение до 5000 сезонов. Она также повторяет проверки окна, фокуса, геометрии и галочки на 33 000 записях. Данные аккаунта и сохранённые настройки не изменяются.

Вторая команда открывает обычное приложение, проходит шесть пунктов меню вниз и вверх, затем считывает занятое место, лимит и число ключей памяти Coil. Отдельный изолированный кэш заполняется 5000 сезонами: описание около 500 символов, пять актёров, одна озвучка и 40 серий; у одного сезона 1000 серий. Разница занятой Java-кучи после сборки мусора оценивает полный кэш и общую часть после удаления приватных полей. Это приблизительное измерение в debug-эмуляторе, без дампа кучи и без изменения личного аккаунта. Постеры учитываются отдельно; их размер зависит от посещённых экранов. Отчёт и снимок лежат в `build/cache-memory-probe` (`CACHE_MEMORY_PROBE_OUT` меняет каталог); после проверки восстановить profile-сборку. Команда не запускается на физической приставке.

Замеры 2026-11-10, Android TV API 34 ARM64, debug, одинаковые параметры синтетической выдачи:

| Число сезонов | Весь кэш | Общая часть | Приватная часть |
| --- | --- | --- | --- |
| 2000 | 12,21 МиБ | 11,85 МиБ | 0,36 МиБ |
| 5000 | 30,42 МиБ | 29,50 МиБ | 0,91 МиБ |

Последний запуск с единой константой: 31 147 / 30 212 / 935 КиБ соответственно. После увеличения лимита прошли `make check` и проверка вытеснения до 5000 сезонов; переходы между списками, фокус и очистка приватной части сохранились. Пользователь также подтвердил работу версии при ручной проверке в эмуляторе. Округление и сборка мусора не дают точности до байта; это не верхняя граница для любых данных сайта. В последнем запуске память постеров Coil заняла 11,06 МиБ (11 325 КиБ), 42 ключа при лимите 38,40 МиБ (39 321 КиБ); в обычном кэше данных было 32 сезона. Эти постеры относятся к посещённым экранам, а не ко всем синтетическим сезонам. HTML хранится на диске и в оценку не входит. Это замер эмулятора, не Ugoos.

Безопасная диагностика фоновых запросов в debug-сборке:

```bash
make logs DEVICE=emulator-5554 LOG_ARGS='-d -s SeasonvarPrefetch:D'
```

Тег показывает `THUMBNAIL` / `LARGE`, успешность и `NETWORK` / `DISK` / `MEMORY_CACHE`; адреса и данные аккаунта не выводятся. Успешная предзагрузка большого файла не означает декодированный постер в памяти — его обычный показ проверяется по `SeasonvarPoster` и визуально. Сроки и ограничения общего кэша остаются прежними.

Галочка находится первой в группе «Сеть», перед обходом блокировок и DNS, по [ADR-0102](adr/0102-image-prefetch-network-setting.md). Перенос сохраняет прежний `image_prefetch` без миграции. В profile-сборке проверить переход вниз с автоперехода сезона на предзагрузку и обратно, а также переход к обходу блокировок.

В profile-сборке проверить, что заголовок пропускается стрелками между предпочитаемыми озвучками и автопереходами.

## Ленты домашнего экрана Android TV

По [ADR-0106](adr/0106-android-tv-home-channels.md) три preview-канала используют один обработчик запуска. `HomePlaybackResolver` не принимает тип ленты: актуальная отметка аккаунта имеет приоритет, затем используется локальный прогресс, иначе первая доступная серия первого доступного сезона. Для локального продолжения сохраняются время обновления и признак завершения; прежний формат позиции остаётся читаемым. Эти поля не образуют отдельную историю аккаунта.

Выбор каналов, ключи карточек и владельцы личных публикаций хранятся в приватных настройках `home-channels`. В `TvProvider` передаются название, постер и непрозрачный URI; адрес видеопотока получается при открытии. Постеры скачиваются существующим сетевым клиентом через Coil и публикуются отдельным провайдером только для чтения. Обновление канала применяется одной системной транзакцией после подготовки всех постеров. При ошибке старые карточки сохраняются. Неиспользуемые постеры удаляются спустя сутки.

Обновление выполняется после возвращения приложения, изменений отметок и выхода из плеера. Периодическое сетевое задание `HomeRefreshJob` с ID 106 запускается примерно раз в шесть часов, сохраняется после перезагрузки и отменяется при выключении всех лент. Точное время определяет Android. Канал, удалённый пользователем, автоматически не создаётся заново: для добавления требуется выключить и включить его в настройках.

По [ADR-0107](adr/0107-launcher-managed-home-channels.md) при отсутствии обработчика `ACTION_REQUEST_CHANNEL_BROWSABLE` управление отображением передаётся лаунчеру: три канала однократно регистрируются без запроса автоматической видимости, доступные карточки обновляются независимо от галочек приложения. В этом режиме периодическое задание остаётся включённым, галочки недоступны, под списком показано пояснение. Прежний выбор сохраняется для устройств со штатным окном. При отсутствии TvProvider публикация недоступна. `make home-platform DEVICE=<serial>` показывает HOME и обработчик системного окна; диагностика публикации пишет только класс ошибки и идентификатор ленты в тег `SeasonvarHome`.

`make check` проверяет общий выбор серии и позиции на синтетических данных. `make home-probe DEVICE=emulator-5554 HOME_PROBE_OUT=<session-dir>` проверяет три системных канала, повторную публикацию без дубликатов, подтверждение добавления, запрет чужих/устаревших/выключенных карточек и запуск реального видео через URI программы. Probe временно блокирует фоновую публикацию, не восстанавливает аккаунт и не записывает серверные отметки; настройки и локальная позиция восстанавливаются. Системные каналы остаются зарегистрированными, исходные карточки возвращаются. Снимки лаунчера и кадров плеера обязательно просмотреть вручную.

После probe вернуть обычную тестовую сборку через `make run-profile DEVICE=emulator-5554`. Проверить галочки, системное подтверждение, сохранение после перезапуска, отображение постеров на домашнем экране и запуск карточки пультом. Скрытие разделов внутри приложения не влияет на эти галочки. Отсутствие `TvProvider` показывает недоступность функции. Наличие провайдера не доказывает, что конкретный лаунчер отображает каналы. Проверка приставки — по запросу пользователя, официальным APK из GitHub Releases.

## Часы в плеере

«Настройки → Плеер → Часы в плеере» открывает выбор «Выключены», «Слева», «По центру», «Справа». По умолчанию часы выключены. Значение сохраняется в `interface.player_clock_position`; подписи и положение выбираются пультом без дополнительных точек фокуса. Формат ЧЧ:ММ использует время и часовой пояс приставки. См. [ADR-0104](adr/0104-player-clock.md).

`make check` проверяет выключенное состояние по умолчанию, сохранённые значения, формат времени, часовые пояса и смену даты/летнего времени. `make player-probe DEVICE=<emulator> PLAYER_PROBE_OUT=<session-dir>` дополнительно сохраняет `clock-off.png`, `clock-left.png`, `clock-center.png`, `clock-right.png` и требует актуальное время и отсутствие фокуса у часов на последующих кадрах, включая паузу и переходы. Результат содержит `clock_positions_verified` и `clock_setting_restored`.

Для каждого положения probe также сохраняет `clock-<position>-title.png` с открытой панелью на паузе. По [ADR-0105](adr/0105-player-title-beside-clock.md) название, сезон и серия идут в одной строке после левых часов; при центральных и правых название остаётся слева. Текст и цифры часов выровнены по общей базовой линии во всех положениях. Проверить выравнивание и отсутствие пересечений; длинный текст сокращается многоточием.

После просмотра PNG вернуть обычную тестовую сборку через `make run-profile DEVICE=<emulator>`. Проверить диалог, отмену выбора и сохранение после `make restart DEVICE=<emulator>`. Открыть реальное видео с включёнными часами, визуально проверить смену кадров, паузу, перемотку, следующую серию и возврат. В конце восстановить исходное положение часов.

## Видимость разделов меню

«Настройки → Приложение → Разделы меню» открывает список галочек, включённых по умолчанию. Изменения сразу сохраняются; «Готово» закрывает диалог и возвращает фокус на строку настройки. «Назад» возвращает в меню, сохраняя переключения. «Настройки» всегда доступны, поиск и аккаунт остаются над меню. Личные галочки можно менять до входа; сами пункты появляются только после восстановления аккаунта. См. [ADR-0101](adr/0101-menu-section-visibility.md).

`make check` проверяет сохранение и повторное чтение скрытых пунктов, игнорирование неизвестных идентификаторов, обязательный доступ к настройкам, удаление и возврат групп, порядок меню и старт с учётом видимости и состояния аккаунта.

Для визуальной проверки определить эмулятор через `make devices`, затем выполнить `make run-profile DEVICE=<serial>`. Проверить:

- Снять все публичные галочки: пункты и заголовок «Каталог» исчезают. Включить один пункт: возвращаются только он и заголовок.
- Скрыть «Продолжить» и все личные списки: группы «Для меня» и «Мои списки» исчезают. Проверить их независимое восстановление.
- Скрыть все необязательные пункты и выполнить `make restart DEVICE=<serial>`: приложение открывает доступные «Настройки», выбор «При запуске» содержит только их.
- При скрытом «Сегодня» перейти вверх к поиску и вниз: фокус попадает на первый видимый пункт. Заголовки не получают фокус.
- Вернуть все галочки и перезапустить приложение: прежний стартовый раздел снова доступен. После проверки восстановить исходную видимость и значение предзагрузки.

Чтение сезонных сообщений сайта отдельно от прогресса аккаунта на «Чёрном зеркале»:

```bash
make mark-probe DEVICE=emulator-5554 MARK_PROBE_MODE=season-messages
make run-profile DEVICE=emulator-5554
```

Нужна существующая сессия эмулятора и запись сериала в личной выдаче. Сценарий делает только GET: сравнивает сообщения `/resume` с постоянными отметками пятого и шестого сезонов и примером «Хочу посмотреть». Выводит агрегированные числа, статусы и признаки наличия, без названий других сериалов, данных профиля, cookie и HTML. Правило генерации сообщений на сервере не объявляется установленным; наблюдения — в [описании API](api/web-api.md#прогресс-в-карточке-сериала).

## Проверка перехода к сериям из всех разделов

Регрессия 2026-11-07: карточка из «Топа» передавала диапазон «5–8», отсутствующий среди отдельных номеров. Выбор оставался пустым, и стрелка вниз ссылалась на неприкреплённый FocusRequester. Общая цель входа в ленту и сетку теперь использует выбранную доступную серию либо первый реальный элемент; это не подмена выбора для воспроизведения. Решение — [ADR-0112](adr/0112-episode-focus-without-selection.md).

Запустить `make check`, затем `make run-profile DEVICE=emulator-5554`. Открыть проблемную карточку: до ручного выбора видна кнопка «Выбрать серию»; `make key DEVICE=emulator-5554 KEY=DPAD_DOWN` выбирает первую доступную серию без запуска видео. При повторном открытии нажать OK на «Выбрать серию»: сетка получает начальный фокус, «Назад» возвращает на кнопку. Проверить обычный выбранный эпизод, длинную ленту и сетку, переход вниз на «Все серии» и возврат вверх.

Проверено в эмуляторе без запуска видео и изменения отметок аккаунта:

## Проверка коротких уведомлений

Стандарт проекта — системный `Toast.LENGTH_SHORT` через общий механизм [ADR-0113](adr/0113-short-system-notifications.md). В обработчиках действий использовать `showShortMessage`, в Compose для асинхронного состояния — `ShortMessageEffect` с текстом или `null`. Сбрасывать ошибку при новой попытке, чтобы повторная неудача снова дала уведомление; рекомпозиция сама по себе его не повторяет.

`make mark-menu-probe DEVICE=emulator-5554` использует автономную фикстуру без сети и записи аккаунта. Проверяет одинаковые координаты кнопок при загрузке, обновлении, сохранении, ошибках и подтверждении удаления. Снимки `03-refresh-error.png` и `05-save-error.png` показывают стандартный Toast снизу; `06-error-expired.png` сделан спустя четыре секунды при той же ошибке и фокусе. Проверено 2026-11-07: уведомление исчезло, кнопки и фокус сохранились.

После изменения уведомлений плеера `make home-probe DEVICE=emulator-5554` подтвердил реальное видео: на двух снимках воспроизведения кадры различаются, на двух снимках паузы совпадают; после перемотки виден другой кадр. Возврат прошёл, настройки и локальный прогресс восстановлены, отметки аккаунта не записывались. `make check` и `make build-profile` прошли.

## Проверка стабильной строки прогресса

Общий принцип для всех экранов — [ADR-0114](adr/0114-stable-async-layout.md). В карточке строка «Прогресс:» существует до загрузки страницы и прогресса аккаунта. При обновлении известное значение сохраняется; неизвестное показывает загрузку, затем «нет данных» при отсутствии результата. Отдельный `progressLoading` завершается также при пустом ответе и ошибке. При смене/закрытии карточки её прежнее состояние сбрасывается; поздний ответ не возвращает старую запись.

`make details-progress-probe DEVICE=emulator-5554` запускает автономную фикстуру настоящего компонента строки в debug-активности. Проверяет первый кадр без состояния карточки, ожидание прогресса, готовые счётчики, обновление известных счётчиков, отсутствие данных и ошибку. В первых шести состояниях сравнивает верхнюю координату строки, полный прямоугольник кнопки серии и сохранение фокуса. Использует запись, разобранную общим парсером: сообщение «Сезон 2 из 5» игнорируется до передачи в интерфейс при отсутствии прогресса, загрузке, ошибке и отличающемся пользовательском счётчике. Обычное сообщение «Новые серии» остаётся видимым. Исключённая подпись не создаёт пустую строку в интерфейсе; геометрия и фокус сохраняются. Сохраняет PNG и `result.json` в `build/details-progress-probe`; каталог можно задать через `DETAILS_PROGRESS_PROBE_OUT`. Сеть и аккаунт не используются.

Проверено в эмуляторе 2026-11-07: все шесть состояний прошли, снимки просмотрены, геометрия и фокус сохранились. В обычной карточке «Топа» проверено отображение готового прогресса. Для детерминированной проверки загрузки используется фикстура: кэш сайта может вернуть значение раньше первой ручной проверки даже при замедленной сети. Сетевая задержка эмулятора возвращена в `none`. `make check` прошёл: 507 JVM-тестов, 39 Python-тестов, сборка и lint.

Уточнение 2026-11-10 по ADR-0130: прошли восемь состояний `make details-progress-probe`, снимки просмотрены. Сообщение «Сезон N из M» исключается общим парсером при любых данных прогресса; обычные сообщения сайта сохраняются. Отдельная строка под исключённую подпись не создаётся, геометрия и фокус не меняются. `make check`: 620 JVM-тестов, 39 Python-тестов, сборка и lint. Profile-сборка прошла; в шестом сезоне «Чёрного зеркала» проверены отсутствие подписи и пустой строки под ней, сохранение пользовательского прогресса и позиции остановки. Отметки аккаунта не изменялись.

### Проверка фильтров «Лучших сериалов»

`make run-profile DEVICE=emulator-5554`: открыть «Лучшие сериалы», перейти с карточки вверх и влево к воронке. В общей панели выбрать жанр и период, подтвердить «Применить» слева. Проверить выдачу, подписи и число условий, отмену черновика через «Назад», немедленный «Сбросить», возврат фокуса и сохранение выбора после `make restart DEVICE=emulator-5554`. Периоды: день, неделя, месяц; сброс — любой жанр и день. Соседняя подборка «Топ» сохраняет собственную выдачу.

Публичный контракт можно повторить загрузчиком:

```sh
make site-fetch SITE_URL='https://seasonvar.ru/?mode=top&genre=17&period=7' SITE_OUT=<каталог-сессии>/best-comedy-week.html
```

`make check` проверяет раздельные кэши, серверный выбор, устаревший жанр, ошибки, сброс и отмену поздних ответов на обезличенных фикстурах. Дополнительные переключатели сайта пока не реализованы.

`make best-filters-probe DEVICE=emulator-5554 BEST_FILTERS_PROBE_OUT=<каталог-сессии>/best-filters` проверяет дополнительные переключатели «Лучших сериалов»: восемь POST отдельно у гостя и с существующей сессией эмулятора, специальную пустую выдачу, неизменность обычного GET и постоянных отметок. Проверка не запускает видео и не записывает историю/отметки; в отчёт попадают только агрегированные признаки. На приставке команда запрещена.

В панели с пульта проверить прокрутку до последней галочки, отмену черновика, применение сочетания, пустой результат и немедленный сброс с возвратом «Показывать отечественные». После перезапуска должны восстановиться общие условия и личные галочки текущего аккаунта. В гостевом наборе отсутствуют смотримые, история и чёрный список. Переключатели качества и доступности отражают правила выдачи сайта, а не подтверждённый запуск каждого видео.

`make public-filters-probe DEVICE=emulator-5554 PUBLIC_FILTERS_PROBE_OUT=<каталог-сессии>/public-filters` повторяет исследование публичных фильтров у гостя и в существующем аккаунте: по 13 форм для каждой боковой подборки и дополнительные GET «Сегодня»/«Анонсов». Отчёт сравнивает ответы с исходными и проверяет неизменность постоянных отметок. Команда только для эмулятора, не запускает видео, не экспортирует cookie или тела личных страниц. Результат исследования на 09.11.2026 — проверенные параметры не применяются; при изменении сайта результаты надо пересмотреть, а не автоматически включать кнопки.

`make history-filters-probe DEVICE=emulator-5554 HISTORY_FILTERS_PROBE_OUT=<каталог-сессии>/history-filters` читает элементы авторизованной истории и сравнивает безопасные GET с исходной последовательностью записей. В отчёте только число записей, наличие элементов, имена публичных обработчиков и результаты сравнения. Команда не отправляет запросы поиска, записи или очистки и запрещена для физической приставки. Поиск истории исключён из приложения по ADR-0123; первоначальная разовая проверка его POST-контракта описана в API.

### Проверка очистки истории

`make history-clear-probe DEVICE=emulator-5554 HISTORY_CLEAR_PROBE_OUT=<каталог-сессии>/history-clear` проверяет диалог на изолированном локальном состоянии: начальный фокус «Отмена», отмену по OK и «Назад», переход к подтверждению, блокировку повторного OK, сохранение геометрии и фокуса при выполнении и ошибке. Запросы к аккаунту не отправляются. Снимки `01-confirmation.png` и `02-clearing.png` необходимо просмотреть визуально. Контракт формы, контрольное чтение, ошибки и сброс старой очереди проверяются JVM-тестами в `make check`.

В реальном интерфейсе эмулятора проверять расположение корзины, переходы между корзиной, видом, обновлением и карточками и закрытие подтверждения. Не подтверждать удаление настоящей истории ради тестирования. Установка на приставку и живое удаление не входят в эту команду.

### Выравнивание кнопок

`make button-layout-probe DEVICE=emulator-5554 HISTORY_CLEAR_PROBE_OUT=<каталог-сессии>/button-layout` проверяет общий `ThemeButton` и диалог очистки на локальных данных. Проверка получает координаты символов через Android Accessibility и сравнивает центр текста с центром кнопки; отдельно проверяет компактные соседние кнопки, явное выравнивание меню слева и столбец галочки. Для диалога проверяются начальное состояние, выполнение, фокус и блокировка повторного нажатия. Снимки `00-common-buttons.png`, `01-confirmation.png` и `02-clearing.png` необходимо просмотреть. Контракт — [ADR-0125](adr/0125-button-content-alignment.md).

`make ui-screens-probe DEVICE=emulator-5554 UI_SCREENS_PROBE_OUT=<каталог-сессии>/ui-screens` последовательно отрисовывает реальные компоненты всех лент, поиска, аккаунта, настроек, фильтров, карточки и «О программе» на синтетических данных. Открывает выбор стартового раздела, видимости меню, каналов, часов, DNS, приоритетов озвучек, фильтров, сезонов, переводов и сетку серий. Для действий измеряет положение текста; сохраняет снимки каждого состояния. Ошибки входа, загрузки озвучек и каталога задаются локально. Авторизация, загрузка APK и удаление истории в этом сценарии не выполняются; изменения настроек приложения не сохраняются. Меню отметок и центрирование кнопок его подтверждения проверяются отдельно через `make mark-menu-probe` (снимки `07-confirmation.png` и `08-confirmation-busy.png`), подтверждение истории — `make button-layout-probe`, видео и действия плеера — `make player-probe`. Все снимки требуют визуального просмотра. Для повторной проверки только диалогов доступна `make ui-dialogs-probe` с тем же параметром каталога результатов.
