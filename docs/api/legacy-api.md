# Старое API api.seasonvar.ru

Источник контракта: исходник `package/index.js` опубликованного npm-пакета `seasonvar-api@1.0.10` и [Ruby-клиент](https://github.com/avsej/seasonvar.rb/blob/35f5495c817892b707d3ed513e0ea72dbbd7107d/lib/seasonvar/client.rb). Это восстановленное описание старого интерфейса, не действующая официальная документация.

## Доступность

2026-11-01 Quad9 вернул `NXDOMAIN` для `api.seasonvar.ru` и по обычному DNS, и по DNS-over-HTTPS с проверкой TLS. Из этой проверки нельзя установить причину отсутствия записи или окончательно признать сервис закрытым. Текущий адрес API неизвестен.

Историческую страницу получения доступа указывали как `https://seasonvar.ru/?mod=api`. Её содержимое, выдача ключей, требования к премиуму и привязке IP в этом исследовании не подтверждены. Публичного метода получения API-ключа по логину и паролю в изученных обёртках нет.

## Транспорт

| Свойство | В изученных реализациях |
| --- | --- |
| URL | `http://api.seasonvar.ru/` |
| Метод | `POST` |
| Тело | `application/x-www-form-urlencoded` |
| Ответ | JSON; полная схема неизвестна |
| Общие поля | `key` — персональный ключ, `command` — имя операции |
| Версионирование, квоты, пагинация | Не установлены |

HTTP указан как исторический адрес. Поддержка HTTPS не подтверждена; реальные учётные данные по открытому HTTP отправлять не следует.

Пример структуры запроса; идентификатор условный, ключ заменён заполнителем:

~~~http
POST http://api.seasonvar.ru/
Content-Type: application/x-www-form-urlencoded

key=<SEASONVAR_API_KEY>&command=getSeason&season_id=12345
~~~

Нельзя превращать этот пример в GET-ссылку с настоящим ключом: изученные клиенты используют POST, а URL попадёт в историю браузера и журналы.

## Команды

Во всех запросах дополнительно нужны `key` и `command`.

| command | Назначение | Параметры |
| --- | --- | --- |
| `getSerialList` | Каталог сериалов | Необязательные `country`, `genre`, `locale`, `sort`, `lastSeasonInfo`, `letter` |
| `getSeason` | Данные одного сезона | Обязательный `season_id` |
| `search` | Поиск по названию | Обязательный `query`; необязательные `country`, `genre` |
| `getUpdateList` | Последние обновления | `day_count`, `seasonInfo` |
| `getGenreList` | Жанры | Нет |
| `getCountryList` | Страны | Нет |
| `getSeasonList` | Сезоны сериала | Один из `id`, `name`, `letter` |

### getSerialList

| Параметр | Описание по обёрткам |
| --- | --- |
| `country` | Массив названий стран |
| `genre` | Массив названий жанров |
| `locale` | `domestic` или `foreign` |
| `sort` | Вложенная структура с `order` и `method` |
| `sort.order` | `kinopoisk`, `imdb`, `popular` или `year` |
| `sort.method` | README npm-пакета указывает `ASC` / `DESC`; Ruby-клиент передаёт `desc` для обратного порядка |
| `lastSeasonInfo` | Дополнительные сведения о последнем сезоне |
| `letter` | Начало названия или буква |

Точная серверная сериализация массивов, вложенного `sort` и булевых значений не проверена. Обёртки передают структуры своим HTTP-библиотекам; это не доказывает, что конкретный вариант `country[]`, `country[0]` или повторяющихся полей принимается сервером сейчас.

### getSeason

Поле `season_id` обозначает ID сезона. Его нельзя автоматически подменять ID сериала или порядковым номером сезона.

В npm-обёртке из результата обрабатываются `id`, `season_number` и `other_season`. Обёртка преобразует их к числам/массиву чисел. Из этого не следует, что сервер возвращает числа, что `other_season` всегда массив или что перечисленные поля исчерпывают ответ.

Схема озвучек, эпизодов, HD-доступа и видеоссылок этой команды не установлена.

### search

`query` — строка поиска. `country` и `genre` в обёртках обозначены массивами. Формат и ранжирование результатов не установлены.

### getUpdateList

npm-обёртка подставляет `day_count=7` и `seasonInfo=false` при отсутствии значений. Это значения по умолчанию клиента; серверные значения отдельно не проверены.

В обёртке обрабатываются поля элементов `id`, `year`, `create_time` и при наличии `season`. Единицы `create_time`, часовой пояс, порядок элементов и допустимый диапазон `day_count` не подтверждены.

### getGenreList / getCountryList

npm-обёртка рассматривает ответ как соответствие `ID → название` и создаёт массив объектов `{id, name}`. Такой массив — результат обработки в SDK, его нельзя документировать как исходный HTTP-ответ сервера.

### getSeasonList

Передаётся один из параметров:

- `id` — ID сериала;
- `name` — название;
- `letter` — начало названия.

Исходник npm-пакета действительно содержит `getSeasonList`. В его README последняя секция ошибочно вызывает `getCountryList`; при реализации ориентироваться на `index.js`, а не копировать этот пример.

## Ошибки

npm-обёртка проверяет верхнеуровневое `body.error` и преобразует его в исключение. Она также ищет строку `503` в текстовом теле и сообщает о чрезмерном количестве запросов. Это эвристика SDK, не опубликованный серверный контракт.

В коде есть сообщение про запрет доступа для IP, но наличие этой строки не подтверждает актуальный механизм привязки IP.

Для нового клиента отдельно различать сетевую ошибку, HTTP-ошибку, не-JSON ответ и JSON с ошибкой. Не принимать HTML страницы блокировки за результат API и не предполагать, что HTTP 200 означает успех.

## Чего нет в подтверждённом контракте

В изученных клиентах нет подтверждённых API-команд для логина по паролю, чтения личных закладок, записи прогресса, обновления токена и выхода из аккаунта. Семь команд выше описывают каталог. Для функций аккаунта найден отдельный [протокол веб-сайта](web-api.md).
