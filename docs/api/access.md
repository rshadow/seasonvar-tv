# Доступ к публичным страницам Seasonvar

## Закрепление ключей TLS в приложении

Android-клиенты используют общую конфигурацию [TlsPinSettings.kt](../../app/src/main/java/ru/seasonvar/tv/data/settings/TlsPinSettings.kt) по [ADR-0133](../adr/0133-centralized-tls-pinning.md). Pins — SHA-256 публичных ключей SPKI удостоверяющих центров. Совпадение одного из разрешённых ключей проверяется дополнительно к системному доверию и имени сервера. Ошибка не разрешает повторить запрос без pinning.

Проверено агентом 2026-11-10 через HTTPS с действующей проверкой цепочки и имени, включая транспорт обхода для Seasonvar:

| Домены | Наблюдаемая цепочка | Основной / резервный ключ |
| --- | --- | --- |
| `seasonvar.ru`, `www.seasonvar.ru`, `cdn.svstat.net` | Let’s Encrypt YR2 → Root YR → ISRG Root X1 | Root YR / Root YE |
| `github.com`, `api.github.com` | Sectigo DV E36 → Root E46 | Sectigo E46 / R46 |
| `objects.githubusercontent.com`, `release-assets.githubusercontent.com` | Let’s Encrypt YR1 → Root YR → ISRG Root X1 | Root YR / Root YE |
| `dns.quad9.net` | DigiCert G3 TLS ECC SHA384 2020 CA1 → Global Root G3 | DigiCert G3 / G2 |
| `cloudflare-dns.com` | SSL.com SSL Intermediate CA ECC R2 → SSL.com Root Certification Authority ECC | SSL.com ECC / RSA |

Root YR присутствует в проверенной цепочке и при кросс-подписи через X1; сам X1 не закреплён. Резервные ключи взяты из опубликованных корней соответствующих центров. Смена ключа промежуточного или серверного сертификата внутри закреплённой цепочки допустима. При переходе на другой корень требуется обновление приложения. Нельзя автоматически заменять pins значениями из не прошедшего проверку соединения.

Все запросы приложения к Seasonvar проходят через `SiteClient` и `NetworkClients`: вход, списки, отметки, карточки, Coil, плейлисты и Media3. Клиенты с cookie и медиаклиенты наследуют политику при любых комбинациях DNS/DPI. `GitHubUpdateSource` использует отдельный закреплённый клиент для метаданных, описаний релизов и APK, включая каждый разрешённый редирект. DoH также имеет отдельный закреплённый клиент. Динамические сторонние видеохосты сохраняют стандартную проверку TLS. Внешний браузер и исследовательские Python-скрипты используют собственные транспорты; описанный ниже загрузчик сохраняет стандартную проверку TLS.

Источники: [проверка OkHttp в CodeQL](https://codeql.github.com/codeql-query-help/java/java-android-missing-certificate-pinning/), [Android о SPKI и резервных ключах](https://developer.android.com/privacy-and-security/security-config#CertificatePinning), [цепочки Let’s Encrypt](https://letsencrypt.org/certificates/), [корни Sectigo](https://support.sectigo.com/Com_KnowledgeDetailPage?Id=kA0Uj0000004IrB), [DigiCert G3](https://cacerts.digicert.com/DigiCertGlobalRootG3.crt.pem) и [G2](https://cacerts.digicert.com/DigiCertGlobalRootG2.crt.pem). Публичные PEM для проверки констант хранятся в тестовых ресурсах и не добавляются в доверенное хранилище приложения.

## Прокси приложения

По [ADR-0139](../adr/0139-http-connect-proxy.md) пользователь может направить Seasonvar, постеры, плейлисты и видео через свой HTTP CONNECT-прокси. Basic-авторизация необязательна и обрабатывается только на уровне прокси по 407, без передачи Proxy-Authorization сайту. TLS и pins действуют внутри туннеля, прямого повторения при ошибке нет. DoH для разрешения имени прокси и обновления GitHub не проходят через этот туннель. SOCKS5 добавлен в ту же настройку по [ADR-0140](../adr/0140-socks5-proxy.md): удалённое разрешение имён, необязательная авторизация [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929.html) без глобального обработчика; CONNECT по [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928.html). Основные правила HTTP: [RFC 9110, CONNECT](https://www.rfc-editor.org/rfc/rfc9110.html#name-connect) и [RFC 7617, Basic](https://www.rfc-editor.org/rfc/rfc7617.html).

## DNS в приложении

Системный DNS, Quad9 DoH и Cloudflare DoH выбираются независимо от DPI-обхода по [ADR-0138](../adr/0138-cloudflare-dns-provider.md). Quad9 остаётся начальным значением. Для Cloudflare используется [официальный endpoint](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/) `https://cloudflare-dns.com/dns-query`, bootstrap `1.1.1.1`, бинарный DNS wireformat по HTTPS. Проверка TLS и имени `cloudflare-dns.com` сохраняется; дополнительные pins взяты из [публичного репозитория SSL.com](https://www.ssl.com/repository/).

## Исследовательский загрузчик

Загрузчик [scripts/fetch-seasonvar.py](../../scripts/fetch-seasonvar.py) получает HTML и JSON оригинального сайта из сети, где обычный HTTPS блокируется. Нужны Python 3.12+ и curl с поддержкой HTTP/2; сторонние Python-пакеты не требуются.

## Команды

Из корня проекта:

~~~bash
make site-fetch
~~~

Главная страница сохраняется в `build/site/index.html`. Успешный запуск выводит HTTP-статус, размер тела, число блоков обновлений, применённую стратегию, адрес сервера и путь результата. Заголовки ответа и содержимое страницы в консоль не выводятся.

Поиск:

~~~bash
make site-fetch SITE_URL='https://seasonvar.ru/autocomplete.php?query=Игра престолов' SITE_OUT=build/site/search.json
~~~

Подборка «Обновления» отдельным AJAX POST, без загрузки главной:

~~~bash
make site-updates
~~~

HTML-фрагмент сохраняется в `build/site/updates.html`. Загрузчик отправляет форму `ganre=&country=&block=0&main=1`, `X-Requested-With: XMLHttpRequest` и `Referer: https://seasonvar.ru/`; редирект AJAX считается ошибкой. Флаг скрипта `--sidebar new` фиксирует этот публичный маршрут и форму.

Подборка «Топ» использует ту же форму и режим `pop`:

~~~bash
make site-top
~~~

Результат — `build/site/top.html`, флаг скрипта — `--sidebar pop`. Общие настройки стратегии, DNS и тайм-аутов те же, что у `make site-updates`.

Подборка «Новинки» использует режим `newest`:

~~~bash
make site-newest
~~~

Результат — `build/site/newest.html`, флаг скрипта — `--sidebar newest`. Форма и настройки доступа общие для всех трёх AJAX-подборок.

«Лучшие сериалы» загружаются отдельной страницей:

~~~bash
make site-best
~~~

Результат — `build/site/best.html`, адрес — `https://seasonvar.ru/?mode=top`. Проверка `div.news` применяется к главной без параметров; у страниц с query-параметрами свой контракт, который проверяет парсер приложения.

Можно передать другую публичную страницу Seasonvar через `SITE_URL`. Пробелы и кириллица в пути и запросе кодируются автоматически.

Проверки без интернета:

~~~bash
make site-test
~~~

Они также входят в `make test` и `make check`.

## Как работает доступ

1. Адреса сайта получаются от Quad9 через DNS-over-HTTPS. Имя `dns.quad9.net` закрепляется на bootstrap-адресе `9.9.9.9` только для этого запроса; curl проверяет TLS-сертификат и использует HTTP/2.
2. Python формирует TLS ClientHello для исходного имени сайта. В режиме `default` TLS-запись разделяется за пять байт до конца SNI, первый байт отправляется отдельно, затем отправляется срочный TCP-байт `a` и оставшаяся часть.
3. Дальнейший TLS-обмен выполняется штатным OpenSSL через `ssl.MemoryBIO`. Проверяются доверенная цепочка сертификата и имя сайта. Данные запроса остаются зашифрованными.
4. Отправляется анонимный GET по HTTP/1.1 либо POST формы боковой подборки при `--sidebar new` / `--sidebar pop` / `--sidebar newest`. Разбор HTTP учитывает chunked-передачу; поддерживается gzip. Размер тела ограничен 8 МиБ.
5. При сетевой ошибке пробуется следующий адрес Quad9. Редиректы разрешены только на HTTPS-адреса `seasonvar.ru` и `www.seasonvar.ru`. У главной без параметров проверяется наличие блоков `div.news`.
6. Успешное тело ответа атомарно сохраняется в файл. Ошибка возвращает ненулевой код и сохраняет прежний файл, если он уже существовал.

Использован прежний исследовательский `dpitest.py` и найденная в предыдущем обсуждении рабочая стратегия ByeByeDPI `-o1 -a1 -r-5+se`. Параметр `-a1` относится к фейковым UDP-пакетам: в этом HTTPS-загрузчике применяется только TCP/TLS-часть стратегии. Это целевой загрузчик, а не полная реализация ByeDPI или SOCKS-прокси. Значение параметров сверено с [README ByeDPI](https://github.com/hufrea/byedpi/blob/main/README.md).

Системные DNS, прокси и настройки приставки не меняются. Учётные данные и cookie не используются; работу авторизации этим скриптом пока не проверяем.

## Сжатие в приложении и исследовательском загрузчике

Проверено агентом 2026-11-09: приложение уже использует прозрачное gzip-сжатие OkHttp 5.5.1. [SiteClient](../../app/src/main/java/ru/seasonvar/tv/data/SiteClient.kt) не устанавливает `Accept-Encoding`; OkHttp добавляет `Accept-Encoding: gzip` и распаковывает ответ до чтения HTML/JSON. [NetworkClients](../../app/src/main/java/ru/seasonvar/tv/data/network/NetworkClients.kt) сохраняет этот механизм и при обходе блокировок: меняются TLS-сокет и версия HTTP, а не обработка сжатия. Отсутствие `Content-Encoding` на уровне кода, читающего готовый ответ, не доказывает отсутствие gzip: после прозрачной распаковки OkHttp удаляет этот заголовок.

Живая анонимная проверка выполнена в отдельном JVM-процессе со скомпилированными `NetworkClients` и `DpiSocketFactory` проекта и его версиями зависимостей. Временно добавленный сетевой наблюдатель измерял тело до распаковки, а обычное чтение — после неё; исходники приложения и устройства не менялись. Во всех семи запросах с обходом получены HTTP 200, `Accept-Encoding: gzip` в запросе и `Content-Encoding: gzip` в сетевом ответе:

| Выдача | Запрос | Сжатое тело, байт | После распаковки, байт |
| --- | --- | ---: | ---: |
| Сегодня | `GET /` | 74 530 | 485 507 |
| Обновления | `POST /ajax.php?mode=new` | 4 134 | 31 007 |
| Топ | `POST /ajax.php?mode=pop` | 3 132 | 28 150 |
| Новинки | `POST /ajax.php?mode=newest` | 3 592 | 30 245 |
| Лучшие сериалы | `GET /?mode=top` | 63 812 | 256 527 |
| Анонсы | `GET /?mode=soon` | 41 045 | 177 952 |
| Поиск «Наруто» | `GET /autocomplete.php?query=Наруто` | 601 | 2 467 |

Числа относятся к телам конкретных ответов, без транспортных заголовков и TLS. Обычный клиент и клиент обхода также прошли локальный контроль автоматического запроса и распаковки gzip. Прямой живой запрос без обхода в этой сети завершился таймаутом до HTTP-ответа; фактическое сжатие прямого ответа сайта этим прогоном не подтверждено.

Личные списки и история используют тот же сетевой клиент с добавленным cookie-хранилищем; отдельной настройки, запрещающей gzip, нет. Авторизованные ответы в этом прогоне не читались и не измерялись.

Сам `scripts/fetch-seasonvar.py` явно отправляет `Accept-Encoding: identity`, хотя умеет распаковать gzip, если сервер его вернул. Поэтому размеры файлов из штатных `make site-*` нельзя считать объёмом сетевого трафика приложения. Отдельная проверка сжатого общего каталога описана в [catalog-filters.md](catalog-filters.md#проверка-выдачи-каталога-и-рейтингов--09112026).

Для будущих запросов каталога следует использовать общий клиент и сохранять штатное прозрачное сжатие. Ручная установка `Accept-Encoding` меняет поведение OkHttp: в его стандартном обработчике автоматическая распаковка включается при самостоятельном добавлении этого заголовка клиентом. В текущей реализации добавлять заголовок или вторую распаковку не требуется.

## HEAD и условное HTTP-кэширование

Проверено агентом 2026-11-09, анонимно, через те же сетевые классы проекта с обходом блокировок. Выполнены 23 запроса, ошибок транспорта не было; аккаунт и устройства не использовались.

| Ресурс | HEAD | Метки и свежесть | Условный GET |
| --- | --- | --- | --- |
| Главная, `/?mode=top`, `/?mode=soon`, поиск «Наруто», `/serialinfo/45962/` | HTTP 200, без тела | В GET и HEAD нет `ETag`, `Last-Modified`, `Cache-Control` и `Expires` | Диагностический `If-Modified-Since` со значением `Date` первого ответа дал HTTP 200 и полное тело на всех пяти маршрутах |
| Три боковые AJAX-подборки и фильтрованный каталог | Не подменяли штатный POST на HEAD | В ответах POST нет `ETag`, `Last-Modified`, `Cache-Control`, `Expires` и `Content-Location` | Стандартный сценарий GET/304 для этих POST не подтверждён |
| [Постер 45962](https://cdn.svstat.net/oblojka/45962.jpg) | HTTP 200, без тела | GET и HEAD содержат `ETag`, `Last-Modified`, `Cache-Control: max-age=604800` и `Expires` | GET с исходным `ETag` в `If-None-Match` и отдельный GET с исходным `Last-Modified` в `If-Modified-Since` оба дали HTTP 304 без тела |

Постер в этой проверке: 68 635 байт, `ETag: "68da6d8b-10c1b"`, `Last-Modified: Mon, 29 Sep 2025 11:29:15 GMT`. Метки относятся к конкретному файлу и не являются константами клиента. Условную ревалидацию именно через Coil на устройстве этим прогоном не проверяли; приложение уже использует его общий кэш изображений.

Наличие HEAD без версии содержимого не позволяет надёжно определить неизменность списка. `Date` сообщает время формирования HTTP-сообщения и не является версией выдачи; в этой проверке оно использовалось только для диагностического условного запроса. Результат ограничен перечисленными анонимными маршрутами и датой; авторизованные страницы не проверялись.

При наличии серверного валидатора достаточно условного GET: неизменившийся ресурс может вернуть 304 без тела, изменившийся — новый ответ. Предварительный HEAD добавляет запрос, а HEAD к URL обработчика POST не проверяет результат формы с выбранными условиями. Семантика — [HEAD](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.2), [If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2) и [POST](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.3) в RFC 9110. Текущий `SiteClient.execute` принимает HTTP 200; поддержку 304 для текстовых ответов нельзя считать уже реализованной только на основании поддержки сервера.

## Параметры Makefile

| Переменная | Назначение |
| --- | --- |
| `SITE_URL` | Публичный HTTPS URL сайта; по умолчанию главная |
| `SITE_OUT` | Файл результата; по умолчанию `build/site/index.html` |
| `SITE_STRATEGY` | `default` — TLS-фрагментация и OOB; `tlsrec` — только фрагментация; `direct` — обычный TLS для сравнения |
| `SITE_TIMEOUT` | Тайм-аут подключения и отдельный общий срок TLS/HTTP-обмена с одним адресом, по умолчанию 10 секунд |
| `SITE_SOURCE_IP` | Необязательный локальный IPv4 исходящего подключения к сайту |
| `SITE_IP` | Необязательная подмена адреса назначения для диагностики; обычный режим получает адреса заново из Quad9 |

При нескольких адресах общее время запроса может превышать `SITE_TIMEOUT`. IP сервера не следует закреплять постоянно.

Файлы в `build/` игнорируются Git. При сохранении ответа в другой каталог следует отдельно проверить его содержимое перед добавлением в репозиторий.

При выключении используется штатный TLS OkHttp. DNS выбирается независимо: «Системный» / «Quad9 DoH» (по умолчанию Quad9 DoH), согласно [ADR-0012](../adr/0012-dns-provider-setting.md). Настройки приложения не меняют режим самостоятельного Python-загрузчика.
