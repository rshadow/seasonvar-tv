## Срок премиума

Сессия и личные страницы не экспортировались; ниже только обезличенные примеры. Оплата, изменение подписки и запросы записи не выполнялись.

| Источник | Проверенный результат | Применимость |
| --- | --- | --- |
| Меню аккаунта | Ссылка `/premium`, текст `Премиум активен до 31.12.2030` | Выбранный источник: смысловой путь и явно подписанная дата во всех четырёх ответах |

Меню аккаунта разбирается в уже проверенной области авторизации; внутри неё срок определяется по ссылке оригинального HTTPS-сайта `/premium` без query и тексту, а не по CSS-классу. Повтор одинаковой даты допустим. Невалидная или противоречащая дата означает неизвестный срок; отсутствие сведений не выдаётся за истечение сессии. Простой пункт «Премиум» / «Премиум аккаунт» без даты трактуется как неактивная подписка; этот вариант покрыт обезличенными тестами, отдельный живой аккаунт без премиума в данном исследовании не использовался. Даты тарифов, комментариев, футера, чужого профиля и внешних ссылок не учитываются.

Срок передаётся в `AccountUser.premium` при входе и проверке сессии. Для отображения не нужны отдельные GET `/premium` или профиля, расчёт оставшихся дней и часовой пояс клиента. При открытии карточки аккаунта выполняется обычное чтение `/resume`; обновление сведений того же пользователя сохраняет поколение сессии. ## Общие правила

- Сохранять cookie в одной сессии между входом, страницами, AJAX-запросами и загрузкой плейлистов.
- Для форм использовать `application/x-www-form-urlencoded`, кодируя значения в UTF-8.
- В изученных клиентах передаются браузерный `User-Agent` и `Referer`. Для `ajax.php` и `jsonMark.php` Go-клиент добавляет `X-Requested-With: XMLHttpRequest`.
- Часть ответов — HTML либо HTML с JavaScript. Расширение `.php` не означает JSON.
- Сохранять точные пути страниц из ответов сайта. ID недостаточно, чтобы надёжно восстановить `/serial-<id>-<slug>.html`.
- Не смешивать с оригинальным сайтом домены `seasonvar.zone` / `seasonvar.net` или чужие прокси.

Пути вида `/seasonvar/login` и `/seasonvar/mark` из Go-проекта принадлежат его собственному прокси. Это не эндпоинты Seasonvar. В этом документе приведены его исходящие запросы к оригинальному сайту.

## 1. Вход и сессия

### Вход

~~~http
POST /?mod=login HTTP/1.1
Host: seasonvar.ru
Content-Type: application/x-www-form-urlencoded
Referer: https://seasonvar.ru/

login=<EMAIL_OR_LOGIN>&password=<PASSWORD>
~~~

Это схема тела с заполнителями, не реальные учётные данные.

Kotlin-клиент сначала делает `GET /` для начальных cookie, затем отправляет форму с `login` и `password` и следует редиректам. Go-клиент не следует редиректу и забирает `svid1` непосредственно из `Set-Cookie`.

Оба подхода нужно проверить на текущем сайте. Наличие HTTP 200 не подтверждает вход: после сохранения cookie следует прочитать личную страницу и проверить признак авторизации.

### Реализация нативного входа

2026-11-03 реализована цепочка: GET формы `/?mod=login` → POST `login`/`password` → GET `/resume` той же временной cookie-сессией. GET формы и её два поля проверены анонимно на оригинальном сайте. В эмуляторе запрос с вымышленной учётной записью завершился сообщением о неверном логине/пароле; 2026-11-03 пользователь подтвердил успешный вход на приставке, агент проверил восстановление сессии после обновления приложения без повторного пароля.

Редиректы входа 301/302/303 переводятся в GET только на оригинальном HTTPS-домене. Пароль передаётся исключительно в теле POST. Cookie с областью domain/path/expiry сохраняются после подтверждения аккаунта, в зашифрованном хранилище устройства. Сессия сайта используется для страниц и плейлистов, но не передаётся CDN. Подробности — [ADR-0033](../adr/0033-account-and-resume.md).

### Проверка входа

Найденные признаки HTML:

| Клиент | Признак |
| --- | --- |
| Go | Ссылка `/profile/<uid>` |
| Kotlin | Ссылка, содержащая `mod=logout`, либо `mod=synch` |

Go-клиент использует `Cookie: svid1=<SESSION>`. Для нашего адаптера безопаснее cookie jar с исходными domain/path/expiry, чем допущение об одной cookie. Указанные в стороннем проекте «30 дней» — наблюдение автора, не подтверждённая гарантия срока жизни.

Пустой список при истёкшей сессии должен отличаться от пустого списка авторизованного пользователя. Проверить это нужно в HTML того же ответа.

### Выход

Kotlin-клиент вызывает `GET /?mod=logout`. При реализации отправить запрос с текущей сессией, затем очистить локальное состояние и личный кэш; результат выхода проверить повторным чтением личной страницы.

Сценарии CAPTCHA, двухфакторной авторизации и входа через соцсети по этим источникам не установлены.

## 2. Поиск

~~~http
GET /autocomplete.php?query=<URL_ENCODED_QUERY> HTTP/1.1
Host: seasonvar.ru
~~~

[Открыть поиск «Игра престолов»](https://seasonvar.ru/autocomplete.php?query=%D0%98%D0%B3%D1%80%D0%B0%20%D0%BF%D1%80%D0%B5%D1%81%D1%82%D0%BE%D0%BB%D0%BE%D0%B2)

~~~bash
curl --get 'https://seasonvar.ru/autocomplete.php' \
  --data-urlencode 'query=Игра престолов' \
  --user-agent 'Mozilla/5.0' \
  --header 'Accept: application/json'
~~~

В изученных клиентах этот запрос выполняется без авторизации. Пользователь подтвердил ответ в своём браузере; наличие ранее установленной cookie в этом браузере не проверялось. Ответ содержит `query`, параллельные массивы `suggestions.valu`, `suggestions.kp`, `data` и `id`.

Полный присланный ответ сохранён в [examples/autocomplete-game-of-thrones.json](examples/autocomplete-game-of-thrones.json). Все четыре массива имеют длину 14; значения `id` — строки. Первый результат — сезон 1, ID `2219`; сезон 8 имеет ID `22063`. Это конкретная поисковая выдача, не полный каталог сервиса.

Иллюстрация минимальной формы ответа; значения условные, это не запись ответа сервера:

~~~json
{
  "suggestions": {
    "valu": ["Название / Original title (1 сезон)"]
  },
  "data": ["serial-12345-example-1-season.html"],
  "id": ["12345"]
}
~~~

В выдаче только из сериалов сопоставлять элементы по индексу. Для смешанной выдачи учитывать описанные ниже разделители. Проверять длины массивов и типы; сохранять возвращённый путь, разрешая его относительно базового URL. Присланный ответ подтверждает HTML в `suggestions.kp`: встречаются пустые строки и `7.67</i>`. В названии восьмого сезона есть ведущий `</i>`. При показе названия и рейтинга очищать HTML; не выполнять его. Не пытаться выводить название или номер сезона из slug: например, ID `2219` возвращён с путём `serial-2219--He_vse_starki_umrut----_psxskbl-00001---sezon.html`.

2026-11-02 агент повторно проверил анонимный запрос «Игра престолов»: 14 результатов в прежнем порядке. Запрос без совпадений возвращает `{"query":"…","suggestions":null,"data":null,"id":null}` — это корректная пустая выдача. Ответ имеет `Content-Type: text/html; charset=UTF-8`, хотя тело — JSON; формат проверяется по содержимому. Проверенный Android-клиент использует этот эндпоинт и общие сетевые настройки. Команда для повторения: `make site-search SEARCH_QUERY='Игра престолов'`; файл — `build/site/search.json`.

2026-11-02 агент проверил все префиксы `n`, `na`, `nar`, `naru`, `narut`, `naruto`. Сайт вернул соответственно 50, 50, 50, 37, 6 и 5 сериалов. Короткие запросы дополнительно содержат актёров (`actor/…`), теги (`tag/…`) и HTML-разделители с пустым `data`. Для разделителя нет элемента в `id`: например, у `naru` 39 названий/путей/рейтингов и 38 ID. `suggestions.valu`, `suggestions.kp` и `data` сопоставляются по одному индексу; индекс `id` увеличивается только для непустого пути. Актёры и теги потребляют ID, но не являются карточками сезонов. Не выводить их идентификаторы как ID сериалов. Клиент показывает сериалы в порядке сайта; выдача только из актёров считается пустым списком сериалов. Реальные обезличенные ответы сохранены в `app/src/test/resources/search-*.json`; отдельный запрос `Narumi Takahira` подтвердил ответ только с актёром.

### Актёры и режиссёры — проверка 2026-11-13

Выдача актёра содержит `.pgs-search-actor[href]` с его точным путём и отдельные `.pgs-search-wrap`. В каждом блоке первая ссылка `.pgs-search-info a[href]` задаёт название и страницу сезона, вторая — оригинальное название; `p` содержит краткое описание. Повторные ссылки одного блока не являются отдельными сезонами. Подпись `Сезонов: N` сообщает количество сезонов, а не номер сезона из ссылки, и приложением не применяется. Проверенный свежий анонимный ответ для Орландо Блума содержит четыре записи; пагинация в нём не обнаружена. Проверка личности актёра отличает корректную пустую выдачу от посторонней страницы или страницы блокировки. Реализация перехода описана в [ADR-0153](../adr/0153-actor-series-list.md).

Проверено агентом без cookie: `GET /autocomplete.php?query=nar` возвращает отдельную группу актёров с путями `actor/<имя>` в `data`. GET по одному из возвращённых путей показал серверную выдачу сериалов: один сезон в `.pgs-search-wrap`, несколько ссылок внутри карточки ведут к одному ID. По ссылке актёра со страницы «Наруто» сервер вернул четыре сезона, включая исходный 2779. Это отдельный серверный источник, а не фильтрация загруженного каталога. Имена и точные пути брать из ответа сайта. Текущий поиск приложения пропускает результаты актёров и тегов.

Основная форма сайта отправляет `q` на `/search`, подсказки используют `/autocomplete.php?query=...`. Отдельного переключателя поиска по режиссёру или актёру в проверенной форме нет. На страницах сезонов 2779 и 2219 актёры имеют ссылки `/actor/...`, а режиссёр указан текстом без ссылки. Серверный интерфейс поиска по режиссёру не подтверждён; отсутствие такой возможности во всех интерфейсах сайта не установлено. Локальная фильтрация не рассматривается по решению пользователя.

Фотографии актёров находятся в `img[src]` внутри `.pgs-sinfo-actor a`, включая скрытую часть состава. Проверено агентом 2026-11-13 без cookie: миниатюра `/a/s/0/3487.jpg` имеет размер 30×30, крупные `/a/0/3487.jpg` и `/a/1/16433.jpg` — 360×570. Размеры других фотографий могут отличаться. Оригинальный `pg.player.min.js?25.4.1` для подсказки актёра удаляет `/s/` из адреса изображения. Запрос `/a/3/38105.jpg` вернул заглушку с котом 300×300; такая же заглушка подтверждена для `/a/0/0.jpg`. Источники изображений — HTTPS `cdn.svstat.net`; приложение использует крупную версию и общий кеш изображений. Копия заглушки из последнего адреса сохранена в `app/src/main/res/drawable/actor_placeholder.jpg` без изменения изображения.

## 3. Главная и подборки

### Главная

`GET /` возвращает HTML. 2026-11-01 загрузчик получил HTTP 200 и восемь блоков `div.news` с датами от 01.11.2026 до 25.10.2026; заголовки дат имеют формат `dd.MM.yyyy`. В тот же день Android-клиент получил 83 обновления, описания и постеры в эмуляторе API 34. Проверенный парсер читает:

| Данные | Селектор / атрибут |
| --- | --- |
| Блок обновлений | `div.news` |
| Дата блока | `div.news-head` |
| Карточка | `a[href][data-id]` |
| Название | `div.news_n` |
| Сезон | Собственный текст `div.news-w`, подпись `(N сезон)`, может отсутствовать |
| Изменения по сериям | `span.news_s` |

Сведения о сезоне из текстовой подписи — результат парсинга, не структурированное поле API. Если подписи нет, номер не задаём. Сохраняем порядок ссылок и удаляем только повторы одной пары «URL + обновление». ID из `data-id` используется в подтверждённом адресе постера `https://cdn.svstat.net/oblojka/<id>.jpg`.

Для «Сегодня» выбираем дату устройства в его часовом поясе, без подстановки вчерашней выдачи. Отсутствие `div.news`, неверная дата или карточка без названия/изменений считаются ошибкой разметки. Корректная главная без сегодняшнего блока даёт пустой результат. Это различие проверяется автономно.

### «Обновления»: прежний встроенный список

Первоначальная проверка 2026-11-02: анонимный `GET /` через загрузчик вернул 50 позиций подборки «Обновления» на 48 страниц сезонов. Эти же 50 позиций доступны в Android-клиенте. Список уже включён в HTML главной; отдельный POST для него не нужен. Он не фильтруется по дню: в этой проверке «Сегодня» пуст, поскольку последняя дата главной — 01.11.2026.

| Данные | Селектор / атрибут |
| --- | --- |
| Блок «Обновления» | `li[data-tabr=rside-new][data-tabgr=rightside]` |
| Карточка | `a.pst.rside-p[href]` |
| Название | `.rside-t` |
| Оригинальное название, необязательно | `.rside-t_en` |
| Номер сезона, необязательно | Собственный текст `.rside-ss`, подпись `Сезон N` |
| Серии и озвучка | Текст `span` внутри `.rside-ss` |
| Страница сезона | Точный `href` карточки |
| Новинка | Точный класс `rside-p-new` у ссылки карточки; отсутствие класса — без бейджа |

Сохранять порядок карточек. Одна страница сезона может присутствовать несколько раз с разными сериями/озвучками — такие позиции нельзя объединять по URL. Например, в проверенном ответе сезон `50804` содержит отдельные обновления `8 серия (DubLik)` и `8 серия (AniDub)`. Ключ записи учитывает URL и текст обновления. Постер использует подтверждённый адрес `https://cdn.svstat.net/oblojka/<id>.jpg`, ID берётся из проверенного пути страницы.

Отсутствующий блок или неполная карточка — ошибка разметки. Пустой блок без заглушки ошибки — пустая подборка. Пагинация этого списка не установлена.

В ответе 49 разных страниц сезонов: один сезон представлен двумя обновлениями. Состав и порядок могут меняться; в клиенте сохраняется порядок ответа, включая подпись `0 серия (RuDub)` у первой позиции проверенного снимка.

Приложение использует этот AJAX-маршрут по [ADR-0017](../adr/0017-updates-via-ajax.md), без запасного GET главной. Старое описание встроенной подборки выше сохраняет результат прежней проверки.

Названия в модели приложения разделены: `title` берётся из `.rside-t`, при его отсутствии/пустоте — из `.rside-t_en`; `originalTitle` сохраняет `.rside-t_en`. Для панели и полного описания вычисляется `fullTitle` без повтора одинаковых названий. Отсутствие обоих названий остаётся ошибкой разметки. Карточка списка использует только `title`. В «Сегодня» основное название берётся из собственного текста `.news_n`, дополнительное — из вложенного `span` без ведущего `/`; в нём может быть альтернативное русское название.

Бейдж «новинка» задан классом `rside-p-new`, он есть у 10 из 50 карточек сохранённого снимка. Проверенный CSS `pg.index.css?25.4.1` использует `.rside-p-new:before` с текстом `новинка`, фоном `#980c3d`, светлым текстом по центру и скруглёнными верхними углами. Приложение хранит этот признак как `isNew` и показывает его на постерах по [ADR-0018](../adr/0018-site-new-badge.md). Номер первой серии сам по себе не означает новинку.

Проверены также `Accept: application/json` с обычной формой и `Content-Type: application/json` с JSON-телом с теми же полями: в обоих случаях HTTP 200, заголовок `text/html; charset=UTF-8` и побайтово тот же HTML. Заголовок не включает JSON-режим; JSON-контракт этого маршрута не установлен.

Повторное сравнение 2026-11-02 выявило различие с видимой подборкой главной. Пользователь без входа в аккаунт видит «Хмельной сон», «Ты один знаешь меня», «Шальной последний босс явился!»; анонимный GET главной даёт ту же тройку. В анонимном AJAX перед ней находятся ещё 11 записей, начиная с «Оно: Добро пожаловать в Дерри», «Покемон: Горизонты», «Ранма 1/2 (2024)». Первые 39 ссылок главной побуквенно совпадают с позициями 12–50 AJAX. Кэш приложения совпадает с независимо полученным AJAX-ответом. Поэтому этот маршрут нельзя считать проверенным эквивалентом начальной видимой подборки главной. Разная задержка обновления серверных снимков — возможное объяснение, но внутренний механизм сайта не установлен.

Пустой фрагмент трактуется клиентом как пустой список. Заглушка `.pgs-msg`, посторонняя разметка или неполная карточка — ошибка контракта, хороший кэш при этом сохраняется. Пагинация не установлена.

## 4. Личные списки и продолжение просмотра

~~~http
GET /resume HTTP/1.1
Host: seasonvar.ru
Cookie: svid1=<SESSION>
Referer: https://seasonvar.ru/
~~~

Ответ — HTML, не JSON.

| Раздел | Найденная разметка |
| --- | --- |
| Есть обновления | `li[data-tabr="marks-new"]` |
| Нет новых серий | `li[data-tabr="marks-nonew"]` |
| Хочу посмотреть | `li[data-tabr="marks-want"]` |
| Посмотрел | `li[data-tabr="marks-watched"]` |
| На чём остановились, в Kotlin-клиенте | `div.pgs-marks-bn` |

Внутри списков используются `div.pgs-marks-el`, `data-marksel`, ссылки `/serial-…`, `.pgs-marks-name`, `.pgs-marks-current`, `.pgs-marks-last` и `.pgs-marks-mess`. Go-клиент извлекает прогресс из текста вида «N из M».

Не приравнивать локальное избранное стороннего приложения к спискам аккаунта сайта.

### Нативные личные списки

Приложение сначала проверяет собственный профиль в `.headblock-menu`: ссылка `/profile/<uid>` либо действия `mod=logout`/`mod=synch` на оригинальном сайте. Отсутствующая шапка — неизвестная разметка, гостевая шапка — отсутствие подтверждённой сессии. Профиль и аватар берутся из шапки; при отсутствии изображения остаётся иконка человека. Имя читается из видимого пункта раскрывающегося меню `[data-menur]`; `alt` изображения может содержать служебное `avatar` и не используется как имя — [ADR-0035](../adr/0035-account-display-name.md).

**Проверено агентом на Ugoos 2026-11-03 после входа пользователя:** текущая авторизованная страница не содержит `.pgs-marks-bn`. Строки `.pgs-marks-el[data-marksel]` находятся во вкладках `li[data-tabr="marks-new"]`, `marks-nonew`, `marks-want` и `marks-watched`. У гостя эти же вкладки существуют без подтверждённого профиля — их наличия недостаточно для авторизации.

Нативное «На чём остановились» читает текущий просмотр из `marks-new` и `marks-nonew` в порядке сайта. Название — `.pgs-marks-name`, сезон — `.pgs-marks-seas`, текст отметки — `.pgs-marks-current`, сообщение — `.pgs-marks-mess`, точный путь — из ссылки внутри строки. `data-marksel` задаёт идентичность записи; ID сезона берётся из пути, а не подменяется ID отметки. Разные записи с одним URL сохраняются. Фрагмент `#rewind=…` не выдаётся за подтверждённое время просмотра.

Планируемые и просмотренные сериалы не подмешиваются в текущий просмотр. Старый `.pgs-marks-bn` остаётся совместимостью для прежней разметки. Пустой результат возможен только после проверки профиля и структуры страницы. Синтетическая фикстура текущего формата — `account-resume-current.html`; решение — [ADR-0034](../adr/0034-resume-current-markup.md).

Разделы «Есть обновления», «Нет новых серий», «Хочу посмотреть» и «Посмотрел» читают соответственно только `marks-new`, `marks-nonew`, `marks-want` и `marks-watched` тем же авторизованным `GET /resume`. Скрытые вкладки также разбираются. Отсутствующая выбранная вкладка означает изменение разметки, а не пустой список. Разделы имеют независимое состояние в памяти; см. [ADR-0036](../adr/0036-personal-lists.md).

**Вкладка обновлений, проверка чтением 2026-11-06:** `marks-new` может одновременно содержать полностью отмеченный предыдущий сезон и частично просмотренный следующий сезон одного сериала. В проверенном ответе сообщение завершённого сезона указывает его номер из общего числа сезонов; `.pgs-marks-last` обеих строк содержит последнюю добавленную серию и озвучку. Ссылка завершённой записи по-прежнему ведёт на её собственный сезон и отметку, а не на следующий сезон. Точный серверный критерий включения в `marks-new` не установлен; его нельзя заменять только сравнением числа отмеченных и доступных серий выбранного сезона. Наш `PersonalFeed.UPDATES` повторяет эту вкладку без дополнительного отбора.

**Проверено чтением сайта 2026-11-06:** у одного сериала в `/resume` одновременно присутствуют отдельные записи нескольких сезонов, включая завершённый предыдущий и начатый следующий. Каждая строка ведёт на собственный сезон и серию через `href` с `rewind`. `AccountParser.resume` сохраняет обе записи в порядке вкладок; автоматического выбора последнего просмотренного сезона всего сериала здесь нет. В проверенной странице старый сезон остаётся самостоятельной записью. Это не означает отсутствия отметки следующего сезона. HTML аккаунта не сохранялся, операции записи при проверке не выполнялись.

Для исходных списков сайта остаётся прежнее поведение. В той же проверке ссылка начатого сезона передавала минуты и секунды в `rewind`, и отдельная страница сезона подтверждала это время. Текущий `EntrySelectionParser.markLink` извлекает только ID серии; точная позиция в карточке приложения берётся из локального `PlaybackProgress`, а не из времени этой серверной ссылки. В официальном `pg.marks.min.js` также подтверждён вопрос об удалении отметки предыдущего сезона после успешного `markSet`; без согласия старая отметка не удаляется. Приложение это предложение не выполняет, как зафиксировано в ADR-0056.

**Выбор серии веб-плеером, проверка исходного алгоритма 2026-11-06:** функции `parseHash` и `goToHash` из свежего официального `main.min.js` выполнены в изолированном JS-контексте на ссылках продолжения из авторизованного `/resume` и реальных `arEpisodes` страниц сезонов. Это проверка выбора серии по коду сайта, без запуска браузерного видео. `goToHash` выбирает эпизод только из `arEpisodes[mark.trans]` открытого сезона и не меняет страницу на другой сезон. При нулевом времени и наличии `next` берёт следующую серию; при наличии длительности может перейти к следующей и в последние 120 секунд. Для последней серии без `next` остаётся её собственный номер. Наличие начатой отметки другого сезона этот алгоритм не проверяет. Обычная отметка из `mark.href` и браузерная временная отметка также относятся к открытому сезону; `markAuto` читает ключ localStorage с его ID.



Поля `.pgs-marks-current` и `.pgs-marks-mess` разбираются отдельно. Сообщение «Сезон N из M» отбрасывается в общем парсере обычных и отфильтрованных личных списков, не сохраняется в `SeriesEntry.accountMark` и не используется как прогресс — [ADR-0130](../adr/0130-ignore-season-counter-message.md). Остальные сообщения и прогресс показываются в большой карточке одной строкой «Прогресс: … · …», где вторая часть — сообщение сайта без общей подписи. В открытой карточке прогресс находится под кнопками, сообщение остаётся в сведениях ([ADR-0111](../adr/0111-season-progress-below-controls.md)); в подпись миниатюры они не входят. При выборе другого сезона отметка исходного сезона сбрасывается — [ADR-0037](../adr/0037-account-mark-details.md).

2026-11-10 агент проверил свежие авторизованные ответы `/resume` и страниц сезонов в эмуляторе, без записи отметок. Сообщение `.pgs-marks-mess` вида «Сезон N из M» встречалось и в `marks-want`; у проверенного примера постоянная отметка воспроизведения отсутствовала, статус страницы был `-1` («Хочу посмотреть»). Во всех проверенных таких сообщениях N < M. Это наблюдаемая подсказка о сезоне, после которого есть более поздние сезоны, а не доказательство пользовательского прогресса; точное условие серверной генерации не установлено.

Для выбранного пользователем «Чёрного зеркала» `/resume` содержал шестой сезон с сообщением «Сезон 6 из 7» и отметкой воспроизведения. Пятого сезона в этой выдаче не было, на его странице отметка отсутствовала. Приложение получает сообщение из конкретной записи личного списка и не вычисляет его для всех сезонов. При отсутствии записи отсутствие сообщения не означает отсутствия последующих сезонов. Проверка — `make mark-probe DEVICE=emulator-5554 MARK_PROBE_MODE=season-messages`; отчёт содержит только числа и булевы признаки, без cookie, профиля и тел HTML.

### Прогресс в карточке сериала

2026-11-03 агент проверил внутри авторизованного приложения: `.pgs-marks-seas` содержит номер сезона отметки, `.pgs-marks-current` — пару эпизодов «N из M». В проверенной записи общее количество совпало с плейлистом стандартной озвучки; номер отметки совпал с исходными данными записи. Проверка выводила только булевы результаты, без содержимого аккаунта. `.pgs-marks-last` содержит сведения о последней серии, а не общий счётчик сезонов.

Раздел «Для меня → Продолжить» по [ADR-0091](../adr/0091-smart-continue-account-marks.md) отдельно читает постоянную отметку со страницы сезона, группирует данные по `data-id-serial` и передаёт целевое время в `EntrySelection.positionMillis`. Исходные парсеры и выдача списков сайта не меняются. По [ADR-0092](../adr/0092-personal-continue-history-only.md) включаются только сериалы, найденные в истории аккаунта, и сохраняется её порядок от новых просмотров к старым. Локальные даты активности не используются. По [ADR-0095](../adr/0095-history-first-continue-loading.md) `/resume` и история читаются одновременно; страницы сезонов загружаются только для сериалов из истории. Общий лимит четыре действует на все фазы, а повторные обращения к одному сезону объединяются на время обновления.

`AccountProgressParser` читает отметки из `marks-new`, `marks-nonew` и `marks-watched` авторизованного `GET /resume`, сохраняя связь с точным ID сезона. Сезон отметки / общее число сезонов — производная пара из номера в записи и числа разных ID в списке сезонов страницы. Это не количество полностью просмотренных сезонов. Отсутствующее или неоднозначное значение остаётся неизвестным.

Пара эпизодов читается непосредственно из `.pgs-marks-current`. Для `marks-watched` без пары полное количество может быть взято из доступного стандартного плейлиста; отсутствие отметки после проверенного авторизованного ответа означает ноль при известном общем количестве. Невалидный или противоречивый текст, неизвестный плейлист и ограничение просмотра не подменяются нулём. Публичный [pg.marks.min.js?25.4.1](https://cdn.svstat.net/asset/js/pg.marks.min.js?25.4.1) связывает действия отметок с отдельным сезоном `idSeason`; его статус «Посмотрел» не является глобальной статистикой сериала.

Модель `SeriesEntry.accountProgress` хранит значения раздельно; серия привязана к сезону. Полная карточка загружает снимок отметок в фоне. При смене сезона прежние значения очищаются. См. [ADR-0043](../adr/0043-account-progress-in-controls.md).

Чтение списков не записывает отметки на сайт. Точное продолжение с времени аккаунта остаётся отдельной возможностью. Запись `jsonMark.php` реализована и проверена 2026-11-04 в разделе о сохранении постоянной отметки. Фикстура `account-resume.html` полностью синтетическая; настоящие личные страницы и cookie в репозиторий не сохраняются.

### История просмотров

`GET /?mod=history` с cookie-сессией; следующие страницы — `GET /?mod=history&page=N`. 2026-11-03 анонимный запрос загрузчиком получил HTML с требованием авторизации; авторизованная структура исследована внутри Android-приложения. Публичные стили `https://cdn.svstat.net/asset/css/pg.history.css?25.4.1` подтверждают классы списка и пагинации.

| Поле | Разметка |
| --- | --- |
| Контейнер | `.pgs-history [data-result=history]` |
| Список | `.pgs-history-c` |
| Запись и точная страница сезона | `a[href]` внутри списка |
| Название | `b` внутри ссылки |
| Дата записи | `span` внутри ссылки; сохраняем исходный текст |
| Сезон и серия | собственный текст ссылки вида `, N сезон, M серия (озвучка)`; серия сохраняется отдельно, не берётся из ID сезона |
| Страницы | `.pgs-history-p a[href]`, ссылки могут повторяться сверху и снизу |

Порядок и повторы сохраняются. Внешние ссылки и изменённую разметку не заменяем пустой историей. Пагинация принимает только проверенный маршрут истории оригинального сайта и следующий по порядку положительный номер страницы. Клиент подгружает следующие страницы по мере прокрутки, сохраняет уже загруженные при ошибке и позволяет повторить запрос.

Скрипт страницы также содержит POST поиска (`history_search`, `query`) и очистки (`dellAllHistory`). Поиск исключён из приложения; очистка вызывается только после подтверждения. Само чтение истории не записывает отметки; запуск нативного воспроизведения синхронизируется отдельно по ADR-0117. Личные ответы не сохраняются на диск; фикстура `account-history.html` синтетическая. Решение — [ADR-0039](../adr/0039-account-viewing-history.md).

#### Поиск истории: проверка 2026-11-09

Встроенный обработчик `[data-input=history-search]` отправляет `POST https://seasonvar.ru/ajax.php` с формой `history_search=true&query=<текст>`, Referer страницы истории и cookie исходной сессии. В ответе присутствует `.pgs-history-c`; при отсутствии совпадений найден `.pgs-msg`.

В существующем аккаунте запрос известного названия вернул соответствующие записи, заведомо отсутствующее название — пустой список, пустая строка — исходную выдачу. GET-параметры `q` и `query` этот поиск не включают. История и постоянные отметки после проверки не изменились. Очистка (`dellAllHistory`) не вызывалась. Поиск сайта остаётся исследованным контрактом; в приложение он не добавляется по [ADR-0123](../adr/0123-history-without-search.md).

#### Очистка истории: контракт 2026-11-09

**Источник — встроенный обработчик оригинальной авторизованной страницы истории; реальное удаление не выполнялось.** Кнопка `[data-click=historydel]` отправляет AJAX `POST https://seasonvar.ru/ajax.php` с единственным полем формы `dellAllHistory=true` (именно с двумя `l` в `dell`), затем перезагружает страницу. Используются cookie исходной сессии, Referer `https://seasonvar.ru/?mod=history`, Origin `https://seasonvar.ru` и `X-Requested-With: XMLHttpRequest`. Структура тела ответа не установлена.

Клиент сначала читает историю и проверяет владельца аккаунта и контейнер списка. Уже пустая история не требует POST. После HTTP 200 повторяет авторизованный GET: успех означает отсутствие записей и следующей страницы. Неузнаваемая разметка, гостевая страница и оставшиеся записи считаются ошибкой. Запрос автоматически не повторяется; сетевой обрыв может означать уже выполненное удаление, поэтому история перечитывается через её ревизию. Отложенные записи старых запусков отбрасываются, новые просмотры снова создают историю.

Запрос и сценарии проверяются на синтетическом транспорте; диалог — `make history-clear-probe` без сетевых обращений. `make history-filters-probe` только читает страницу и проверяет признаки исходного обработчика. Живая проверка удаления всей истории аккаунта не проводилась. Поведение интерфейса и зависимых кэшей — [ADR-0124](../adr/0124-confirmed-history-clear.md).

#### Запись просмотра: `plStat.php`

**Проверено агентом 2026-11-08 в авторизованном эмуляторе, с разрешения владельца аккаунта.** Исходник оригинального [main.min.js?25.4.1](https://cdn.svstat.net/asset/js/main.min.js?25.4.1) связывает событие PlayerJS `new` с `svfunc.player.stat()`, который отправляет `POST /plStat.php`. По [PlayerJS сайта](https://cdn.svstat.net/js/playerjs77.js), версия 9.97.2, событие возникает при первом запуске и смене файла. Обычная пауза и продолжение используют другие события. Это учёт запуска файла, а не периодическое сохранение позиции и не достижение порога просмотра.

Запрос — форма `application/x-www-form-urlencoded` на оригинальный сайт. В проверке использованы cookie текущей сессии, `Referer` точной страницы сезона, `Origin: https://seasonvar.ru` и `X-Requested-With: XMLHttpRequest`. Значения cookie не передаются в URL или теле формы.

| Поле формы | Источник и значение |
| --- | --- |
| `id_season` | `svfunc.idSeason`: `data-id-season` страницы сезона |
| `file_id` | `player.api("vars")`: поле `vars` выбранного листа JSON-плейлиста, ID контента |
| `serial_id` | `svfunc.idSerial`: `data-id-serial` страницы, ID сериала, отличный от ID сезона |
| `svid1` | Результат `document.cookie.indexOf("svid1")`: позиция имени cookie в доступной JavaScript строке, либо `-1`; это не значение cookie и не булево `0/1` |
| `idTrans` | ID активной озвучки из `data-translate`; исходник использует `-1`, если активного элемента нет |
| `page` | `window.popup`; на проверенной обычной странице передано пустое значение |
| `numFile` | `player.api("playlist_id")`: поле `id` выбранного листа плейлиста |

`idSeason` и `idSerial` инициализируются в [pg.player.min.js?25.4.1](https://cdn.svstat.net/asset/js/pg.player.min.js?25.4.1). `numFile` не является индексом массива или внутренним ключом приложения вроде `1_seriya`. `file_id` не является видеоссылкой. Параметры берутся у той же серии и озвучки, для которых разрешается поток; подменять отсутствующие идентификаторы предположениями нельзя.

В проверке выбран «Наруто», первый сезон, первая серия, озвучка 2x2: `id_season=2779`, `serial_id=1299`, `file_id=1049680`, `idTrans=0`, `numFile=1`. Это публичные идентификаторы выбранного контента, не данные сессии.

Результат проверки:

- До запроса запись выбранного сезона в истории отсутствовала. Авторизованные GET страницы сезона и плейлиста её не добавили.
- POST вернул HTTP 200 с пустым телом. Последующий GET истории подтвердил появление первой серии с правильной озвучкой и сегодняшним временем на первом месте.
- Повтор той же формы через небольшой промежуток не создал вторую запись и не изменил отображаемое время. Остальные записи истории сохранили содержимое и относительный порядок.
- Постоянная отметка выбранного сезона после обоих запросов совпала с исходной. Запросы `jsonMark.php` в этом тесте не выполнялись.

Для приложения HTTP 200 считается успешной отправкой, включая проверенный ответ с пустым телом. Контрольный GET истории не выполняется — [ADR-0116](../adr/0116-history-write-http-success.md). Успех помечает историю и «Продолжить» устаревшими для обычного обновления при возврате или открытии — [ADR-0117](../adr/0117-playback-history-sync.md). Повторное чтение в исследовании использовалось для подтверждения контракта, а не как обязательная часть рабочей отправки.

Полное серверное правило объединения повторов, временное окно, другие озвучки и ненумерованные серии не проверены. Метод нельзя объявлять безусловно идемпотентным. В запросе нет клиентского времени просмотра; возможность восстановления исторических дат не установлена.

Приложение отправляет событие после первого кадра и начала воспроизведения, один раз за запуск серии. Метаданные берутся из уже загруженных страницы и выбранного листа плейлиста; без них история не отправляется, видео остаётся доступным. Отправка в фоне привязана к версии сессии: максимум три попытки в течение 30 секунд, без очереди на диске. Сохранение позиции через `jsonMark.php` и чтение истории остаются отдельными механизмами. Источники и дата проверки — в [sources.md](sources.md#проверка-записи-истории-просмотров).

### Единая модель записи и параметры перехода

Парсеры списков создают `SeriesEntry`, определённый вместе с `EntrySelection` в `CatalogModels.kt`. По точному `id`/`url` открывается сезон. Общий `initialSelection` содержит известные `episodeId`/`episodeLabel` и `translationId`/`translationLabel`; неизвестные значения остаются пустыми. Отдельное поле `historyEpisode` заменено общим полем серии.

История читает номер серии и озвучку из собственного текста ссылки. Главная и AJAX-подборки заполняют их из `news_s`/`rside-ss span`; при нескольких обновлениях одной записи передаются только однозначные общие параметры. Личные отметки могут передать ID серии из распознанного `#rewind=N_seriya…`; произвольный фрагмент и число отмеченных эпизодов не считаются ID серии. Извлечение ID не подтверждает время продолжения или серверную запись прогресса.

Карточка сопоставляет контекст с загруженными озвучками и их эпизодами, сохраняя приоритет исходных параметров перед локальной отметкой. Если указанная озвучка не найдена, выбирается стандартная с сохранением известной серии — [ADR-0042](../adr/0042-standard-translation-fallback.md). Поиск и «Лучшие сериалы» передают сезон, не придумывая серию и озвучку. Решения — [ADR-0040](../adr/0040-details-entry-context.md) и [ADR-0041](../adr/0041-shared-catalog-entry.md).

## 5. Страница сезона

`GET /serial-<season_id>-<slug>.html` по точному пути из каталога или поиска.

| Сведения | Источник в HTML |
| --- | --- |
| ID сезона | `data-id-season` |
| ID сериала | `data-id-serial` |
| Связанные сезоны | Ссылки внутри `pgs-seaslist` |
| Озвучки | `ul.pgs-trans li[data-translate]` |
| Соответствие озвучки плейлисту | `var pl = …` и `pl[n] = …` |
| Счётчик/описание эпизодов в Go-клиенте | `arEpisodes` |
| Текущая отметка аккаунта | `var mark`, включая `href` и `trans` |

`season_id`, `serial_id`, `translation_id` и номер эпизода — разные значения. Страница с префиксом `serial-` в изученных клиентах обозначает сезон.

Для описания 2026-11-01 проверены `.pgs-sinfo[data-id-season]` и абзацы `.pgs-sinfo-info > p`; ID должен совпадать с выбранной карточкой. `meta[name=description]` используется как запасной, обычно сокращённый текст. Получение описания не подтверждает доступность видео.

Из `var mark.href` Go-клиент извлекает номер серии по фрагменту `#rewind=<number>_…`. Полный формат отметки, точная позиция в секундах и семантика всех полей требуют проверки.

### Проверка метаданных для ТВ-карточки

2026-11-02 агент анонимно получил [страницу первого сезона «Игры престолов»](https://seasonvar.ru/serial-2219--He_vse_starki_umrut----_psxskbl-00001---sezon.html) и [«Хмельного сна»](https://seasonvar.ru/serial-50920-Hmel_noj_son.html), просмотрел статическую HTML/CSS-вёрстку первой без JavaScript. Это проверка страницы и её подписей, не проверка плеера или плейлиста.

- `.pgs-sinfo-title` содержит название вместе с веб-приставками и номером сезона; `.pgs-sinfo_list` — оригинальное/альтернативное название, жанры, возраст, страну, год и режиссёров.
- `.pgs-sinfo-actor` содержит список актёров и действие раскрытия полного состава. В первом примере на постере есть «Топ 100», отдельно указаны места в жанровых топах и теги; рейтинги IMDb/КиноПоиск на этих двух страницах не обнаружены, но подтверждены отдельно на «Наруто» ниже.

Каждый непустой ключ (например `1_seriya` или `Osnovnoj_seriya`) содержит `n` — метку эпизода и необязательный `next` — следующую метку. Пустой ключ содержит `next` первого эпизода. Host: seasonvar.ru
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest
Referer: https://seasonvar.ru/
Cookie: svid1=<SESSION>
~~~

Найденные варианты тела:

| Действие | Поля формы |
| --- | --- |
| Отметка серии | `pauseadd=1&id=<SEASON_ID>&seria=<EPISODE>` |
| Озвучка | Необязательное дополнение `tran=<TRANSLATION_ID>` |
| Позиция | Необязательное дополнение `minute=<MINUTE>&second=<SECOND>` |
| Весь сезон просмотрен | `id=<SEASON_ID>&seria=-2&minute=0&second=0&watched=1` |
| Хочу посмотреть | `id=<SEASON_ID>&seria=-1&minute=0&second=0&wanttosee=1` |
| Снять отметку | `delId=<SEASON_ID>` |

Go-клиент разбирает ответ как JSON-объект, но не устанавливает строгую схему успеха. **По исходнику оригинального `pg.marks.min.js?25.4.1`, загруженного 2026-11-03:** сайт считает запись или удаление успешными при `response.msg == "success"`. Это проверка контракта клиента сайта, а не подтверждение результата реального POST. Для записи позиции используются `pauseadd=true`, `id`, `seria`, `tran`, `minute`, `second`. Поле `response.id` может предлагать удаление отметки предыдущего сезона; автоматически удалять её нельзя.

Операции меняют аккаунт. Для проверки нужны известный сезон и последующее чтение `/resume` или страницы сезона. Первоначальное исследование ограничивалось чтением; результат обратимой проверки записи 2026-11-04 описан ниже.

### Временная автометка сайта

**Источник: публичные оригинальные скрипты `pg.marks.min.js?25.4.1` и `main.min.js?25.4.1`, загружены агентом 2026-11-03.** Это отдельный механизм от постоянной отметки `jsonMark.php` и списка `/resume`.

- `markAuto` сохраняет данные только в браузерном `localStorage`; HTTP-запроса для автоматического сохранения в этом скрипте нет.
- Работа включается при наличии ID пользователя из cookie `svid1` и поддержки localStorage. Ключ — `svsid_<USER_ID>_<SEASON_ID>`, значение — `<SERIES>|<MINUTE>|<SECOND>`. Временная отметка не содержит озвучку или время последнего изменения.
- Номер серии берётся из `player.api("playlist_id")`, позиция — из `player.api("time")`. При нулевой позиции `markAuto.set()` ничего не записывает.
- На событии `play` сайт сразу сохраняет текущую позицию и запускает повтор через 60 000 мс. События `new`, `pause`, `stop`, `end` отменяют таймер; сами по себе они не вызывают немедленное сохранение.
- При открытии страницы `markAuto.get()` читает данные для текущего пользователя и сезона. Сайт добавляет строку «Автоотметка на: …» к постоянной отметке. Установка или удаление постоянной отметки очищает временную через `markAuto.remove()`.
- Переход по строке создаёт hash вида `#rewind=<SERIES>_seriya_na_<MINUTE>_minute_<SECOND>_sekunde`. `main.min.js` выбирает эпизод по `arEpisodes[mark.trans]`. В `goToHash()` при нулевом времени либо оставшихся менее 120 секундах и известной длительности выбирается следующий эпизод, если он существует; это наблюдение по JS, поведение проигрывателя в браузере отдельно не проверено.

Автометка из конкретного браузера недоступна нативному клиенту через HTTP/API и не синхронизируется с другими устройствами этим механизмом. Встроенное приложение уже хранит собственный `ResumePoint` локально: сохранение раз в 5 секунд, на обычной паузе пультом, выходе и смене серии. Существующая карточка показывает «Продолжить» только для совпадающих выбранных сезона, озвучки и серии. Явный контекст из списка имеет приоритет над локальным продолжением по ADR-0040. Это не чтение браузерного localStorage и не запись постоянной серверной отметки.

### Сохранение постоянной отметки в приложении

2026-11-04 проверено агентом в авторизованном эмуляторе Android TV API 34: POST с pauseadd=true, id, seria, tran, minute, second возвращает msg=success; повторное чтение страницы сезона содержит новую пару href/trans в var mark. В тесте менялось только время существующей отметки; исходное значение после проверки восстановлено и подтверждено повторным чтением. Личные значения, cookie и ответы страниц в фикстуры не переносились.

[PlaybackMarkParser](../../app/src/main/java/ru/seasonvar/tv/data/account/PlaybackMark.kt) читает #rewind=... в var mark.href, нормализует стандартную озвучку и проверяет идентичность сезона. Допускается изменившийся slug того же сезона, но не другой ID или внешний домен. Пустой href означает отсутствие отметки; -1/-2/-3 остаются отдельными статусами списка. Ответ POST сам по себе не считается подтверждением.

AccountRepository сериализует запись вместе с проверкой сессии, проверяет пользователя до POST и после него и сообщает об изменении прогресса только после совпавшего read-back. Режим automatic не уменьшает номер серии и не снимает отметку просмотренной серии/сезона или чёрного списка.

Автоматическая отправка работает по [ADR-0056](../adr/0056-automatic-account-playback-marks.md): текущая позиция раз в минуту и на паузе/выходе, завершение на 90%, минимум 30 секунд реального проигрывания. Для локального продолжения остаётся свой ResumePoint. Клиент пока не подставляет точное серверное время в кнопку «Продолжить»; это не смешивается с подтверждённой записью и чтением счётчиков.

### Удаление постоянной отметки в приложении

Оригинальный публичный `pg.marks.min.js?25.4.1` повторно прочитан 2026-11-04: `svfunc.markRemove` отправляет POST `jsonMark.php` с `delId` выбранного сезона и проверяет `msg=success`. Это снятие постоянной отметки сезона, а не удаление записи истории. Необязательное предложение удалить другой сезон не выполняется приложением.

2026-11-04 в авторизованном эмуляторе выполнен обратимый `make mark-probe MARK_PROBE_MODE=delete-roundtrip`: POST, отсутствие отметки на свежей странице и исчезновение сезона из всех пяти личных подборок подтверждены; исходная отметка восстановлена и прочитана обратно. Cookie и значения отметки наружу не выводились. Удаление привязано к проверенному аккаунту и сериализовано с очередью автосохранения. Контракт и интерфейс — [ADR-0057](../adr/0057-remove-account-list-marks.md).

## 7. Плейлисты и воспроизведение

Найдены разные поколения протокола. Их нельзя считать одним действующим контрактом.

### Текущий проверенный вариант: HTML → JSON → MP4

**Проверено агентом 2026-11-02, анонимно.** Исходная [страница «Наруто»](https://seasonvar.ru/serial-2779--Naruto_pssrhvg-0-season.html) содержит `var pl` и дополнительные присваивания `pl[n]`. Ключ соответствует ID перевода из метаданных страницы; значение — временный путь плейлиста. Его нужно извлекать из свежего HTML перед запуском, а не составлять из ID или брать из суточного кэша описания.

1. GET точного URL сезона по HTTPS. Проверить `data-id-season`.
2. Найти путь выбранного перевода в `var pl` / `pl[n]`, разрешить относительно страницы. Допускается только оригинальный домен сайта.
3. GET найденного плейлиста с `Referer` точной страницы. В проверке сервер отдал JSON с `Content-Type: text/html; charset=UTF-8`; одного заголовка недостаточно для определения формата.
4. Развернуть вложенные массивы `folder` (также поддерживается `playlist`). Получено 220 конечных эпизодов. Лист содержит `id`, `title`, `file`, `subtitle`, `galabel`, `vars`; в проверенном ответе поля строковые, `title` содержит HTML.
5. Сопоставить `id` листа с `arEpisodes.n`, то есть меткой серии. Для первой серии метка — `1`, внутренний ключ карточки — `1_seriya`. Это разные идентификаторы; `vars`, индекс массива и `galabel` не подменяют номер эпизода.
6. Декодировать `file` по формату публичного [PlayerJS сайта](https://cdn.svstat.net/js/playerjs77.js), версия 9.97.2: убрать префикс `#2`, первое вхождение `//b2xvbG8=` и декодировать стандартный Base64 как UTF-8. Это вставка публичного маркера `bk0="ololo"`, не пароль и не ключ аккаунта. Другие префиксы `#` пока не поддерживаются. Для незакодированного `file` используется URL напрямую.
7. Из строки качества выбрать первую объявленную ссылку. Разделитель — переход к следующей метке качества и URL; запятые и скобки внутри имени файла сохраняются. Путь нормализуется с URI-кодированием скобок/пробелов, без изменения значений query. Протокол `//` и HTTP переводятся в HTTPS; credentials в URI запрещены. Запрос видео отправляет `Referer` страницы сезона, без cookie аккаунта.

В этой проверке GET с `Range: bytes=0-1023` вернул **206, video/mp4** и MP4-сигнатуру `ftyp`; затем Media3 в эмуляторе показал видео, паузу и перемотку. Временные пути и подписанные видеоссылки не сохраняются в документации, фикстурах и логах. Полный ответ плейлиста намеренно не коммитится.

Воспроизводимая проверка без записи или печати видеоссылки:

~~~bash
make site-video-probe SITE_URL='https://seasonvar.ru/serial-2779--Naruto_pssrhvg-0-season.html' SITE_TRANSLATION=0 SITE_EPISODE=1
~~~

Загрузчик использует существующую DPI-стратегию и Quad9 DoH; проверяет первые 1024 байта, не скачивает серию целиком. Клиент получает ссылку заново на каждый запуск. Срок жизни ссылки, HD по подписке, субтитры и поведение аккаунта не установлены. Продолжение в приложении сейчас локальное, по [ADR-0031](../adr/0031-native-playback.md); это не запись `jsonMark.php`.

**Проверка имён файлов 2026-11-02:** у «Боруто» (15615) и «Избранного», сезон 2 (51084), путь содержит квадратные скобки; у «Моего Айртона» (51091) — запятую. Прежний поиск URL через отрицательный класс символов обрывал путь и приводил к HTTP 404. После сохранения полного имени `make site-video-probe` получает 206 / video/mp4 / `ftyp` для всех трёх. В тестах используются вымышленные URL с той же пунктуацией. Подписанные пути не сохраняются.

Следующие разделы сохраняют сведения о других реализациях и поколениях протокола.

### Вариант A: плейлист указан в странице

Kotlin-клиент ищет `var pl` и присваивания `pl[n]` прямо в HTML сезона. ID озвучки связывается с `data-translate`; выбирается активная озвучка, иначе `0`, иначе первая доступная.

Затем клиент делает GET по полученному пути тем же HTTP-клиентом с cookie и `Referer`. Имя `bepl.txt` встречается в комментариях, но путь нужно получать из ответа сайта, а не собирать вручную.

Kotlin-парсер ожидает JSON-массив с полями:

| Поле | Как используется |
| --- | --- |
| `id` | Номер/метка эпизода; не путать с ID контента |
| `title` | Название серии; HTML очищается |
| `vars` | ID контента для внешнего плеера |
| `galabel` | Резервный источник ID: часть после последнего `_` |

Описанный парсер не получает готовый MP4/HLS URL. Дальше приложение открывает `https://angrycdn.net/player/<CONTENT_ID>/` в WebView с `Referer` страницы сезона и `Origin` сайта.

**Следствие для нашего приложения:** наличие списка серий ещё не решает нативное воспроизведение. Контракт извлечения видеопотока у этого плеера по изученным файлам не установлен.

### Вариант B: player.php и прямые ссылки

Kodi-клиент извлекает из HTML `data-id-season`, `data-id-serial` и `data4play.secureMark/time`, затем отправляет:

~~~http
POST /player.php HTTP/1.1
Host: seasonvar.ru
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest
Referer: https://seasonvar.ru/<EXACT_SEASON_PATH>

id=<SEASON_ID>&serial=<SERIAL_ID>&type=html5&secure=<PAGE_MARK>&time=<PAGE_TIME>
~~~

Значения `secure` и `time` берутся со страницы; правила их срока жизни не установлены. Не подставлять захардкоженные значения из чужих примеров.

Ответ содержит HTML/JavaScript с `var pl` и `pl[n]`. По найденным URL клиент загружает JSON-плейлист. В старых фикстурах есть `title`, `file`, `subtitle`, `galabel`, `id`; парсер поддерживает и вложенное поле `playlist`.

В этом варианте `file` содержит видеоссылку. Старый формат не подтверждает наличие такого поля сейчас, доступность HD, поддержку HLS/DASH или воспроизводимость ссылок вне исходной сессии.

### Ограничения реализации

Не использовать догадку о URL плеера или CDN как публичный контракт. Домены картинок в клиентах различаются (`cdn.bigsv.ru`, `cdn.svstat.net`); по возможности извлекать URL из HTML и разрешать относительно адреса страницы.

Не передавать cookie Seasonvar всем внешним доменам: cookie jar должен учитывать область действия. Для внешнего плеера отдельно проверить нужные `Referer` / `Origin`. Не копировать из старых клиентов отключение TLS-проверки, plaintext-логирование сессий или передачу пароля через URL.

На этапе реализации нужно подтвердить: выбор озвучки, соответствие ID эпизода, поток/качество, перемотку, истечение видеоссылки, права подписки и сохранение прогресса после просмотра.

### «Анонсы»: публичная страница ожидаемых сериалов

Источник: ссылка «Скоро на нашем сайте» в левой панели оригинальной главной. Проверено агентом 2026-11-04 без входа: GET https://seasonvar.ru/?mode=soon возвращает 36 записей.

Заголовок .content .content-wrap .pgs-head — «Скоро на сайте». Активная панель .pgs-search > .tabs-result > li.act содержит информационный .pgs-msg и строки .pgs-search-wrap. В каждой строке: точная ссылка сезона a.pst[href], русское и необязательное оригинальное название в .pgs-search-info > a, номер сезона в собственном тексте, span с ориентировочной датой и p с кратким описанием.

Поле expectedReleaseDate в SeriesEntry хранит дату как текст: неизвестные и уточняемые даты не превращаются в ошибки. Полный текст span сохраняется в update. Ключ объявления зависит от ID сезона, поэтому изменение даты не сбрасывает выбор карточки.

Все строки сохраняются в порядке ответа, без сортировки и фильтрации по дате. Даты страницы относятся к оригинальной премьере; перевод может появиться позднее. Страница с правильным заголовком и пустой панелью — пустой список, блокировка или повреждённая разметка — ошибка.

Команда: make site-announcements. Обезличенный снимок: app/src/test/resources/announcements.html; содержит только публичную панель, без скриптов и данных сессии. Решение: [ADR-0070](../adr/0070-announcements-section.md).

### Метка аккаунта «Смотрю» в общих списках

Проверено агентом 2026-11-04 в авторизованном эмуляторе на указанном пользователем сериале «Сильнейшая ведьма в мире стартовала»: главная и AJAX-«Обновления» содержат i.svico-mwatch. На главной иконка находится внутри div.news_n, в AJAX — непосредственно внутри a.pst.rside-p. Пробник возвращает только классы, названия атрибутов и булевы результаты, без cookie и тел персональных ответов.

Общий CSS main.css сопоставляет svico-mwatch и svico-pause одному символу. pg.index.css показывает его на картинках светлым на фоне #980c3d в верхней левой части. svico-mwatched — другая метка и не означает «Смотрю».

SeriesEntry.isWatching заполняется точным классом svico-mwatch в пределах конкретной карточки. Общие иконки фильтра вне карточек и элементы всплывающей rside-d не учитываются. Парсеры остальных HTML-списков и HTML внутри поискового названия сохраняют такой же признак, если он присутствует в ответе. Наличие локальной позиции или истории само по себе не задаёт метку.

Авторизованные ответы сохраняются в отдельный приватный HTML-кэш текущего аккаунта с очисткой при выходе — [ADR-0129](../adr/0129-shared-card-data-cache.md). После подтверждённого изменения серверной отметки открывавшиеся публичные списки обновляются в фоне; изменения на другом устройстве становятся видны при следующем обновлении списка. Контракт — [ADR-0072](../adr/0072-site-watching-badge.md).

Read-only проверка, не меняющая отметки аккаунта:

~~~bash
make mark-probe DEVICE=emulator-5554 MARK_PROBE_MODE=catalog-badges
~~~

## Общий список переводов для настройки озвучки

Проверено агентом 2026-11-05: анонимный GET главной `https://seasonvar.ru/` содержит `select[data-filter="golosa"]`. Его `option[value]` задают названия переводов; `value="all"` — служебный пункт «Любой», который не является озвучкой. В проверенном ответе 104 значения без него, включая AlexFilm, Amedia и AniDub. Число и состав не фиксируются в приложении. Это HTML-фильтр сайта, отдельный JSON-контракт не установлен.

Для предпочтений сохраняется упорядоченный список строковых значений option, а не ID переводов из страниц сезона. При открытии сезона оно однозначно сопоставляется с подписью `ul.pgs-trans li[data-translate]` с нормализацией регистра и пробелов. Одинаковость ID между разными сезонами не предполагается. Стандартный вариант определяется отдельно по ADR-0042.

По решению пользователя справочник заново запрашивается при каждом открытии добавления озвучки. На диск он не записывается; после закрытия данные диалога освобождаются. Сохраняются только выбранные значения и их порядок по ADR-0076. Управление порядком работает без загрузки справочника. Ошибка сети, отсутствие фильтра или невалидные опции не сбрасывают предпочтения. Парсер и тесты используют только структуру публичного фильтра, без аккаунта.


### Ручные статусы личного списка

2026-11-05 повторно прочитан публичный оригинальный `pg.marks.min.js?25.4.1` (команда `make site-scripts`). `svfunc.markSet` отправляет на `jsonMark.php` поля `id`, `minute=0`, `second=0`, `seria` и ровно один флаг действия:

| Выбор | seria | Флаг |
| --- | --- | --- |
| Хочу посмотреть | -1 | wanttosee=true |
| Посмотрел | -2 | watched=true |
| Не буду смотреть | -3 | notWatched=true |

«Смотрю» — обычная положительная отметка серии с `pauseadd=true`, `tran`, `minute`, `second`, а не четвёртое отрицательное значение. Клиент сохраняет существующие серию, озвучку и время; для новой отметки использует выбранную либо первую реальную серию.

В авторизованном эмуляторе 2026-11-05 `make status-probe DEVICE=emulator-5554` подтвердил все четыре варианта последующим чтением страницы, а желаемый и просмотренный — также чтением соответствующих вкладок. Исходные серия, озвучка и время восстановлены и повторно прочитаны. Проверка не сохраняет личные ответы в фикстуры и выводит только обезличенные признаки успеха. Приложение не выполняет предложение ответа удалить предыдущий сезон. Решение и интерфейс — [ADR-0081](../adr/0081-account-list-status-actions.md).

## Обложки: миниатюра и большой файл

Проверено агентом 2026-11-06 на сериале 51144. На странице `.pgs-sinfo-img[data-click=posterBig]` содержит обычный `//cdn.svstat.net/oblojka/51144.jpg` (200 × 250). По клику обработчик `posterBig` заменяет `oblojka` на `oblojka/large`; профильный скрипт предварительно убирает `/small/`. Большой HTTPS URL — `https://cdn.svstat.net/oblojka/large/51144.jpg` (1080 × 1350). Маленький вариант `/oblojka/small/51144.jpg` имеет 93 × 116. Размеры не являются общим контрактом для всех сериалов.

Источники: [pg.player.min.js](https://cdn.svstat.net/asset/js/pg.player.min.js?25.4.1), [pg.profile.js](https://cdn.svstat.net/asset/js/pg.profile.js?25.4.1). Ответ большой обложки: HTTP 200, JPEG, `Cache-Control: max-age=604800`. Наличие большого файла у всех записей не установлено; при ошибке клиент использует обычный постер. Общий Coil хранит большую обложку в памяти и на диске отдельно от миниатюры по её URL; см. [ADR-0097](../adr/0097-adaptive-large-preview-poster.md).

## Комментарии и рецензии — проверка 2026-11-13

Проверено агентом без авторизации на страницах сезонов 2779 и 2219. Вкладка `comments` после плеера содержит короткие комментарии `.svc_comment`: текст `.svc_msg`, дата, автор, ответы и элементы оценки. Отдельная вкладка `reviews` содержит развёрнутые рецензии `.pgs-review-post`. Авторы связаны с профилями Seasonvar, аватары берутся с CDN сайта; в проверенной разметке нет указания на импорт этих текстов с КиноПоиска или IMDb.

Первая порция рецензий включена в HTML карточки, по семь записей в каждом примере. Счётчики вкладок — 36 и 35 соответственно. Встроенный `var review` содержит `last`; кнопка `data-click="reviewShow"` вызывает обработчик из [pg.player.min.js?25.4.1](https://cdn.svstat.net/asset/js/pg.player.min.js?25.4.1):

~~~http
POST /ajax.php
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest

review_id_serial=<ID_СТРАНИЦЫ_СЕЗОНА>&last_review=<LAST_ИЗ_HTML>
~~~

Несмотря на имя `review_id_serial`, оригинальный обработчик подставляет `svfunc.idSeason`. В живой проверке чтение остальных рецензий вернуло HTTP 200 и HTML: 29 записей для 2779, 28 для 2219. Полученные порции вместе с первыми семью совпали со счётчиками; следующей кнопки в ответе не было. Ответы обрабатываются как HTML, пользовательский текст не исполняется. Область привязки рецензий ко всем сезонам одного сериала отдельно не проверялась.

Счётчик берётся из текста `[data-tabt=reviews]`, первая порция — из `[data-tabr=reviews] .pgs-review-post`. Автор находится в `.pgs-review-name a`, дата — в `.pgs-review-date`; текст лежит непосредственно внутри записи, без отдельного контейнера. Имя, дата, аватар и исполняемые элементы исключаются из тела; `<br>` и абзацы преобразуются в переносы обычного текста. Эти поля могут отсутствовать, но пустое тело не считается рецензией.

Дополнительный ответ содержит соседние `.pgs-review-post`, а не целую страницу. Клиент отправляет запрос через общий `SiteClient`, с `Referer` страницы сезона и `X-Requested-With: XMLHttpRequest`. Это чтение; публикация, оценки и короткие комментарии не вызываются. HTML страницы и дополнительной порции используют общий кеш с разделением областей аккаунта; полный разобранный текст хранится только в модели экрана чтения. См. [ADR-0154](../adr/0154-series-reviews-reader.md).

В том же скрипте найдено создание рецензии через `POST /userReview.php`: текст длиннее 500 символов отправляется на модерацию. Это наблюдение по исходнику; запись не выполнялась. Правила входа для публикации, модерация, голосование и пагинация коротких комментариев не исследованы. Аккаунты и устройства в проверке не использовались; персональные поля не переносятся в документацию или фикстуры.
