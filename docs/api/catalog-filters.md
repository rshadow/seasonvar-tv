# Фильтры каталога и списков Seasonvar

Проверено агентом 06.11.2026: получены свежие анонимные HTML главной, `/resume`, `/?mode=top`, `/?mode=soon`, `/?mod=history` и официальные скрипты. Использованы `make site-fetch` и `make site-scripts` с доступом по [описанию доступа](access.md). Сырые страницы и скрипты находятся только в игнорируемом `build/site/`.

Начальная проверка подтверждала наличие элементов и исходников обработчиков. Применение непустых фильтров после входа дополнительно проверено 08.11.2026 для личных списков и реализовано в приложении. Жанр и период «Лучших сериалов» также проверены и реализованы; общий каталог дополнительно проверен и подключён 10.11.2026, результаты приведены ниже.

## Личные списки

Источник: [страница отметок](https://seasonvar.ru/resume) и [pg.marks.min.js](https://cdn.svstat.net/asset/js/pg.marks.min.js?25.4.1).

Под раскрывающейся областью фильтрации находятся два `select[data-change="mark-filter"]`:

| Параметр | Элемент | Значения |
| --- | --- | --- |
| Жанр | `name="marks-genre"` | ID жанра из `option[value]`, `all` снимает ограничение |
| Страна | `name="marks-country"` | Название страны из `option[value]`, `all` снимает ограничение |

Обработчик отправляет `POST /ajax.php`: `marks_filter=true`, `country=<value>`, `genre=<value>`. Ответ вставляется в `[data-result="marksf"]`, общий контейнер четырёх вкладок `marks-new`, `marks-nonew`, `marks-want`, `marks-watched`. Поэтому это общий фильтр личных списков, а не отдельная публичная подборка. В приложении «На чём остановились» составляется из первых двух вкладок.

Разметка присутствует и в гостевом ответе. Это не подтверждение авторизации и не основание считать личные списки пустыми. Авторизованный отбор подтверждён проверкой ниже. Справочники жанров и стран брать из свежих опций сайта, не закреплять их состав в коде. Настройка открытия в новой вкладке рядом с фильтрами относится к браузеру и фильтром не является.

### Проверка и реализация личных фильтров — 08.11.2026

Авторизованный эмулятор подтвердил варианты из свежего `/resume` и три запроса: `all/all`, отдельный жанр, отдельная страна. POST возвращает HTTP 200 и HTML-фрагмент четырёх `data-tabr` без `.headblock-menu` и `.pgs-marks`. Фильтрация сужает соответствующие вкладки; пустая вкладка остаётся в ответе. `all/all` совпал с исходной выдачей. Обычный GET `/resume` после фильтров сохранил все исходные записи, порядок и отметки: проверенные условия не сохранились на сервере. Набор опций в этой проверке: 22 значения жанра и 107 стран, включая варианты `all`; эти количества не являются ограничением протокола.

Приложение перед фильтрацией читает `/resume`, проверяет владельца и получает свежие опции. Неизвестные сохранённые значения заменяются `all`. При ограничениях отправляется POST, а фрагмент принимается только с полным набором четырёх вкладок в той же версии сессии; заголовок аккаунта в нём не выдумывается. При отсутствии ограничений достаточно обычного GET. Нераспознанный или пустой ответ не считается пустым списком; при ошибке структуры повторное авторизованное чтение позволяет отличить истёкшую сессию.

Одна [панель по ADR-0118](../adr/0118-shared-list-filter-panel.md) показывает жанр и страну для «На чём остановились», «Есть обновления», «Нет новых серий», «Хочу посмотреть», «Посмотрел». Черновик применяется по кнопке; «Сбросить» сразу загружает выдачу без ограничений по [ADR-0119](../adr/0119-filter-reset-and-action-buttons.md). Успешные условия сохраняются раздельно для раздела и владельца. Фильтры экрана не передаются в `resume()` для «Продолжить», прогресса или домашних лент. Запросов записи постоянных отметок или истории эта операция не выполняет.

Воспроизведение проверки: `make personal-filters-probe DEVICE=emulator-5554 PERSONAL_FILTERS_PROBE_OUT=<каталог-сессии>/personal-filters`. Требуется существующая сессия эмулятора; на приставке команда не работает. В отчёте только публичные варианты, структура, счётчики и результат сравнения; тела личных ответов и cookie не сохраняются. Автономные тесты используют синтетические фикстуры.

## Лучшие сериалы

Источник: [отдельная страница](https://seasonvar.ru/?mode=top), включая её встроенный JavaScript. Это не боковая AJAX-подборка «Топ» (`mode=pop`).

| Условие | Элементы и параметры из исходника |
| --- | --- |
| Жанр | `.gen`, query `genre=<ID>`; пустое значение без ограничения |
| Период популярности | `.per`, query `period=1`, `7`, `31`: день, неделя, месяц; на проверенной странице выбран день |
| Качество | `fhdTop` → `filterTop[fhd]`, `hdTop` → `filterTop[hd]` |
| Субтитры | `subTop` → `filterTop[sub]` |
| Отечественные сериалы | `engTop` → `filterTop[eng]`; флаг RU включён по умолчанию, параметр инвертирован: при включении пустой, при выключении `yes` |
| Доступность в стране | `blockTop` → `filterTop[block]` |
| Сериалы, которые пользователь смотрит | `markTop` → `filterTop[mark]` |
| Ранее просматривавшиеся сериалы | `historyTop` → `filterTop[history]` |
| Чёрный список | `notwatchedTop` → `filterTop[nw]` |

Жанр и период меняют URL `/?mode=top&genre=…&period=…`. Дополнительные флаги отправляются POST на текущий URL в объекте `filterTop`; значения `yes` либо пустая строка. Применение и ограничения авторизации проверены ниже. `history` не приравнивать без проверки к постоянному статусу «Посмотрел».

### Повторная проверка жанра и периода — 08.11.2026

Анонимные GET `/?mode=top` и `/?mode=top&genre=17&period=7` возвращают полные страницы, а не AJAX-фрагменты. В первой серверный скрипт отмечает `.per[value=1]`, во второй — `.gen option[value=17]` и `.per[value=7]`; HTML-атрибуты `selected` у жанра при этом остаются начальными. Эффективный выбор надо учитывать по инициализации страницы, а не только по HTML-атрибутам. Справочник содержит 21 жанр и пустое значение «Любой жанр»; периоды — 1, 7, 31. Состав справочника не фиксировать в приложении. Дополнительно проверен `genre=18&period=31`: скрипт отмечает аниме и месяц. Приложение проверяет соответствие серверного выбора запросу и разделяет кэш по жанру и периоду; сброс возвращает любой жанр и день, см. [ADR-0121](../adr/0121-best-list-genre-and-period.md).

### Проверка дополнительных переключателей — 08.11.2026

Проверка агентом: POST на `/?mode=top&period=1` с восемью полями `filterTop[fhd|hd|sub|eng|block|mark|history|nw]`, каждое `yes` либо пустая строка. Ответ — только элементы `.pgs-search-wrap`, без `#search-res` и без полей жанра/периода. При пустом результате сервер присылает один `.pgs-msg` с текстом «Сожалеем, по вашему запросу ничего не найдено»; это подтверждено сочетанием `genre=10`, `fhd=yes`, `sub=yes`, `eng=yes`. Пустое тело или произвольное сообщение не считать успешной пустой выдачей. Анонимно отдельные `fhd`, `hd`, `sub`, `eng`, `block` меняют состав выдачи. `eng=yes` исключает отечественные; галочка RU на сайте инвертирована. На публичных страницах «Купертино» и «Айда!» найден `poster.fhd`, у исключённой Full HD-фильтром «Ставки на любовь» такого признака нет. Флаг `block` исключил две позиции из первоначальной сотни; доступность определяет сайт для страны запроса, это не гарантия воспроизведения.

Живой тест эмулятора проверил гостевой клиент и существующую сессию. При применении личных ограничений приложение предварительно читает выбранную страницу через репозиторий аккаунта и проверяет владельца; истёкшая сессия не считается успешным применением проигнорированных флагов. У гостя `mark`, `history`, `nw` оставили исходную выдачу. После входа `mark` и `history` исключали часть совпадений с названиями личного списка (6 → 1 и 6 → 2 соответственно). Названия использовались только в исследовательском сравнении в памяти; приложение фильтрует серверным запросом. Отдельного положительного примера чёрного списка в аккаунте не установлено, поэтому проверена форма `nw` и валидный ответ, а не исключение конкретного чёрного сериала. Обычные GET до и после всех запросов совпали у гостя и после входа; постоянные отметки также остались прежними.

Повторить: `make best-filters-probe DEVICE=emulator-5554 BEST_FILTERS_PROBE_OUT=<каталог-сессии>/best-filters`. В отчёте только агрегированные счётчики и признаки, без тел личных ответов, cookie, названий и ID пользователя.

## Общий фильтр каталога

Источник: [главная](https://seasonvar.ru/) и [main.min.js](https://cdn.svstat.net/asset/js/main.min.js?25.4.1), функции `fChange` и `fShowResult`.

| Группа | Возможности из разметки |
| --- | --- |
| Страна | Выбор страны и исключение выбранной; все, русские или зарубежные сериалы |
| Названия | Оригинальное название для зарубежных сериалов; отключено для остальных групп |
| Жанры | Несколько условий через добавление строки, включение и исключение жанров |
| Год | Равен, больше или меньше выбранного |
| Количество сезонов | Равно, больше или меньше выбранного |
| Рейтинг | КиноПоиск или IMDb; равен, больше или меньше выбранного |
| Перевод | Выбор озвучки из актуального списка сайта |
| Анонсы | Условие для сериалов, ещё ожидаемых на сайте |
| Качество и субтитры | Full HD/1080, HD, наличие субтитров |
| Ограничения показа | Доступность в стране, смотримые сериалы, история просмотра, чёрный список |
| Сортировка | Название, КиноПоиск, IMDb, год, популярность, добавление |

`fChange` собирает объект `filter` и отправляет `POST /index.php` с `countFilter=yes` для счётчика. `fShowResult` отправляет тот же `filter` без `countFilter` для выдачи в `[data-filter="result"]`. Жанры: `quotG`/`notQuotG`; страны: `quotC`/`notQuotC`; год: `quotY`/`moreY`/`underY`; сезоны: `quotS`/`moreS`/`underS`; рейтинг: `quotR`/`moreR`/`underR` и `rait`; перевод: `quotT`; сортировка: `sortTo`. Дополнительные поля: `only`, `engName`, `hd`, `fhd`, `sub`, `block`, `history`, `mark`, `nw`, `exp`. Значения сортировки: `name`, `kinopoisk`, `imdb`, `god`, `view`, `newest`.

Общий фильтр виден также в боковой панели других страниц. Его наличие рядом со списком не означает, что он фильтрует этот список: обработчик отдельно выводит результаты каталога.

### Проверка выдачи каталога и рейтингов — 09.11.2026

Статус: проверено агентом в сети, анонимно, без cookie и изменения аккаунта. Источники — свежая [главная](https://seasonvar.ru/), обработчики `fChange`/`fShowResult` в [main.min.js?25.4.1](https://cdn.svstat.net/asset/js/main.min.js?25.4.1), ответы `POST /index.php` и `GET /serialinfo/<id>/`. Реализация каталога в приложении не начата.

`POST /index.php` с формой `filter[...]` без ограничений и с `filter[sortTo][]=name` вернул HTTP 200, 33 834 ссылки в HTML объёмом 5 704 607 байт. Отдельный запрос с теми же условиями и `countFilter=yes` вернул число `33834`. Это наблюдение о текущей выдаче, не фиксированный размер каталога. Результат содержит `.lside-serial[data-serial=list]`, группы `data-tabt`/`data-tabr` и ссылки с `data-id` и точным `href` страницы сезона. В проверенном ответе вся выдача пришла сразу; постраничную загрузку для этого маршрута не подтверждали.

Отдельно проверен `filter[sortTo][]=newest` без ограничений: HTTP 200, те же 33 834 записи, первые ID — `51187`, `51185`, `51184`, `51183`, `51182`; вариант в форме сайта подписан «По добавлению». Запрос с `Accept-Encoding: gzip` получил `Content-Encoding: gzip`: тело по сети — 1 321 992 байта, после распаковки — 5 702 534 байта. Контрольный `Accept-Encoding: identity` получил несжатое тело того же размера; распакованные ответы совпали побайтово. Это примерно 4,3-кратное сокращение объёма тела, а не ограничение числа записей. В обоих ответах передача была chunked; `ETag`, `Last-Modified` и `Cache-Control` отсутствовали. Размеры и первые ID относятся к моменту проверки.

Обработчик `fShowResult` не передаёт размер страницы или смещение. Группы результата переключаются локальным обработчиком вкладок; отдельный запрос следующей порции в этом сценарии не найден. Это не доказывает отсутствие иных маршрутов сайта. До подтверждения серверной пагинации нельзя называть ограничение локально подготовленных карточек сокращением сетевой выдачи. В основном ответе передаются ссылки и названия; он не включает скачанные изображения и описания всех сериалов. Сжатие, потоковый разбор и локальный кэш для общего каталога, а также общее окно подготовки карточек и обложек по вместимости экрана приняты в [ADR-0127](../adr/0127-shared-list-preparation-window.md); расширение ещё не реализовано.

Непустые условия `filter[quotG][]=17`, `filter[quotC][]=США`, `filter[quotY][]=2025` дали 85 записей. Запросы с `filter[sortTo][]=name`, `kinopoisk` и `imdb` вернули по 85 записей в разных порядках. При сортировке по названию группы соответствуют буквам; по КиноПоиску — `8`, `7`, `6`, `0`, по IMDb — `8`, `7`, `6`, `5`, `0`. **Точных оценок IMDb/КиноПоиска у отдельных записей этого ответа нет.** Номер рейтинговой группы, включая `0`, не подставлять вместо оценки.

В той же выборке при `filter[rait]=imdb` условия `filter[quotR][]=8` и `filter[moreR][]=7` дали одинаковые 15 записей группы `8`, включая «Бургеры Боба» с точной оценкой `8.20`. `filter[moreR][]=8` вернул пустой результат, `filter[underR][]=8` — 70 записей остальных групп. Это подтверждает сравнение целочисленных групп в проверенной выборке, а не точных дробных оценок. Не обещать точное равенство оценке `8.00` или поддержку порога `8.5` без отдельной проверки.

Точные оценки приходят **отдельным** анонимным `GET /serialinfo/<data-id>/`, который сайт вызывает при наведении на ссылку каталога. Проверены `/serialinfo/45962/`, `/serialinfo/43153/` и `/serialinfo/44167/`: HTTP 200, HTML объёмом 1002, 886 и 1010 байт. В `.serial-w` отдельные `div` содержат подпись, а вложенный `span` — значение; например, [ответ для «Бургеров Боба»](https://seasonvar.ru/serialinfo/45962/) содержит `IMDB: 8.20` и `КиноПоиск: 7.23`. Там же есть краткое описание, оригинальное/альтернативное название при наличии, жанр, страна, год и число сезонов. Наличие обоих рейтингов у всех сериалов и срок обновления этих данных не установлены.

В проверенном обработчике `fChange` нет поля поиска по названию, а `fShowResult` отправляет только сформированный объект фильтров. `/autocomplete.php?query=...` — отдельный интерфейс поиска; сочетание его строки с фильтрами каталога одним серверным запросом не подтверждено. По решению пользователя каталог проектируется **без строки поиска**, с фильтрами непосредственно над описанием и списком — [ADR-0126](../adr/0126-catalog-inline-filters.md). Локальный поиск по названиям был предложением и не принят.

## Исследование общедоступных подборок — 09.11.2026

Проверка агентом, гостевой клиент: 39 POST к `ajax.php?mode=new|pop|newest`, по 13 случаев на подборку. Кроме исходной формы проверены `ganre=17`, `ganre=18`, альтернативный ключ `genre=17`, страны `Япония` и `Россия`, несуществующие жанр/страна, `block=1`, `main=0` отдельно и с жанром/страной, повтор исходного запроса. Во всех 13 случаях каждой подборки совпали полные тела ответа, состав и порядок ссылок: 50/48/50 карточек в исходных ответах соответственно. Это подтверждает игнорирование проверенных параметров на этих маршрутах у гостя; числа карточек не являются постоянным контрактом.

Свежий официальный `main.min.js?25.4.1` по-прежнему содержит один вызов этих маршрутов с пустыми `ganre`/`country`, `block=0`, `main=1`. У «Сегодня» и «Анонсов» собственные элементы фильтрации в полученной разметке не найдены. Общая форма вызывает `fChange`/`fShowResult` и отдельную выдачу каталога, поэтому переносить её условия на существующие подборки без подтверждения нельзя. Проверка повторена в эмуляторе у гостя и в существующем аккаунте: всего 78 POST, во всех случаях полные тела ответов внутри каждой подборки совпали с исходным. Для «Сегодня» и «Анонсов» дополнительно проверены GET с `genre=18&country=Япония` и `ganre=17&block=1`: состав основной выдачи не изменился в обоих контекстах, собственных `input/select[data-filter]` в основной области не найдено. Постоянные отметки после исследования сохранились.

Исследование этих публичных подборок завершено. Подтверждённых собственных фильтров в проверенных интерфейсах нет; кнопки с неработающими условиями не добавляются по ADR-0118. Общий каталог остаётся отдельной задачей; последующая проверка истории описана ниже. Это вывод о проверенном контракте на указанную дату, а не запрет повторной проверки при изменении сайта.

Повторить: `make public-filters-probe DEVICE=emulator-5554 PUBLIC_FILTERS_PROBE_OUT=<каталог-сессии>/public-filters`. Нужна существующая сессия эмулятора. ## Фильтры истории просмотров — 09.11.2026

Проверка агентом после входа: у `GET /?mod=history` найдены поле `[data-input=history-search]`, кнопка `[data-click=historydel]` и пагинация. Отдельных элементов жанра, страны, периода или общей формы каталога на этой странице нет. GET с `genre`/`country`, `ganre`/`block`, `period`, `q` и `query` сохранили исходную последовательность записей.

Поиск выполняется отдельным `POST /ajax.php`: `history_search=true`, `query=<название>`. Проверены известное название, заведомое отсутствие совпадений и пустой запрос: получены 12, 0 и исходные 59 записей соответственно. Ответ — фрагмент с `.pgs-history-c`; без совпадений присутствует `.pgs-msg`. Эти количества относятся к проверке, а не к ограничениям протокола. Последующий обычный GET вернул исходную историю, постоянные отметки также сохранились. Очистка не вызывалась; её отдельная реализация описана в [ADR-0124](../adr/0124-confirmed-history-clear.md).

По решению пользователя поиск в приложение не добавляется — [ADR-0123](../adr/0123-history-without-search.md). Исследовательский пункт TODO завершён. Повтор проверки структуры и безопасных GET: `make history-filters-probe DEVICE=emulator-5554 HISTORY_FILTERS_PROBE_OUT=<каталог-сессии>/history-filters`. Команда не отправляет запросы поиска или очистки, не экспортирует личный HTML, cookie, названия или ID записей.

## Что пока не подтверждено

- **Состояние фильтров на сервере.** У личных фильтров и «Лучших сериалов» обычные GET после фильтрации не изменились; для общего каталога сохранение условий в cookie/сессии и независимость вкладок пока не проверены. Перед реализацией убедиться, что фильтрация не меняет постоянные отметки и другие списки пользователя.

## Требования к клиенту

Жанр и страна личных списков, жанр, период и дополнительные переключатели «Лучших сериалов» реализованы; остальные возможности запланированы. Состав и статус задач — в [TODO](../../TODO.md#фильтры-списков).

- **Личные списки: жанр и страна** — реализованы фильтры страницы `/resume` в «Есть обновления», «Нет новых серий», «Хочу посмотреть» и «Посмотрел». Они применяются и к «На чём остановились», который объединяет первые два списка. Есть варианты без ограничения жанра и страны.
- **«Лучшие сериалы»: жанр и период** — выбирать жанр и популярность за день, неделю или месяц. Не смешивать с боковой подборкой «Топ».
- **«Лучшие сериалы»: дополнительные переключатели** — Full HD/1080, HD, субтитры, отечественные сериалы, доступность в стране, показ/скрытие смотримых сериалов, просмотренных ранее и чёрного списка. Реализованы по [ADR-0122](../adr/0122-best-list-switches.md); личные переключатели доступны после входа.
- **Каталог: основные и расширенные фильтры** — размещение непосредственно на странице по [ADR-0126](../adr/0126-catalog-inline-filters.md), без поиска по названию. Страна с включением/исключением; русские/зарубежные/все сериалы; несколько жанров с включением/исключением; год и число сезонов с условиями «равно», «больше», «меньше»; источник рейтинга КиноПоиск/IMDb и условия по рейтинговым группам с учётом проверки выше; озвучка; Full HD/HD и субтитры; условия смотримых сериалов, истории просмотра и чёрного списка. По решению пользователя группу «Прочее» и её параметры — доступность в стране, «Скоро на сайте», переключение оригинальных названий — не реализовывать. Описание этих возможностей сайта выше относится к протоколу, а не к объёму приложения.
- **Каталог: сортировка** — по названию, КиноПоиску, IMDb, году, популярности и времени добавления. По [ADR-0126](../adr/0126-catalog-inline-filters.md) начальный вариант и вариант после сброса — по добавлению, новые первыми; `filter[sortTo][]=newest` проверен отдельным анонимным запросом выше.
- **Боковые «Обновления», «Топ», «Новинки»** — исследованы 09.11.2026; проверенные параметры не применяются у гостя и после входа. Подтверждённых собственных фильтров для подключения нет.
- **«Сегодня» и «Анонсы»** — исследованы 09.11.2026; собственных фильтров не найдено, проверенные GET не меняют выдачу.
- **История просмотров** — исследована 09.11.2026; найден только поиск по названию, его реализация исключена по ADR-0123.
- **Управление фильтрами с пульта** — показывать активные ограничения, дать сброс и сохранять выбор при возврате; состояние каждого списка учитывать отдельно.

## Подключение каталога и повторная проверка — 10.11.2026

Проверено агентом в эмуляторе через общий `SiteClient`, у гостя и в существующей сессии. Полная выдача по добавлению содержала 33 838 уникальных записей, HTML — 5 704 077 байт после распаковки. Один выбранный жанр сократил гостевую выдачу до 602 записей. После входа отдельные флаги `history`, `mark`, `nw` дали 33 568, 33 590 и 33 827 записей. Последующее чтение постоянных отметок совпало с исходным; записи аккаунта не выполнялись. Эти числа описывают проверку, а не ограничения протокола.

В выдаче встречаются повторные ссылки на один ID сезона: приложение сохраняет первое вхождение и исходный порядок. Точный путь берётся из `href`, ID проверяется по пути и `data-id`. Пустой результат распознаётся только по явному сообщению `.pgs-msg`: «Под заданный фильтр ничего не подходит». Условие IMDb `moreR=8`, ранее давшее пустую выдачу, в повторной проверке вернуло 85 записей; конкретная комбинация фильтров не является постоянной фикстурой пустоты.

Приложение отправляет повторяемые параметры массивов, получает свежие опции формы, нормализует сохранённые значения и разделяет общие и личные условия. Кэш содержит исходный HTML с ключом фильтров и сортировки. Разбор из снимка продолжается порциями по [ADR-0131](../adr/0131-windowed-list-parsing.md); общий компонент списка получает постепенно дополняемые записи. Самостоятельной серверной пагинации каталога не обнаружено.

Повторение: `make catalog-live-probe DEVICE=emulator-5554`. Сохраняются только счётчики, время и результат сравнения отметок; тела личных ответов не сохраняются в отчёте.
