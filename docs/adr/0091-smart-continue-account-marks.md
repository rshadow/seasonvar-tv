# ADR-0091: Умный список «Продолжить» по отметкам аккаунта

Дата: 2026-11-06

Статус: Принято; название группы и включение записей без истории пересмотрены в [ADR-0092](0092-personal-continue-history-only.md), порядок загрузки — в [ADR-0095](0095-history-first-continue-loading.md).

Дополняет [ADR-0036](0036-personal-lists.md) и [ADR-0040](0040-details-entry-context.md). Уточняет источник позиции продолжения из [ADR-0031](0031-native-playback.md) только для нового списка.

## Контекст

Сайт может одновременно возвращать завершённый старый и начатый новый сезон. Его списки нужно сохранить без изменения поведения. Пользователь выбрал отдельную группу «Умные списки» с нашим локально вычисляемым «Продолжить», наполняемым существующими отметками аккаунта. Сортировка должна использовать серверные данные, поскольку просмотр происходит на сайте и в приложении. Локальную историю активности не заводим.

## Решение

- После входа меню содержит группу «Умные списки» с пунктом «Продолжить». Это отдельный раздел с собственным представлением лента/плитка, позицией и фокусом. Его можно выбрать первым разделом в настройках. Заголовок группы не получает фокус.
- Исходные записи — тот же авторизованный `/resume`, что у «На чём остановились». Публичные подборки, все личные списки сайта и история сохраняют прежний состав, порядок и точные переходы.
- Группируем записи по `data-id-serial`, не по названию. Список сезонов даёт их номера и точные ссылки. В группе выбираем последний по порядку сезон с действующей отметкой.
- Постоянная отметка с ненулевым временем означает продолжение той же серии с этой позиции. Нулевое время означает просмотренную серию: выбираем следующую в цепочке сайта. Счётчик «N из N» сам по себе не доказывает завершение последней серии.
- После последней просмотренной серии ищем первый доступный эпизод следующего сезона. Пропускаем уже просмотренные сезоны и ещё не доступные анонсы; не предлагаем трейлеры. Чёрный список учитываем. Если продолжения нет, сериал скрывается из этого списка. Серверные отметки при этом не удаляются.
- Сохраняем совместимую озвучку, затем применяем предпочтения и стандартный вариант по действующим правилам. Недоступная известная серия не заменяется произвольной первой.
- Одна карточка на сериал с постоянным ключом `smart:<serialId>`. Она заранее содержит целевые сезон, серию, озвучку и время в общей `EntrySelection`; открытие не пытается извлекать их из подписи.
- Сортировка — по первому появлению сериала в истории аккаунта, которую сайт отдаёт от новых записей к старым. Учитываются все его сезоны, повторы не меняют найденный новый ранг. Подгружаем страницы, пока найдены все кандидаты или история закончилась. Карточки без записи в истории идут после известных в стабильном порядке. Дата выхода серии не используется.
- Серверная история может не содержать просмотр, сделанный в приложении. Запись в неё отдельным протоколом пока не реализована; это ограничение сортировки, а не повод придумывать локальные даты.
- Результат кэшируется в приватных настройках устройства отдельно для владельца. В кэше только сведения карточки и контекст продолжения; cookie, паролей и видеоссылок нет. Выход и смена аккаунта очищают прежний кэш и отменяют запросы. Запоздалый ответ не может попасть в другую сессию.
- При каждом открытии раздела и возврате приложения на передний план сначала показываем кэш, затем обновляем в фоне: просмотр на сайте не создаёт локального сигнала обновления. Ограничиваем одновременные запросы страниц. Сбой отдельной записи не заставляет вернуться к более старому завершённому сезону: сохраняем прежнюю неуточнённую карточку и показываем ошибку обновления. Сетевые ошибки, HTTP и разметку различаем.
- Явную позицию передаём в плеер как `PlaybackRequest.resumePositionMillis`. Ноль начинает выбранную следующую серию с начала и не подменяется прежней локальной позицией. Подсказка используется один раз, при смене серии очищается. Обычные открытия и локальное сохранение позиции сохраняют прежние правила.
- Автопереход видео внутри плеера остаётся в пределах текущего сезона по ADR-0080. Выбор следующего сезона здесь относится к следующему открытию из списка продолжения.
- Раздел ничего не записывает в аккаунт сам по себе. Обычное сохранение прогресса во время просмотра работает по ADR-0056; обновление отметок помечает умный список для перечитывания.

## Альтернативы

- Изменить «На чём остановились» и «Есть обновления»: пользователь предпочёл соответствие спискам сайта.
- Собирать новую локальную историю просмотров: не учитывает активность на другом устройстве и не соответствует выбранному источнику данных.
- Открывать самый новый доступный сезон без проверки отметки: можно пропустить непросмотренные серии.
- Брать дату из подписи `/resume`: там встречаются даты выхода, не время просмотра.

## Последствия и проверка

Раздел зависит от входа и доступности данных сайта; на первом открытии нужны страницы отмеченных сезонов и история. Кэш сохраняет отзывчивость при последующих открытиях. Для надёжного порядка всех просмотров между приложением и браузером требуется отдельное исследование записи серверной истории.

Проверки: `make check` с синтетическими отметками, цепочками серий, историей и кэшем; read-only `make smart-continue-probe DEVICE=emulator-5554`; обязательный `make player-probe DEVICE=emulator-5554` с просмотром кадров после изменения позиции запуска. Возврат к обычной тестовой сборке — `make run-profile DEVICE=emulator-5554`.
