# ADR-0024: Поиск с системным текстовым и голосовым вводом

Дата: 2026-11-02

Статус: Принято. Хранение истории и начальный фокус уточнены в [ADR-0082](0082-local-search-history.md).

## Контекст

Пользователь выбрал поиск по кнопке с лупой вместо названия приложения в левом верхнем углу. Ввод — стандартной Android-клавиатурой; отдельная кнопка микрофона должна находиться слева от поля. Проверен публичный JSON `GET /autocomplete.php?query=…`: результаты содержат отдельные сезоны и точные пути страниц.

## Решение

- Вместо заголовка меню показывать квадратную кнопку с лупой. Как у «Обновить», без фокуса видна только иконка, при фокусе — золотая кнопка. Фокус сам по себе не открывает поиск: требуется OK или клик.
- По нажатию показывать поиск справа, переводить фокус в стандартное текстовое поле Compose и открывать системную IME. Поле, иконки, цвета и интервалы используют общую тему. Собственную клавиатуру не создавать. Начальную подсказку показывать один раз в центре экрана; под полем выводить только счётчик после получения результатов.
- Слева от поля размещать кнопку микрофона. Она запускает `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` через Activity Result API. Первый непустой результат становится запросом. Отмена сохраняет прежний текст; отсутствие системного обработчика или пустой успешный ответ показывать явно. Запись аудио выполняет выбранный системный обработчик, приложение не запрашивает доступ к микрофону.
- Отправлять URL-кодированный GET к оригинальному сайту с текущими настройками DNS и обхода. Пустую строку не отправлять. После набора ждать 300 мс; действие поиска на клавиатуре и обновление запускают запрос сразу.
- Отменять предыдущий поиск при изменении текста и уходе с экрана; отменённый ответ не может изменить новую выдачу. Разбор JSON выполнять в фоне, проверять соответствие запросу, типы, длины параллельных массивов, ID и адреса страниц. Сохранять порядок сайта, очищать HTML, номер сезона брать из подписи, а путь — из ответа. В смешанной выдаче разделители с пустым путём не имеют ID; индекс ID увеличивать только для непустых путей. Актёры и теги не становятся карточками сериалов. Выдачу без сериалов показывать как «Ничего не найдено» с пояснением «Попробуйте уточнить название»; реальные ошибки сети сохранять отдельно.
- Использовать общую ленту карточек и описаний. Номер сезона показывать на миниатюре, когда нет подписи обновления. Клавиатура скрывается при выполнении действия поиска; вниз из поля без клавиатуры переводит к результатам. На конце ленты фокус останавливается; вверх ведёт на обновление. Закрытие описания возвращает к выбранной карточке.
- «Назад»/Esc при открытой клавиатуре сначала скрывает её. Следующий возврат переводит фокус на лупу. Двойной возврат после закрытия IME сохраняет правило выхода ADR-0013. Запрос, выбор и позиция поиска независимы от других разделов; новый текст начинает ленту сначала.
- Последнюю выдачу и текст хранить в памяти ViewModel, без дисковой истории запросов. При возврате сохранять готовые результаты, прерванный поиск запускать заново. Описания и постеры используют существующие общие кэши.

Уточняет верхнюю область меню из [ADR-0023](0023-compact-rectangular-menu.md) и ввод/возврат из [ADR-0013](0013-navigation-without-back-buttons.md).

## Альтернативы

- Собственная экранная клавиатура дублирует системную и не соответствует запросу пользователя.
- Собственный распознаватель через `SpeechRecognizer` требует управления аудио, разрешениями и жизненным циклом; на этом этапе достаточно системного диалога.
- Запрос на каждый символ создаёт лишние обращения и гонки; поиск только после OK требует больше нажатий.
- Парсинг страницы результатов вместо проверенного JSON добавляет зависимость от HTML.

## Последствия

Поиск не требует входа и показывает сезоны из автодополнения сайта. Наличие распознавания речи, язык и качество зависят от сервисов устройства; отсутствие обработчика не мешает текстовому поиску. Воспроизведение и выбор серий остаются отдельными задачами.
