# ADR-0039: История просмотров аккаунта

Дата: 2026-11-03. Статус: принято.

## Контекст

Пользователь попросил добавить историю оригинального сайта `https://seasonvar.ru/?mod=history`. Это отдельная страница аккаунта, не вкладка отметок `/resume` и не локальный список запусков нашего плеера. Публичный ответ требует входа; авторизованная структура проверена в эмуляторе 2026-11-03 внутри приложения без извлечения cookie и сохранения личного HTML.

## Решение

Добавляем «История просмотров» после «Посмотрел» в личные пункты меню. Раздел виден после входа, открывается при наведении фокуса и использует общую ленту с карточкой выбранного сериала. Миниатюры содержат название и подпись «Сезон N · Серия M» при наличии полей; дата из истории показана только в большой и открытой карточке с подписью «В истории сайта: …». Значение даты сохраняется как на сайте. Сохраняются отдельная выбранная карточка, позиция ленты и возврат Esc/Назад.

Источник — авторизованный `GET /?mod=history`. Контейнер: `.pgs-history [data-result=history]`, записи: `.pgs-history-c a`. Внутри записи `b` содержит название, `span` — дату, собственный текст ссылки — сезон, серия и озвучка. Номер серии читаем из этого текста, а не выводим из ID сезона или фрагмента ссылки. Если серия не указана, не подставляем вымышленный номер. В большой карточке номер серии также включается в строку истории. Точный путь сериала берём из `href`, фрагмент ссылки не трактуем как подтверждённую позицию видео. Название разбирается на русское и оригинальное при наличии. Сохраняем порядок ответа, все записи страницы и повторные появления одного сезона.

Пагинацию читаем из `.pgs-history-p a[href]`. Следующие страницы загружаются в фоне по мере приближения к концу ленты и дописываются в неё. При подгрузке карточки и фокус сохраняются, индикатор работает на кнопке обновления. При ошибке остаётся загруженная часть; кнопка повтора загружает неудавшуюся следующую страницу. Обычное обновление перечитывает историю с первой страницы.

Принимаем только HTTPS-ссылки оригинального сайта на `/` с `mod=history` и положительным номером `page`. Внешние домены, другие операции, лишние параметры, пропуски и циклы пагинации не обходятся автоматически. Авторизацию проверяем на каждой странице; истечение сессии очищает все личные разделы. Пустая история требует подтверждённой авторизации и распознанного контейнера. Ошибки сети, HTTP и разметки различаются.

История хранится только в памяти. При выходе или смене аккаунта отменяются запросы и очищаются страницы, выбор и позиция. При выборе другого сезона в карточке дата и номер серии исходной записи сбрасываются. Поиск внутри истории, её удаление и запись истории на сайт этим разделом не реализуются.

## Альтернативы

- Только первая страница: скрывает старые записи.
- Загрузка всех страниц заранее: увеличивает ожидание и расход памяти для длинной истории.
- Локальная история плеера: не повторяет данные учётной записи сайта.

## Последствия

В меню становится шесть личных разделов; общая прокрутка меню сохраняется. Чтение истории не означает синхронизацию серверных отметок или времени просмотра. Парсер, маршрутизация, границы пагинации, повторы и отмена поздних ответов проверяются на синтетических данных.

Проверка: `make check` (168 JVM-тестов, 17 Python-тестов и Lint) и `make build-profile` прошли; в эмуляторе подтверждены загрузка, соответствие числа записей ответу сайта, сезон и серия на миниатюрах, дата, обновление и восстановление фокуса. Многостраничный сценарий проверен синтетическими тестами: в доступной истории аккаунта одна страница.
