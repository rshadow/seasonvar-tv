# ADR-0048: Постоянная подпись release APK

Дата: 2026-11-03

Статус: Хранение секретов пересмотрено [ADR-0049](0049-project-local-secrets.md); остальные решения действуют.

## Контекст

Для распространения APK через GitHub Releases нужна постоянная подпись: Android принимает обновление установленного приложения только с совместимым сертификатом и возрастающим `versionCode`. Debug/profile используют отладочную подпись и не служат опубликованными релизами.

Пользователь создал ключ RSA 3072 в PKCS12 и попросил хранить его отдельно от остальных секретов, в `android.env`. Генерация ключа остаётся разовой операцией без цели Makefile.

## Решение

- Единственный локальный источник ключа и паролей подписи — `~/android.env`, права `0600`. Это исключение из общего правила о `~/secrets.env`; прежние параметры подписи оттуда удалены.
- Файл содержит `SEASONVAR_SIGNING_KEYSTORE_BASE64`, `SEASONVAR_SIGNING_STORE_PASSWORD`, `SEASONVAR_SIGNING_KEY_PASSWORD`, `SEASONVAR_SIGNING_KEY_ALIAS`. PKCS12 хранится в Base64; отдельный бинарный файл ключа не создаётся.
- `make release` собирает оптимизированный неподписанный APK штатным Gradle, затем запускает [SignRelease.java](../../scripts/SignRelease.java). Скрипт загружает ключ в память и подписывает APK через библиотеку `apksig` из закреплённого SDK Build Tools 35.0.0.
- APK подписывается по схемам v2/v3; minSdk приложения — 26. После подписания проверяются обе схемы и сертификат. При неудаче выходной APK удаляется. Значения секретов, исключения и содержимое хранилища не выводятся.
- Результат — `app/build/outputs/apk/release/app-release.apk`. Обычные debug/profile-сборки не требуют ключа; `make release` не устанавливает приложение и не публикует его.
- Для обновлений использовать тот же ключ и увеличивать `versionCode`. Резервная копия `~/android.env` хранится отдельно от Git; пересоздание ключа не заменяет его восстановление.

## Альтернативы

- **Подпись debug-ключом.** Подходит для разработки, но не для постоянных публичных релизов.
- **Бинарный keystore в проекте или временном каталоге.** Создаёт дополнительную копию секретного ключа; выбран загрузчик PKCS12 в памяти.
- **Ключ и пароли в общем `~/secrets.env`.** Пользователь предпочёл отдельный файл для Android.
- **Генерация через Makefile.** Пользователь попросил оставить её разовой ручной операцией.

## Последствия и ограничения

Для первой установки release вместо debug/profile потребуется удалить приложение; локальные настройки, позиция просмотра и сессия при этом теряются. Автоматически удалять установленную версию нельзя.

Подпись не заменяет функциональную проверку релиза. Публикация на GitHub и настройка CI — отдельные действия; этот ADR определяет локальную сборку и подпись APK.
