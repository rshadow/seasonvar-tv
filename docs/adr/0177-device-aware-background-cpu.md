# ADR-0177: общий бюджет вычислений при подготовке списков

Статус: принято. Дата: 2026-11-17. Дополняет [ADR-0003](0003-performance-principles.md), сохраняет [ADR-0170](0170-list-visibility-and-background-refresh.md) и общий механизм окна подготовки.

## Контекст

Ограничение предзагрузки тремя ресурсами не охватывает параллельный разбор посещённых списков, общие данные карточек и обработку изображений. Работа вне главного потока всё ещё конкурирует с интерфейсом за процессор и память. Приложение запускается на устройствах с разным числом доступных процессоров.

## Решение

`BackgroundCpu` предоставляет один общий `Dispatchers.IO.limitedParallelism` для тяжёлой подготовки. Лимит рассчитывается при создании процесса через `Runtime.availableProcessors()`: число доступных процессоров, минимум один. Политика находится в `CacheSettings.cpuParallelism`, без настройки в интерфейсе и таблицы моделей. Для четырёх доступных процессоров лимит равен четырём; для восьми — восьми. Это ограничение одновременных вычислений, а не привязка потоков к физическим ядрам.

Общий диспетчер используют разбор публичных и личных списков, каталога и данных карточек, продолжение оконного разбора, декодирование миниатюр при предзагрузке и подготовка размытого фона. Получение сетевого ответа, чтение и сохранение HTML-кеша остаются на прежних путях I/O; ожидание сети не удерживает вычислительный слот. Потоковый HTML-парсер читает переданный локальный Reader в пределах вычислительной задачи, сохраняя окно 250/200 и освобождение источника при отмене.

Планирование окна и порционная подготовка карточек для показа остаются на обычном `Default`. Изображения, непосредственно запрошенные интерфейсом, декодируются на `Default`; предзагрузка задаёт ограниченный диспетчер в запросе Coil. Фоновая подготовка использует отдельный view с ограничением числа выполняемых задач, сохраняя логическую ёмкость `Default` для видимого экрана. Длина очереди этим механизмом не ограничена; собственный пул потоков не создаётся. Операционная система распределяет фактическое процессорное время; свободное физическое ядро и строгий приоритет не гарантируются.

Скрытые посещённые списки продолжают обновляться заранее. Порядок ресурсов выбранной и видимой части окна, сетевая параллельность, настройка предзагрузки, объём общего кеша и локальное применение отметок сохраняются. Постоянный регулятор нагрузки, опрос температуры и изменение размера пула во время работы в это решение не входят.

## Проверка и альтернативы

Profile-сборка содержит отдельный замер реального разбора 250 записей и декодирования локального JPEG при навигации. Есть непрерывная стресс-нагрузка с большим JPEG и конечная пачка из 12 разборов и 24 декодирований обычных миниатюр 200 × 300 px. Сравнение выполняется на одном оптимизированном APK с одинаковым ART, исходными данными и прогревом. Подмена диспетчера разрешена только в profile-сборке; обычный release не имеет переключателя политики.

Проверяются реакция фокуса, кадры, CPU, очередь, выполненная работа и готовность пачек, GC, подписки отметок и удержание кеша. Само сокращение потраченного CPU или числа завершённых задач не считается ускорением. [Методика и результаты](../development.md#фоновая-подготовка-и-отзывчивость) должны сопровождать изменение политики; эмулятор не подтверждает производительность Ugoos.

Сохранение неограниченного I/O-пула для вычислений не задаёт общий бюджет. Независимый лимит для каждого обработчика суммирует параллельность. Ограничение всей работы одним бюджетом заставляет короткую подготовку видимого экрана ждать тяжёлую предзагрузку. Гипотеза с половиной процессоров не принята: в конечной пачке готовность данных ухудшалась без устойчивого выигрыша отрисовки. Общий `Default` с полной ёмкостью также не даёт раздельной очереди для интерфейса; выбран ограниченный I/O-view. Собственный пул потоков и закрепление ядер не требуются для этого решения.

Основание: [Runtime.availableProcessors](https://developer.android.com/reference/java/lang/Runtime#availableProcessors()), [Kotlin limitedParallelism](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-coroutine-dispatcher/limited-parallelism.html). Нужны проверки отмены до начала разбора и при возврате готового окна, защиты аккаунта, кеша и фокуса.
