# ADR-0058: Бесплатные проверки безопасности GitHub и защита изменений

Дата: 2026-11-04

Статус: Принято

Дополняет [ADR-0050](0050-github-actions-builds-and-releases.md) и сохраняет [ADR-0053](0053-explicit-release-tag-command.md).

## Контекст

Репозиторий публичный. Пользователь выбрал Secret scanning/Push protection, Dependabot, CodeQL, проверку новых зависимостей в PR и защиту main/релизных тегов. Эти функции доступны для публичного репозитория бесплатно. Серверные переключатели и импорт правил владелец выполняет вручную; конфигурации и результаты CI хранятся в проекте/GitHub.

## Решение

- Секреты проверять средствами GitHub Secret scanning и Push protection. Это дополняет игнорирование локальных файлов, включая корневой cookies, и не гарантирует обнаружение любого произвольного пароля.
- Dependabot проверяет Gradle и GitHub Actions еженедельно по понедельникам. Minor/patch обновления объединяются в PR, major изменения остаются отдельными. Автоматического слияния нет. Alerts/security updates включаются в настройках репозитория; version updates задаёт `.github/dependabot.yml`.
- CodeQL анализирует Java/Kotlin, Python и GitHub Actions на push в main, PR, еженедельно и вручную. Используется advanced setup с security-extended. Kotlin собирается через `make codeql-build`: повторная компиляция без кэша/инкрементальности, включая утилиту подписи. Утилита только компилируется, ключи и файл секретов не читаются. PR и анализ CodeQL не получают ключ подписи APK.
- Для Gradle формировать фактически разрешённый граф, включая транзитивные зависимости. `Dependency graph` исполняет код сборки с contents: read и сохраняет граф как артефакт. Отдельный `Publish dependency graph` по workflow_run получает contents: write только для отправки данных: он не делает checkout, не запускает shell/Gradle/код PR и использует закреплённые официальные actions. Статус Dependency snapshot ставится на коммит исходного workflow только после успешной публикации; при ошибке устанавливается failure. Для этого выдаётся statuses: write. Этот путь применяется и к PR из forks/Dependabot.
- `Dependency review` запускается на PR с contents: read, ожидает публикацию снимков до 25 минут и до сравнения требует успешный Dependency snapshot и для base, и для head, затем отклоняет новые уязвимости уровня high/critical. Отсутствующий снимок не считать доказательством безопасности. Остальные уровни показываются для разбора; автоматического обновления/слияния нет.
- В main запрещены удаление и force push. Изменения проходят через PR с актуальной базой, разрешёнными обсуждениями и успешными проверками build, CodeQL для трёх языков, Dependency graph, Dependency snapshot и Dependency review. Источник обязательных статусов — GitHub Actions. Результаты CodeQL дополнительно блокируют ошибки и security alerts high/critical. Обязательных одобрений другого человека нет: владелец работает один. Исключений для обхода правил не добавляется.
- Для v* запрещены удаление и force push; создание нового тега разрешено только по явной команде пользователя, как и раньше. Импортируемые правила — `.github/rulesets/main.json` и `.github/rulesets/release-tags.json`. Отправка обычных коммитов/настройка безопасности не создают релиз.
- Первое подключение workflow допускает начальный push конфигурации до включения защиты: workflow_run должен уже существовать в default branch, чтобы опубликовать начальный граф. После начального успешного анализа и проверки PR владелец импортирует активные правила. Файлы правил сами по себе не включают защиту на сервере.
- Сохранить текущую сборку/тесты/подпись по ADR-0050. Новые actions закрепляются полными SHA в workflow и toolchain.lock.json. Для Gradle action выбран внешний кэш Actions; коммерческий провайдер кэша не подключается. Используются стандартные Ubuntu runners публичного репозитория.
- Штатные команды установки инструментов, экспорта путей SDK/JDK для Actions и сборки CodeQL находятся в Makefile: ci-tools, ci-export-env, codeql-build. CI не требует глобальной установки SDK или навыков на компьютере разработчика.

Запросы GitHub API при ожидании снимков повторять до трёх раз средствами `actions/github-script` с увеличением задержки. Это обрабатывает временные HTTP 5xx; обычные ошибки 400/401/403/404/422 не повторяются. Ошибка публикации снимка, истечение 25 минут или найденная уязвимость по-прежнему завершают проверку ошибкой; повтор запроса не заменяет успешный снимок.

## Альтернативы

- Только Android Lint и тесты не проверяют все известные уязвимости сторонних библиотек и весь поток данных приложения.
- CodeQL default setup не использует подготовку закреплённого SDK и отдельную компиляцию инструмента подписи.
- Dependency graph только по тексту Gradle не даёт полного разрешённого дерева. Один переключатель Dependabot без снимков недостаточен для этого проекта.
- Выдача contents: write коду PR ограничивает поддержку forks и увеличивает риск изменения репозитория. Публикация готовых данных вынесена в отдельный workflow.
- Обязательное одобрение другого человека блокировало бы работу единственного владельца.

## Последствия и проверка

Появляются дополнительные CI-запуски и PR Dependabot; проверки PR могут ждать разрешения зависимостей. Секреты остаются в разрешённых хранилищах, сканеры не заменяют правила их хранения. Проверки безопасности не заменяют запуск приложения и видимого видео по правилам проекта.

Фактические серверные настройки отличаются от содержимого файлов: порядок ручного включения и импорт правил описаны в [docs/github-security.md](../github-security.md). Результаты первого запуска фиксируются после проверки GitHub Actions; заранее считать их успешными нельзя.
