# ADR-0069: Короткое описание релиза для пользователей

Дата: 2026-11-04

Статус: Принято

Уточняет описание релиза из [ADR-0050](0050-github-actions-builds-and-releases.md).

## Контекст

Автоматический список коммитов раскрывает детали разработки и неудобен пользователям. Пользователь выбрал для выпуска без новых пользовательских функций версию 0.3.1 и попросил описывать релизы кратким списком предложений до 10 слов.

## Решение

- Писать описание на русском простыми словами, без названий библиотек, CVE, команд, коммитов и PR.
- Использовать список: каждый пункт — короткое предложение до 10 слов. Не добавлять заголовки и автоматически сгенерированный changelog.
- Описывать только реальные изменения; не обещать новые функции, если их нет. Для 0.3.1: «Обновлены компоненты приложения».
- Хранить текст в docs/releases/<versionName>.md рядом с исходниками соответствующего выпуска.
- make release-package проверяет список и длину пунктов, сохраняет NOTES.md вместе с APK и SHA256SUMS. Публикующая job читает этот файл через --notes-file; код репозитория она не выполняет.
- Перед выпуском увеличивать versionCode. Для 0.3.1 выбран versionCode 3, после 0.3.0 с versionCode 2.
- Создание тега по-прежнему требует явной команды пользователя по ADR-0053.

## Альтернативы

- Автоматические примечания GitHub: перечисляют изменения разработчиков вместо короткого пользовательского описания.
- Ручное редактирование после публикации: усложняет повторяемость выпуска и оставляет промежуточное описание.

## Последствия

Каждый выпуск получает отдельный проверяемый текст. Отсутствие описания или неправильный формат останавливает упаковку. История исходников и PR остаётся доступна в репозитории без включения в текст релиза.
