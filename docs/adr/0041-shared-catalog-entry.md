# ADR-0041: Единая частичная модель карточки списка

Дата: 2026-11-03. Статус: принято.

## Контекст

Разные списки Seasonvar предоставляют разный набор данных. История знает сезон, серию, озвучку и дату; обновления содержат серию и иногда озвучку; поиск обычно знает только страницу сезона. Пользователь предложил заранее собирать доступные сведения в одну структуру, которую карточка использует при открытии.

## Решение

Единое определение карточки — `SeriesEntry` в [CatalogModels.kt](../../app/src/main/java/ru/seasonvar/tv/data/CatalogModels.kt). Здесь же определены вложенные типы данных записи, включая `EntrySelection`, `AccountMark`, `AccountProgress`, `ProgressCounter` и `SeasonEpisodeProgress`.

| Данные | Поля |
| --- | --- |
| Точный сезон и страница | `id`, `url`, необязательный номер `season` |
| Название, оригинальное название, постер | `title`, `originalTitle`, `posterUrl` |
| Известная серия | `initialSelection.episodeId`, `initialSelection.episodeLabel` |
| Известная озвучка | `initialSelection.translationId`, `initialSelection.translationLabel` |
| Прогресс аккаунта | `accountProgress.seasons` — сезон отметки / всего сезонов; `accountProgress.episodes` — ID сезона и отмеченные / все эпизоды ([ADR-0043](0043-account-progress-in-controls.md)) |
| Остальные сведения источника | `update`, `isNew`, `seasonCountLabel`, `previewDescription`, `accountMark`, `historyVisitedAt` |
| Идентичность записи | `sourceKey` и вычисляемый `key`; разные записи одного сезона сохраняются |

Неизвестные необязательные поля остаются `null`, блок выбора по умолчанию пуст. Наличие номера сезона не означает, что известны серия или озвучка. Доступный ID не подменяется номером или индексом. Один факт хранится в одном поле: отдельное `historyEpisode` удалено, история использует общий `initialSelection.episodeLabel`.

Парсеры заполняют модель до передачи интерфейсу. История читает серию и озвучку из текста записи, публичные обновления — из своих полей обновления, личные отметки — распознанный ID серии из ссылки. Если одна запись содержит несколько обновлений, сохраняются только общие однозначные параметры. Исходные подписи для отображения сохраняются отдельно.

Открытие карточки принимает сам `SeriesEntry`; общий механизм по [ADR-0040](0040-details-entry-context.md) сопоставляет известные ID и названия с данными выбранного сезона. Интерфейс не разбирает подпись миниатюры и не содержит правил извлечения для отдельных разделов. Полная карточка по-прежнему использует `SeriesDetails` для загруженных сезонов, озвучек, эпизодов и остальных метаданных.

Модель исходной записи неизменяема. Текущий ручной выбор хранится в состоянии карточки и не переписывает данные истории или каталога. При повторе загрузки сохраняется текущий выбор, а исходная запись остаётся той же. Личные данные и контекст остаются в памяти согласно правилам аккаунта.

## Альтернативы и последствия

Разбирать подпись после нажатия — связывает переход с оформлением и повторяет парсинг в интерфейсе. Отдельные модели перехода для каждого списка — создают разные правила для одинаковых параметров. Дублирование серии в поле истории и общем контексте ведёт к расхождению значений.

Новые списки заполняют тот же `SeriesEntry` имеющимися данными. Новые поля и их семантика добавляются в центральную модель; изменение оформления подписи не влияет на выбор серии и озвучки.
