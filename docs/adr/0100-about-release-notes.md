# ADR-0100: Описания установленного и новых выпусков в «О программе»

Дата: 2026-11-07

Статус: Принято

## Контекст

Одного номера новой версии недостаточно, чтобы решить, устанавливать ли обновление. Даже после обновления пользователь должен видеть, что изменилось в установленной версии. Проверка и установка уже описаны в [ADR-0074](0074-in-app-github-updates.md).

## Решение

- При входе в «О программе» вместе с проверкой обновления отдельно загружать описания опубликованных стабильных выпусков GitHub. Показать установленную версию и все более новые, от большего номера к меньшему. Черновики, prerelease и обычные теги без релиза не показывать.
- Для каждого выпуска вывести версию, дату публикации и полный текст описания с абзацами и пунктами списка. Установленный выпуск отметить словом «Установлена». Для пустого описания написать «Описание изменений не указано». Если подходящих опубликованных выпусков нет, явно сообщить, что описание этой версии пока недоступно.
- При отсутствии обновлений оставить сообщение «Установлена последняя версия» и описание установленного выпуска. Для локальной сборки `0.4.0-dev<hash>` использовать базовую версию `0.4.0` при сравнении и выборе описаний. Это не ослабляет строгую проверку стабильных тегов GitHub и проверку APK.
- Оставить одну кнопку скачивания и установки последней новой версии над описаниями. Не добавлять отдельную кнопку проверки. Ошибка или долгая загрузка описаний не блокирует проверку обновления, скачивание и установку. Ошибки описаний показывать отдельно; при неудачном обновлении списка оставлять сохранённый текст.
- Сохранять описания во внутреннем кэше `updates/release-notes.json`, отдельно от APK. При повторном входе показывать кэш сразу и обновлять в фоне; чтение, сеть, разбор и запись выполняются вне UI-потока. Публиковать новый кэш только после успешной загрузки всех страниц; отмена, повреждённый ответ и сетевой сбой сохраняют прежний файл. Неудачная запись кэша не скрывает уже загруженные описания. Android может освободить внутренний кэш.
- Использовать анонимный `GET /repos/rshadow/seasonvar-tv/releases?per_page=100&page=N` через отдельный клиент GitHub без сессии Seasonvar. Загружать страницы до неполной, а не до первой старой версии: порядок публикации может отличаться от порядка версий. Ограничивать размер ответа и всей истории; при превышении лимита показывать ошибку, а не выдавать усечённый список за полный.
- Весь экран прокручивается стрелками пульта. После последней кнопки стрелка вниз листает описания; вверх возвращает к кнопкам, влево и «Назад» — в главное меню. Текст не получает отдельных остановок фокуса. Сохраняются стили общей темы, без рамок вокруг выпусков и без обрезания описаний.

## Альтернативы

- Показывать только последний выпуск: пропускает промежуточные изменения и описание установленной версии.
- Связать описания с единственным `/latest`: недостаточно данных и недоступность истории мешала бы установке.
- Открывать GitHub или WebView: неудобно с пульта и требует перехода из приложения.
- Хранить только в памяти: повторное открытие после перезапуска снова требует сети.

## Последствия и проверка

Дополнительный запрос истории выполняется независимо от проверки APK. История требует пагинации и отдельного состояния ошибок; кэш не содержит сессии, токенов или подписанных видеоссылок. Полный Markdown с интерактивными ссылками не нужен: наши краткие описания по [ADR-0069](0069-short-release-notes.md) состоят из текста, абзацев и списков.

`make update-test` проверяет фильтрацию и числовую сортировку, dev-версию, пагинацию после старых выпусков, сохранение текста, кэш между экземплярами репозитория, отмену и сбой обновления, повреждённый кэш и независимость установки. `make update-preview DEVICE=emulator-5554` показывает длинную историю с новой версией; `UPDATE_PREVIEW_SCENARIO=current` — установленную, `notes-network` — сохранённое описание при ошибке истории и доступном обновлении.

Источник контракта: [GitHub REST API — List releases](https://docs.github.com/en/rest/releases/releases#list-releases), проверено 2026-11-07. Публичные релизы доступны без авторизации; ответ содержит `body`, `published_at`, `draft`, `prerelease`, `tag_name`, параметры страниц — `page` и `per_page` (до 100).

2026-11-07: `make check` — 459 JVM-тестов, проверки Python и зависимостей, debug-сборка и lint прошли. В эмуляторе проверены длинная история новой версии, возврат к кнопкам и сохранённый текст при ошибке истории с доступной установкой. Затем восстановлена обычная profile-сборка: показаны настоящий выпуск 0.4.0, дата и все девять пунктов его описания.
