# ADR-0146: особенности «АнтиЗапрета» только в его предустановке

Статус: принято. Дата: 2026-11-11. Уточняет [ADR-0144](0144-custom-pac-source.md) и [ADR-0145](0145-proxy-tls-chain-completion.md).

## Контекст

Пользовательский PAC должен работать без обходных решений, предназначенных для конкретного сервиса. Совпадение адреса PAC не означает одинаковый ответ: «АнтиЗапрет» выбирает содержание по User-Agent.

## Решение

Специальный браузерный User-Agent, закрепление сертификата сервера получения PAC и дополнение цепочки HTTPS-прокси перекрёстным сертификатом настраиваются только в ветке `AntiZapret`. Пользовательский PAC получает обычный User-Agent приложения, общую политику закрепления сертификатов и системный TLS для прокси. HTTP CONNECT, SOCKS5 и прямой транспорт не используют настройки предустановки.

Загрузчик, вычислитель, расписание, статусы и применение нативных маршрутов общие. Источник передаёт им свои параметры. Проверка конечного сайта и его закреплённых сертификатов сохраняется во всех режимах.

Файл PAC, таблица маршрутов, время успешного получения и период обновления разделяются по каноническому адресу и варианту источника. Это пересматривает совместное использование одной копии из ADR-0144: ответ для браузерного заголовка предустановки нельзя подставлять пользовательскому PAC. Минутное ограничение попыток остаётся общим для одного канонического адреса, включая переключение между двумя вариантами и перезапуск приложения.

## Альтернативы и последствия

Глобальное дополнение цепочек изменяло бы поведение пользовательских серверов. Дублирование загрузчика и интерфейса создало бы две расходящиеся реализации. Явные параметры источника изолируют особенности сервиса и сохраняют единый механизм PAC.
