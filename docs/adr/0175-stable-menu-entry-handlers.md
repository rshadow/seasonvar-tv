# ADR-0175: стабильные обработчики входа из меню

Статус: принято. Дата: 2026-11-16. Дополняет [ADR-0025](0025-responsive-section-switching.md).

## Контекст

Обработчики OK и вправо у каждого пункта меню захватывали `enterContent` с параметрами текущего списка. Смена раздела меняла обработчики и модификаторы всех пунктов. На фиксированных данных 48 переходов вызывали 816 композиций `ThemeButton`, хотя изменялось оформление двух пунктов.

## Решение

Меню получает актуальное действие входа через `rememberUpdatedState`. Обработчики читают его при нажатии, сохраняя свою идентичность между обновлениями содержимого. Выбор раздела выполняется немедленно; действие использует текущие список, раскладку и выбранную карточку. Состояние фокуса остаётся внутри кнопки.

Действие передаётся лямбдой `{ enterContent() }`. Ссылка на локальную функцию `::enterContent` в используемом Kotlin сравнивается как равная при разных захваченных контекстах: структурная политика `rememberUpdatedState` сохраняет старое значение. Проверка входа в разные списки должна выявлять такую ошибку.

Сохраняем общий `ThemeButton`, его выравнивание, оформление и стандартную проверку параметров Compose. Новые границы экранов, задержки переключения и аннотации стабильности моделей не вводятся.

## Альтернативы и последствия

Кеширование действия без обновления сохраняет старый контекст списка. Вынос всего состояния экранов расширяет изменение без необходимости: достаточно сохранить обработчики существующих кнопок. Смена раздела продолжает обновлять содержимое, а неизменившиеся пункты меню пропускаются.

Проверка отделяет движение фокуса верхних кнопок от смены раздела, считает композиции и измеряет CPU и кадры без трассировщика. Функциональный сценарий проверяет OK, вправо, карточку и возврат для всех списков в обеих темах. Методика и ограничения приведены в [документации разработки](../development.md#кнопки-меню-и-смена-фокуса).
