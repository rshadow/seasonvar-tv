# ADR-0074: Проверка и установка обновлений из GitHub

Дата: 2026-11-04

Статус: Принято

## Контекст

Пользователь хочет узнавать о новой версии и устанавливать её из «О программе». Проверка запускается сразу при входе в раздел, без отдельной кнопки. Подпись и данные установленного приложения должны сохраняться по ADR-0048 и ADR-0071.

## Решение

- При каждом входе в «О программе» запрашивать последний стабильный опубликованный выпуск через `GET https://api.github.com/repos/rshadow/seasonvar-tv/releases/latest`. Повторные вызовы во время проверки, загрузки или установки не создают второй запрос. Автоматических проверок по таймеру и при обычном запуске приложения нет.
- Показывать установленную версию, состояние проверки и версию последнего выпуска. Числовые компоненты версии сравнивать отдельно: 0.10.0 новее 0.9.0. Равная и более старая версии не предлагают установку. Отсутствие релизов и ошибки сети, HTTP и формата различать.
- Для более новой версии показывать «Скачать и установить», только если у релиза есть загруженный `seasonvar-tv-<version>-universal.apk`, допустимый размер и SHA-256 в поле `digest`. Если APK ещё недоступен, сообщать об этом, сохраняя видимую версию. Черновики и prerelease не устанавливать.
- Скачивать только по нажатию пользователя. Показывать процент загрузки, сохранять отзывчивость меню. Запросы, разбор JSON, работа с файлом и проверка APK выполняются в фоне. Работа продолжается при переходе в другой раздел в пределах процесса; установщик открывается только пока открыт раздел «О программе». После уничтожения процесса пользователь начинает загрузку заново.
- Использовать отдельный HTTPS-клиент без токена GitHub, cookie Seasonvar и обхода DPI сайта. Не отключать TLS. Начальный адрес APK должен точно соответствовать репозиторию, тегу и имени файла. Перенаправления разрешены только на github.com, release-assets.githubusercontent.com и objects.githubusercontent.com; их число и размер ответа ограничены. Подписанные адреса не логировать.
- Файл хранить во внутреннем кэше `updates`, сначала как `update.part`. До передачи установщику проверить размер, SHA-256, пакет приложения, совпадение версии с релизом, увеличение versionCode и одинаковый набор сертификатов установленного и нового APK. Незавершённый файл удалять. Несовпадение подписи — понятная ошибка, без удаления приложения или предложения стереть данные. Смена ключа с ротацией сертификата требует отдельного решения.
- Готовый APK передавать стандартному установщику Android через FileProvider с временным правом чтения только каталога обновлений. Для установки объявить REQUEST_INSTALL_PACKAGES; при необходимости открыть системное разрешение установки именно для Seasonvar TV. После разрешения продолжить установку, после отказа оставить возможность повторить действие.
- Подтверждение обновления выполняет пользователь в Android. После отмены готовый файл можно передать повторно без скачивания, пока открыт тот же раздел. Приложение не запрашивает удаление старой версии, не очищает настройки и не обходит проверку подписи Android.
- Фокус получают только кнопки. Стрелки вверх/вниз переключают ссылку GitHub и установку, влево и «Назад» возвращают в меню. Текст версии, сообщения и индикатор не получают фокус. Новые цвета и размеры не дублировать вне общей темы.

Описания установленного и более новых выпусков, их кэш и прокрутка экрана дополняются [ADR-0100](0100-about-release-notes.md).

## Альтернативы

- Отдельная кнопка проверки: пользователь выбрал автоматическую проверку при входе.
- Проверять при каждом запуске и скачивать автоматически: лишняя сеть и действие без запроса пользователя.
- Открывать страницу GitHub для ручной загрузки: неудобно с пульта.
- Устанавливать без системного подтверждения или удалять несовместимую версию: нарушает контроль пользователя и сохранение данных.

## Проверка

Автономные тесты проверяют числовое сравнение версий, отсутствие и неподходящий APK, ошибки GitHub, границы ответов, HTTPS-перенаправления, целостность, совместимость пакета и сертификатов, отсутствие установки без нажатия и повторную попытку после отказа.

`make update-probe DEVICE=emulator-5554` читает настоящий релиз и проверяет скачанный APK без установки и без аккаунта Seasonvar. `make update-preview DEVICE=emulator-5554` создаёт локальный APK с увеличенной тестовой версией, сохраняя версию проекта, и показывает реальный экран с локальной выдачей. Этот сценарий и его подмены существуют только в androidTest. Подтверждение в Android обновляет тестовую сборку; `make update-restore BUILD_TYPE=profile DEVICE=emulator-5554` возвращает обычную тестовую версию через разрешённое для отладки понижение с сохранением данных. На приставку эти команды не допускаются. Теги и релизы не создаются.

2026-11-04: в эмуляторе проверены новая версия, переход к кнопке D-pad, процент загрузки, запрос разрешения Android и стандартный установщик. Пользователь подтвердил установку тестовой 0.3.2 поверх 0.3.1; дата первой установки не изменилась, вход восстановился. Настоящий экран автоматически получил последний релиз 0.3.1 и не предложил понижение установленной 0.3.2.

Итоговые проверки после переноса на актуальный main: `make check` — 318 JVM-тестов, 39 Python-тестов, Android Lint без ошибок; profile-сборка с R8 собрана и запущена. Настоящий GitHub APK скачан и проверен через `make update-probe`. Сценарий несовпадения подписи оставил установщик закрытым. После возврата обычной profile 0.3.1 сохранены сессия и дата первой установки; в «О программе» показаны одинаковые версии и «Обновлений нет», Esc возвращает фокус в меню. Приставка не использовалась.

## Последствия

Обновления доступны без браузера, файлового менеджера и разрешения на общее хранилище. Доступность GitHub и ограничения его API влияют на проверку; повторить её можно новым входом в раздел. Эмулятор с тестовой подписью не может обновляться публичным APK с другой подписью; существующие данные ради этого не удаляются. Проверка обновлений не выпускает новую версию — ADR-0053 сохраняет силу.
