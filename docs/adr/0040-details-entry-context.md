# ADR-0040: Выбор сезона, серии и озвучки при открытии карточки

Дата: 2026-11-03. Статус: принято; откат озвучки уточнён в [ADR-0042](0042-standard-translation-fallback.md).

Уточняет начальный выбор из [ADR-0031](0031-native-playback.md) и переход из истории по [ADR-0039](0039-account-viewing-history.md).

## Контекст

При открытии записи истории правильный сезон уже загружается по точной ссылке, но известная серия остаётся только подписью: карточка выбирает локальное продолжение либо первую серию. Пользователь установил общее правило для всех экранов: известные сезон, серия и озвучка должны выбираться при переходе в карточку.

## Решение

Правило действует для «Сегодня», публичных подборок, поиска, всех личных списков, истории и будущих экранов. Каждый источник передаёт все известные параметры выбранной записи в общую логику открытия карточки.

| Что известно при переходе | Что выбирается в карточке |
| --- | --- |
| Сезон | Именно этот сезон по его ID и точному пути страницы |
| Серия | Именно эта серия внутри выбранного сезона и озвучки |
| Озвучка | Именно эта озвучка выбранного сезона |

Параметры применяются совместно. После загрузки нужного сезона сначала определяется озвучка, затем серия из её списка, поскольку доступные эпизоды зависят от озвучки. Известная серия не заменяется первой серией сезона или эпизодом из другой отметки просмотра.

Предпочитаем точные ID. Если источник даёт только название озвучки или номер/название серии, сопоставляем их с данными загруженного сезона однозначно. Номер серии не является индексом элемента списка, а ID сезона не является ID сериала, перевода или эпизода. Контекст передаётся отдельными полями, а не извлекается интерфейсом из объединённой подписи миниатюры.

## Приоритет выбора

1. Известные параметры исходной записи имеют приоритет при открытии карточки.
2. Совместимая локальная отметка продолжения заполняет только параметры, которых источник не задал.
3. Остальные неизвестные параметры берутся из штатного выбора сайта: озвучка по умолчанию, затем первая доступная серия.

Если серия известна, а озвучка не задана, выбираем совместимую озвучку с этой серией: из локальной отметки, затем озвучку по умолчанию, затем первую подходящую в порядке сайта. Если озвучка задана явно, используем её, проверяя наличие нужной серии в её списке.

Локальное время продолжения применяется только при совпадении сезона, озвучки и серии. Например, переход из истории на 7-ю серию не переключается на локально отмеченную 10-ю. Если на той же 7-й серии и в той же озвучке есть валидная локальная позиция, сохраняется действие «Продолжить» по ADR-0031.

Для недоступной или неоднозначной серии показываем проблему и оставляем ручной выбор. Известную, но отсутствующую серию нельзя молча подменить первой. Обработка отсутствующей или неоднозначной озвучки пересмотрена в ADR-0042: автоматически выбирается стандартная с сохранением известной серии.

Контекст применяется при конкретном открытии карточки. Последующий ручной выбор пользователя сохраняется; фоновая загрузка, повтор запроса и позднее чтение локальной отметки не должны откатывать его. Возврат из плеера сохраняет выбранные параметры и фокус.

## Примеры и проверка реализации

- Запись истории с сезоном 2, серией 7 и озвучкой A открывает сезон 2 с выбранными A и серией 7, даже при локальной отметке на другой серии.
- Запись обновлений с известной серией и озвучкой выбирает их по тому же правилу.
- Результат поиска, в котором известен только сезон, открывает его; локальное продолжение используется при совместимости с этим сезоном.
- Две записи одного сезона с разными сериями или озвучками открываются со своими параметрами; повторное использование модели карточки не переносит старый выбор.
- Проверить отсутствующие параметры, именованные серии, различающиеся списки озвучек, недоступную серию, конфликт локальной отметки, повтор запроса и поздний ответ после другого перехода. Автоматические проверки используют синтетические данные.

## Альтернативы и последствия

Всегда открывать первую серию — теряется смысл перехода из истории и обновлений. Всегда отдавать приоритет локальной отметке — выбранная пользователем запись может вести к другому эпизоду. Отдельные правила по разделам создают различия в одинаковых переходах.

Нужен единый механизм выбора, которому парсеры и экраны передают известные параметры. Отображение информации на миниатюре само по себе не означает, что начальный выбор реализован. Контекст передаётся в `SeriesEntry.initialSelection`, общий выбор выполняет `EntrySelectionResolver`. Центральная модель записи описана в [ADR-0041](0041-shared-catalog-entry.md).

Проверка реализации: общий `make check` — 195 JVM-тестов, 17 Python-тестов и Android Lint; `make build-profile` с R8. В эмуляторе проверены серия из истории, стандартная озвучка при несовпадении названия, фокус выбранной серии и возврат к исходной записи.
