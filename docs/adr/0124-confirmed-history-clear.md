# ADR-0124: Очистка истории с подтверждением

Дата: 2026-11-09

Статус: Принято

Дополняет [ADR-0039](0039-account-viewing-history.md), [ADR-0117](0117-playback-history-sync.md) и [ADR-0123](0123-history-without-search.md).

## Контекст

Пользователь запросил очистку истории через корзину слева от выбора вида в правом верхнем углу, обязательно с подтверждением. История принадлежит аккаунту Seasonvar; «Продолжить» зависит от неё. Открытие диалога и отмена не должны менять данные.

## Решение

- Только в «Истории просмотров» добавить кнопку с корзиной непосредственно перед переключателем вида. Место кнопки сохранять при загрузке и пустом списке; действие недоступно до загрузки непустой истории и во время очистки.
- Диалог объясняет удаление всей истории на сайте и в приложении и невозможность отмены. Слева «Отмена» с начальным фокусом, справа «Очистить историю». «Назад» закрывает диалог. Начальное удержание OK не должно подтверждать удаление.
- Запрос отправлять только после отдельного подтверждения. Повторное нажатие во время операции не создаёт второй запрос. Во время выполнения «Закрыть» скрывает диалог, сохраняя уже подтверждённую операцию. После закрытия возвращать фокус корзине, если раздел ещё открыт.
- Перед записью проверять авторизацию и узнаваемую страницу истории. Использовать штатный POST `/ajax.php` с `dellAllHistory=true`, затем проверять пустую историю авторизованным GET. HTTP 200 без пустого результата не считать успешной очисткой. Правило ADR-0116 о достаточности HTTP 200 относится к записи запуска серии, а не к удалению всей истории.
- Сериализовать очистку с записями аккаунта. Сбросить старые ожидающие записи истории отдельной версией очереди, сохраняя версию аккаунта и постоянные отметки. Новые запуски после очистки снова могут попадать в историю. Подтверждение и результат привязать к версии сессии; смена аккаунта отменяет старую операцию.
- Отменить старые загрузки страниц истории. После успеха очистить её список и пагинацию, состояние и кэш «Продолжить», запросить обновление каналов устройства. После попытки POST обновлять ревизию истории даже при ошибке: сервер мог обработать запрос до обрыва соединения. Другие списки и постоянные отметки не сбрасывать.
- Ошибку показывать коротким стандартным уведомлением по ADR-0113. Слоты диалога сохраняют размеры при загрузке и ошибке по ADR-0114. Автоматически повторять разрушительный запрос нельзя; повтор допускается по явному нажатию пользователя.

## Альтернативы и последствия

Локальная очистка не меняла бы историю сайта и при следующем обновлении вернула бы записи. Удаление без подтверждения повышает риск случайного нажатия с пульта. Поэтому выбран штатный серверный контракт с явным подтверждением и последующей проверкой.

Контракт POST установлен из обработчика оригинальной страницы. Удаление настоящей истории аккаунта при разработке не выполняется: запрос, проверка результата и ошибки покрываются синтетическими тестами; диалог проверяется в эмуляторе на изолированном состоянии. Проверка живого необратимого удаления остаётся за владельцем аккаунта.
