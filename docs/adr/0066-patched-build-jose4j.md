# ADR-0066: Исправленная jose4j в инструментарии сборки

Дата: 2026-11-04

Статус: Принято

## Контекст

Предупреждение Dependabot №16 обнаружило `org.bitbucket.b_c:jose4j:0.9.5`, транзитивную зависимость AGP 9.5.0. CVE-2024-29371 позволяет вызвать отказ в обслуживании при распаковке JWE с чрезмерной степенью сжатия. Исправленный выпуск — 0.9.6. Dependabot не может автоматически обновить зависимость, отсутствующую среди прямых объявлений проекта.

Полный граф на 2026-11-04 показывает jose4j только в корневом `classpath` инструментов сборки. В конфигурациях приложения и Android Lint библиотека не обнаружена.

## Решение

Задать `buildJose4jVersion=0.9.6` в `gradle.properties` и ограничение `org.bitbucket.b_c:jose4j` в корневом `buildscript.dependencies.constraints`. Закрепить POM и JAR официального Maven Central в `toolchain.lock.json` с контрольными суммами. Ограничение относится к инструментам сборки и не добавляет jose4j в APK.

Добавить jose4j в `make check-resolved-dependencies`, уже входящий в `make check`. Регрессионная проверка должна отклонять 0.9.5 в корневом classpath и в другой конфигурации при уже исправленной корневой версии. При проверке исправления сначала подтвердить отказ на реальном старом графе, затем успешную проверку заново разрешённого графа с 0.9.6.

Выполнить `make check`, `make ci-lint`, `make codeql-build` и `make build BUILD_TYPE=release`. Перед слиянием дождаться всех обязательных проверок GitHub. После слияния проверить публикацию графа `main` с исправленной версией; до чтения актуального состояния предупреждения не объявлять alert закрытым.

## Альтернативы

- Закрыть предупреждение вручную. Оставляет уязвимую библиотеку в инструментарии.
- Изменить обработку JWE в приложении. Приложение не управляет вызовами jose4j внутри AGP.
- Обновить весь AGP ради транзитивной зависимости. Расширяет изменение при наличии исправленного совместимого выпуска jose4j.

## Последствия

Проверка полного графа не позволит незаметно вернуть старую jose4j при обновлении сборки. Когда AGP сам начнёт выбирать исправленную версию, явное ограничение можно удалить после проверки графа. Проверка минимальных версий дополняет предупреждения GitHub и не заменяет их.
