# ADR-0071: Тестовые сборки в эмуляторе и публичные релизы на приставке

Дата: 2026-11-04

Статус: Принято

Уточняет применение подписи из ADR-0048 и локальных команд ADR-0005.

## Контекст

У тестовой сборки и публичного релиза разные сертификаты. Android не позволяет обновлять приложение поверх другой подписи. Пользователь выбрал официальные релизы для своей приставки и отдельно потребовал тестовые сборки в эмуляторе, чтобы сохранять его настройки.

## Решение

- В эмулятор устанавливать тестовую debug/profile-сборку с прежней тестовой подписью. Для обычной проверки оптимизированного приложения использовать make run-profile DEVICE=emulator-5554.
- На пользовательскую приставку устанавливать официальный подписанный APK из GitHub Releases, проверяя его контрольную сумму и подпись. Постоянный ключ релизов сохраняется между выпусками.
- Обновлять через adb install -r, доступный в make install-apk. Смена версии не является основанием удалять настройки, сессию или локальные позиции просмотра.
- При несовпадении подписей сначала установить происхождение сборок по публичным сертификатам APK. Не считать эту ошибку доказательством потери ключа.
- Удалять приложение с данными только по отдельному явному разрешению пользователя после объяснения потерь.
- Профилирование на приставке по ADR-0025 остаётся отдельной явно запрошенной проверкой; способ установки должен учитывать существующую подпись и сохранение данных.

## Альтернативы

- Ставить публичный APK и в эмулятор: конфликтует с существующей тестовой подписью.
- Чередовать тестовые и публичные сборки на пользовательской приставке: создаёт конфликт подписи вместо обычного обновления.
- Удалять приложение при каждом обновлении: противоречит требованию сохранять данные.

## Последствия

Сборки выбираются по назначению устройства, а не только по номеру версии. Обычные обновления в каждом окружении сохраняют данные. Ключи не пересоздаются ради установки и не попадают в репозиторий. Исключение для явно запрошенной локальной dev-сборки с тем же постоянным ключом описано в [ADR-0086](0086-local-dev-release-signature.md).
