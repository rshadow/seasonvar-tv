# ADR-0086: Локальная dev-сборка с релизной подписью

Дата: 2026-11-05

Статус: Принято

## Контекст

ADR-0071 выбирает публичные релизы для пользовательской приставки, чтобы обновления сохраняли данные. Для проверки нового интерфейса пользователь явно попросил локальную сборку с постоянной релизной подписью и суффиксом dev для отличия от опубликованной версии.

## Решение

- По явному запросу разрешена установка локальной release-сборки на приставку с тем же постоянным ключом из `secrets.env`, что используется публичными релизами. Это исключение для запрошенной проверки; обычные обновления по-прежнему берутся из GitHub Releases.
- Команда `make release-dev` берёт короткий хеш текущего Git-коммита и передаёт суффикс `-dev<хеш>` через необязательное свойство Gradle `versionNameSuffix`. Например, версия имеет вид `0.3.1-devabcdef0`. Для точного соответствия исходников коммиту перед сборкой сохранить изменения коммитом. В экспортированной рабочей копии хеш можно явно передать через `DEV_COMMIT`. Обычный `make release` не добавляет суффикс; CI не меняет номер публичной версии автоматически.
- Суффикс влияет на `versionName` release-сборки и наследующих его типов. `applicationId`, `versionCode`, ключ и схемы подписи сохраняются. Отдельное приложение для dev не создаётся.
- Перед установкой проверить подписи собранного APK и уже установленного на приставке приложения; использовать `make install-apk APK=... DEVICE=...` с обновлением `adb install -r`. При несовпадении подписи остановиться, не удалять приложение и данные.
- Если на устройстве уже более новый `versionCode`, не обходить защиту от понижения версии; подготовить совместимый номер отдельно. Сам текстовый суффикс не меняет порядок установки Android.
- Локальная сборка и установка не создают тег или GitHub Release. Публикация по-прежнему требует явной команды пользователя.

## Альтернативы

- Debug/profile-подпись конфликтует с публичной установкой и не подходит для этой проверки.
- Смена идентификатора приложения создаёт отдельную установку с другими данными.
- Сборка без суффикса плохо отличается от опубликованной версии.

## Последствия

Пользователь узнаёт локальную сборку в разделе «О программе», сохраняя настройки, сессию и просмотр. Сборка имеет доступ к тем же данным приложения и требует того же обращения с релизным ключом, что публичный выпуск.

Уточняет [ADR-0071](0071-emulator-and-tv-builds.md) для явно запрошенных локальных проверок. Источник ключа остаётся по [ADR-0049](0049-project-local-secrets.md).
