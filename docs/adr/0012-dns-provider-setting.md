# ADR-0012: Независимый выбор DNS-провайдера

Дата: 2026-11-01

Статус: Принято

## Контекст

Выбор DNS был связан с галочкой обхода блокировок. Пользователь поручил выделить его в отдельную настройку с вариантами «Системный» и «Quad9 DoH», предусмотрев расширение списка.

## Решение

- Добавить «Настройки → Сеть → DNS»: выбор одного провайдера из списка с радиокнопками, доступный с пульта и мыши.
- Предоставить «Системный» (`Dns.SYSTEM`) и «Quad9 DoH». По умолчанию использовать Quad9 DoH, сохраняя прежний основной режим доступа.
- Хранить выбор независимо от `dpi_bypass`: SharedPreferences `network`, ключ `dns_provider`, стабильные строковые ID `system` и `quad9_doh`. Не сохранять порядковый номер элемента. При отсутствии или неизвестном значении выбирать Quad9 DoH.
- Перечислять провайдеров в `DnsProvider`. UI строит список по его значениям; подключение нового провайдера требует его ID, названия и реализации резолвера.
- Для Quad9 использовать `https://dns.quad9.net/dns-query` с bootstrap-адресом `9.9.9.9`, проверкой TLS и IPv4-ответами. Bootstrap-запрос идёт штатным HTTPS отдельно от транспорта сайта.
- Разрешить все четыре сочетания DNS и галочки обхода из [ADR-0011](0011-network-bypass-setting.md). Отключение обхода не меняет DNS; выбор DNS не меняет галочку.
- Применять выбранный резолвер в общей Call.Factory для HTML и Coil. Для каждой комбинации переиспользовать клиент с соответствующими DNS и TLS-транспортом; соединение другого режима не должно подменять выбранную конфигурацию.
- После изменения обновлять «Сегодня» и выбранное описание. Уже выполняющиеся запросы могут завершиться с прежней конфигурацией; сохранённые данные не удалять.

## Альтернативы

- Привязка Quad9 к обходу не позволяет отдельно проверить влияние DNS и TLS-алгоритма.
- Свободный ввод URL вместо списка требует настройки протокола и валидации, которых пока не запрашивали.
- Изменение системного DNS затронуло бы остальные приложения устройства.

## Последствия и ограничения

Провайдеры можно добавлять без изменения формата сохранённой настройки. Системный режим использует резолвер Android, а не закреплённый в приложении адрес. Доступность сайта зависит от выбранной сети и сочетания настроек; автоматической подмены провайдера при ошибке нет.

Независимость четырёх сочетаний, повторное использование клиентов и чтение стабильных ID проверяются автономными JVM-тестами. Проверка TLS остаётся включённой в обоих транспортных режимах. В эмуляторе Android TV API 34 проверены все четыре сочетания в UI, переключение с пульта и сохранение пары «обход выключен + системный DNS» после остановки процесса.

Выбор DNS вынесен из ADR-0011 по просьбе пользователя; алгоритм обхода описан только в том ADR.

Расположение параметров уточнено в [ADR-0013](0013-navigation-without-back-buttons.md): «Сеть» — подзаголовок общего экрана «Настройки», отдельного перехода в подраздел нет.

На общем экране настроек выбор DNS оформляется строкой в стиле галочки обхода: название «DNS-сервер», пояснение назначения и отдельное текущее значение. Вся строка получает один фокус; OK или клик открывает список провайдеров.

Общий формат названия, пояснения и элемента управления справа закреплён в [ADR-0015](0015-settings-item-format.md).
