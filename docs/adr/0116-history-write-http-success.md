# ADR-0116: Успех отправки истории по HTTP 200

Дата: 2026-11-08

Статус: Принято

## Контекст

Проверенный запрос `plStat.php` возвращает HTTP 200 с пустым телом. При исследовании создание записи подтвердили чтением истории. Для штатной отправки пользователь выбрал HTTP 200 как достаточный критерий успеха, без дополнительных запросов.

## Решение

- Считать отправку события истории успешной при HTTP 200. Пустое тело допустимо, JSON-подтверждение не требуется.
- После HTTP 200 завершать отправку события без контрольного GET истории. Не перечитывать списки для подтверждения записи.
- Помечать зависимые списки устаревшими и обновлять их при обычном открытии или возврате по [ADR-0117](0117-playback-history-sync.md). Клиент отмечает успех отправки; состав и порядок истории получает с сайта.
- Сетевая ошибка и ответ с другим кодом не считаются успешной отправкой. Повторное чтение не входит и в обязательный алгоритм повтора POST.

Правило относится к `plStat.php`. Проверка записи постоянных отметок через `jsonMark.php` сохраняет свой действующий контракт.

## Альтернативы и последствия

Контрольный GET подтверждает видимую запись, но добавляет запрос и усложняет обработку повторов, которые сервер может объединять. Его использовали при исследовании протокола; в рабочем сценарии выбран достаточный HTTP-результат. Отправка остаётся независимой от последующей загрузки списков.

Контракт и ограничения проверки — в [документации API](../api/web-api.md#запись-просмотра-plstatphp).
