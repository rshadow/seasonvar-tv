# ADR-0045: Раздел при запуске приложения

Дата: 2026-11-03. Статус: принято.

## Контекст

Пользователь хочет выбирать пункт меню, на котором начинается работа после запуска приложения. Формулировка настройки должна объяснять результат без терминов о фокусе и навигации.

## Решение

В настройках перед группой «Сеть» добавить группу «Приложение» и пункт:

```text
При запуске                                      Сегодня
Выберите раздел, который будет открываться первым.
```

При нажатии открывается «Что открывать при запуске» со списком пунктов главного меню. Выбранный вариант отмечается справа. Можно выбрать ровно один раздел. Длинный список прокручивается, заголовок диалога остаётся виден. Оформление строки и диалога следует [ADR-0015](0015-settings-item-format.md); заголовки групп не получают фокус.

По умолчанию выбран «Сегодня». Варианты идут в порядке меню: публичные подборки, личные списки после входа, затем «Настройки» и «О программе». Кнопки поиска и аккаунта над меню не входят в этот список.

Выбор сохраняется локально в настройках интерфейса `InterfaceSettings` и применяется при следующем запуске: открывается выбранный раздел, фокус остаётся на его пункте меню. Изменение настройки не уводит пользователя с текущего экрана. Возврат из плеера или сворачивание приложения не запускают выбор заново. При восстановлении уже открытого окна сохраняется его раздел.

Для личного списка сначала дожидаемся проверки сохранённого входа. Если аккаунт недоступен, открываем «Сегодня», не стирая выбранный личный список. Публичные и системные разделы не ждут проверки аккаунта. Появление личной группы после проверки входа не меняет выбранный пункт меню. Если пользователь начал пользоваться меню до завершения проверки, отложенный стартовый переход отменяется. Неизвестное сохранённое значение заменяется «Сегодня».

Настройка не меняет сетевые параметры. Все пункты настроек остаются доступны прокруткой и с пульта; вход из меню переводит управление на первый пункт «При запуске».

## Альтернативы и последствия

Автоматически запоминать последний экран — другое поведение, не позволяющее закрепить удобный первый раздел. Несколько независимых галочек допускают противоречивый выбор, поэтому используется список с одной отметкой.

Новый раздел меню при необходимости добавляется в общий набор `Section` с постоянным идентификатором для сохранения. Личные списки остаются доступны только после подтверждённого входа; отсутствие аккаунта не превращается в пустой личный список.

## Проверка

`make check` прошёл: 216 JVM-тестов, 17 Python-тестов и Android Lint. Автономные тесты проверяют сохранённые идентификаторы, неизвестное значение, доступность личных вариантов и выбор после проверки аккаунта.

В эмуляторе Android TV API 34 проверены отмена, сохранение после перезапуска, старт с публичного, личного и системного раздела, видимость выбранного пункта после появления личной группы, длинный диалог и переходы к сетевым параметрам. Сброс позиций скрытых личных списков не ждёт их появления на экране. После проверки восстановлен выбор «Сегодня».
