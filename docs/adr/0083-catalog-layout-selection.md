# ADR-0083: Лента с описанием и адаптивная сетка каталога

Дата: 2026-11-05

Статус: Принято

## Контекст

[ADR-0006](0006-tv-navigation-and-content-layout.md) задаёт меню слева и описание над горизонтальной лентой справа; сетка была отложена. Пользователь подтвердил второй вид с автоматической подстройкой размера карточек под доступную область и уточнил, что каждый список должен помнить собственный выбор.

## Решение

- Меню слева постоянно видно. По умолчанию используется нынешняя лента с описанием.
- Перед обновлением в шапке каталога находится квадратная кнопка переключения с общим стилем иконок. Одно нажатие меняет вид. Иконка и доступное название обозначают следующий вид: «Показать сеткой» / «Показать лентой с описанием».
- Вид выбирается и запоминается отдельно для каждой публичной подборки, каждого личного списка, истории просмотров и результатов поиска. Выбор сохраняется локально в `interface` по ключам `catalog_layout.<идентификатор раздела>`; название раздела на экране на ключ не влияет. Изменение одного списка не меняет другие. Для ещё не настроенного списка используется лента с описанием. История поисковых запросов, настройки и страница сериала имеют собственную компоновку.
- Сетка занимает всю область под шапкой и прокручивается вертикально. Описание доступно при открытии сериала; перемещение фокуса в сетке не запускает загрузку скрытого описания.
- Изначально выбран `GridCells.Adaptive`; общий расчёт размеров ленты и сетки уточнён в [ADR-0084](0084-shared-catalog-card-metrics.md). Сетка использует `GridCells.FixedSize` с рассчитанной шириной. Минимальная ширина задана в `themes.xml` (`seasonvar_catalog_min_card_width`) и доступна через `SeasonvarTheme`; остальные размеры и палитра также берутся из темы.
- Постер сохраняет соотношение ширины к высоте из темы. Под ним две строки названия и одна строка доступной подписи. Все карточки одинакового размера, включая последний неполный ряд. По высоте карточки не растягиваются ради целого числа рядов.
- Названия, сезон/серия, метки, порядок выдачи и действия совпадают с лентой. Смена вида не требует повторного запроса каталога. Общая пагинация использует положение текущего представления.

### Схема

```text
Лента                                 Сетка
┌────────┬───────────────────────┐    ┌────────┬───────────────────────┐
│ Меню   │ Раздел       [▦] [↻]  │    │ Меню   │ Раздел       [▤] [↻]  │
│        │ Название     Постер   │    │        │ [постер] [постер] …   │
│        │ Сведения и описание   │    │        │ Название Название     │
│        │                       │    │        │ Подпись  Подпись      │
│        │ [постер] [постер] →   │    │        │ [постер] [постер] … ↓ │
└────────┴───────────────────────┘    └────────┴───────────────────────┘
```

### Фокус и состояние

- Выбранная карточка общая для видов; при переключении она остаётся видимой. Фокус остаётся на переключателе. Вниз с кнопок шапки возвращает к выбранной карточке.
- Прокрутка отдельная для каждого раздела и вида. Возврат из сериала восстанавливает выбранную карточку. Переключение раздела не сбрасывает остальные списки.
- В сетке стрелки перемещают фокус между соседними карточками. Влево из первого столбца возвращает в меню; вверх из первого ряда ведёт к переключателю. Справа от края ряда и снизу от последнего ряда переход блокируется: фокус не уходит на обновление. Навигация и прокрутка внутри сетки выполняются Compose.
- OK открывает сериал; длительный OK показывает существующие действия аккаунта. Esc/«Назад» работают по ADR-0014.
- Стабильные ключи, ленивое создание элементов, загрузка постеров под размер и постепенное заполнение по ADR-0025 сохраняются.

## Альтернативы

- Фиксированные четыре столбца хуже используют разную ширину и не соответствуют подтверждённой адаптации.
- Переключение только в настройках требует ухода из каталога и дополнительных нажатий.
- Описание над сеткой оставляет меньше места постерам и дублирует страницу сериала.
- Общий вид для всех разделов проще хранить, но пользователь предпочёл независимый выбор: например, ленту для обновлений и сетку для больших личных списков.

## Последствия

Доступны подробный просмотр и плотный обзор каталога. В сетке для описания нужно открыть сериал. Дополнительно хранятся небольшие состояния прокрутки, а данные, парсеры и карточки остаются общими.

Уточняет ADR-0006. Основание: пользователь подтвердил два вида, адаптивный размер карточек и реализацию.
