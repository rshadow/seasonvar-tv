# ADR-0011: Настраиваемый обход блокировок в Android-клиенте

Дата: 2026-11-01

Статус: Принято

## Контекст

Прямое соединение с Seasonvar в проверенной сети блокируется. Загрузчик из [ADR-0007](0007-local-site-access.md) получает страницы с помощью TCP/TLS-стратегии. Пользователь поручил применить этот же алгоритм в приложении и включить его по умолчанию.

## Решение

- Добавить «Настройки → Сеть → Обход блокировок». Галочка включена при первом запуске, управляется пультом и сохраняется в приватных SharedPreferences приложения.
- Галочка управляет только TCP/TLS-алгоритмом. DNS выбирается независимо согласно [ADR-0012](0012-dns-provider-setting.md); переключение обхода его не меняет.
- Реализовать TCP/TLS-часть прежней стратегии `-o1 -a1 -r-5+se` на Kotlin: разделение первой TLS-записи за пять байт до конца SNI, отдельная отправка первого байта, срочный TCP-байт `a`, пауза 10 мс и оставшаяся часть. UDP-параметр `-a1` к HTTPS не относится.
- Шифрование, TLS-handshake и проверку сертификата выполнять платформенным SSLEngine с системным trust manager. Сохранять проверку имени HTTPS и дополнительную проверку OkHttp. Самописный код меняет границы и отправку ClientHello, не реализует криптографию.
- Использовать HTTP/1.1 для этого транспорта. Прямой режим оставлять на штатном OkHttp/TLS с выбранным пользователем DNS.
- Выбирать транспорт в общей Call.Factory для новых запросов HTML и Coil. После переключения обновлять «Сегодня» и повторять загрузку выбранного описания. Уже выполняющиеся запросы могут завершиться с прежним режимом.
- Размещать хранение настройки и TLS-адаптер в `data/network`. Цвета и размеры нового экрана брать из общей темы по ADR-0008.

## Альтернативы

- Python-сервер на компьютере разработчика потребовал бы внешнего процесса для работы приложения.
- VPN или глобальный прокси изменили бы доступ других приложений.
- Отключение проверки сертификата не позволяет подтвердить подлинность сайта.

## Последствия и ограничения

Нужны отдельные тесты границ SNI и сохранности TLS-содержимого, а также живая проверка Android-транспорта. 2026-11-01 на Android TV API 34 обход вместе с Quad9 DoH получил главную, описание и постеры; прямой режим с системным DNS отклонил недоверенный сертификат блокировки. Проверены переключение и сохранение галочки после остановки процесса.

Это целевой алгоритм для запросов клиента, а не полная реализация ByeDPI. Работа зависит от сети и сервера; Ugoos и будущие видеопотоки требуют отдельной проверки. Авторизация этим изменением не проверялась.

Эта запись принимает ранее отложенное в ADR-0007 решение об Android-транспорте; самостоятельный Python-загрузчик остаётся инструментом исследования.

Выбор DNS выделен в ADR-0012 по просьбе пользователя. Этот ADR описывает галочку и TCP/TLS-транспорт.

Расположение параметров уточнено в [ADR-0013](0013-navigation-without-back-buttons.md): «Сеть» — подзаголовок общего экрана «Настройки», отдельного перехода в подраздел нет.
