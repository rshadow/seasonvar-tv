# ADR-0002: Нативный клиент на Kotlin, Compose for TV и Media3

Дата: 2026-11-01

Статус: Принято

## Контекст

Разрабатываем приложение для Android TV и Android-приставки Ugoos X5M с Android 14. Приоритеты — отзывчивый интерфейс, предсказуемое управление пультом и удобное воспроизведение. Общая кодовая база с другими платформами сейчас не требуется.

## Решение

Использовать нативный Android-стек:

| Часть | Выбор |
| --- | --- |
| Язык приложения | Kotlin |
| Интерфейс | Jetpack Compose с компонентами Compose for TV |
| Каталоги и списки | Ленивые раскладки Compose Foundation с поддержкой навигации по фокусу |
| Видеоплеер | Jetpack Media3, реализация ExoPlayer |

Compose for TV предназначен для телевизионных интерфейсов; стандартные ленивые раскладки Compose поддерживают прокрутку при перемещении фокуса. Media3 предоставляет операции воспроизведения, паузы и перемотки и расширяемый плеер для медиапотоков. См. [документацию Compose for TV](https://developer.android.com/training/tv/playback/compose), [списки для ТВ](https://developer.android.com/training/tv/playback/compose/lists) и [Media3 ExoPlayer](https://developer.android.com/media/media3/exoplayer).

Код приложения, адаптер Seasonvar и интерфейс разрабатываем самостоятельно, используя эти библиотеки. Протокол сайта и парсеры отделяем от UI и плеера.

Совместимые версии Kotlin, Android SDK и библиотек выбираем при создании сборки по официальным требованиям и фиксируем в проекте. Этот ADR не устанавливает конкретные версии или дополнительные библиотеки для HTTP, изображений и хранения данных.

## Альтернативы

- **React Native / TypeScript.** Рабочий вариант для общей кодовой базы нескольких платформ. Для текущего Android-приложения дополнительная интеграция ТВ-поддержки и плеера не даёт решающего преимущества.
- **HTML/JavaScript в WebView.** Подходит для прототипа веб-интерфейса, но добавляет задачи по управлению фокусом, жизненному циклу браузера и веб-плееру.

## Последствия и ограничения

Нативный стек даёт прямую интеграцию с Android, но сам по себе не гарантирует быстроту. Требования к производительности определены в [ADR-0003](0003-performance-principles.md).

Для Media3 нужна актуальная воспроизводимая ссылка на поток с корректной авторизацией. Поиск и список серий пока не подтверждают наличие такой ссылки. Первым сквозным прототипом проверяем цепочку «вход → сезон → озвучка → серия → воспроизведение → сохранение прогресса» на Ugoos.

Выбор нативного плеера не означает, что контракт получения видео уже установлен. Если потребуется другой способ воспроизведения, пересмотр оформляем новым ADR.

Основание: пользователь принял предложенный стек Kotlin + Compose for TV + Media3 и поручил записать решение.
