# ADR-0117: Запись запуска серии в историю сайта и обновление списков

Дата: 2026-11-08

Статус: Принято

Дополняет [чтение истории](0039-account-viewing-history.md), [постоянные отметки](0056-automatic-account-playback-marks.md), [отбор «Продолжить»](0092-personal-continue-history-only.md) и [критерий HTTP 200](0116-history-write-http-success.md).

## Контекст

Нативный плеер сохранял позицию через `jsonMark.php`, но не добавлял просмотр в историю сайта. Эти механизмы независимы: история определяет недавние просмотры, а постоянная отметка — целевую серию и время продолжения. Из-за отсутствующей истории просмотренный в приложении сериал мог не попасть в «Продолжить».

Проверка оригинального `plStat.php` на одной серии подтвердила запись истории. HTTP 200 достаточно для завершения отправки; контрольное чтение пользователь исключил. Однако загруженная история хранится в памяти, а «Продолжить» использует её состав и порядок и имеет дисковый кэш. Их нужно уведомлять об успешной записи.

## Решение

### Отправка

- При разрешении видео извлекать ID сериала и сезона из свежей страницы, а ID контента `vars` и точный `id` — из выбранного листа плейлиста. Дополнительных запросов для этих данных нет. Параметры не получать из номера строки, подписи интерфейса или внутреннего ключа серии. Если метаданных не хватает, пропустить запись истории, сохранив возможность смотреть видео.
- Для вошедшего пользователя отправлять оригинальную форму `POST /plStat.php` после первого показанного кадра и начала воспроизведения. События могут прийти в любом порядке; нужны оба. Один логический запуск серии даёт одно событие. Пауза, продолжение, перемотка, буферизация, пересоздание поверхности или Activity его не повторяют. Ручная и автоматическая смена серии или сезона создают новый запуск. Повторное открытие плеера пользователем тоже считается новым запуском.
- Отправлять в фоне на уровне приложения, отдельно от очереди постоянных отметок и без задержки воспроизведения. Cookie использовать только для оригинального сайта; поле `svid1` содержит позицию имени в доступной скрипту строке cookie, а не значение cookie. Соблюдать domain/path/expiry и исключать HttpOnly при вычислении этого поля.
- Привязывать событие к версии проверенной сессии на момент открытия файла. При выходе, истечении или смене сессии отменять отправку и отбрасывать её ожидающие события. Старый плеер не пишет в новый аккаунт.
- HTTP 200, включая пустое тело, завершает отправку. Не выполнять контрольный GET, не проверять JSON и не менять вручную серверный порядок записей. Постоянные отметки сохраняют собственную проверку по ADR-0056.
- Сетевые ошибки, HTTP 429 и 5xx допускают максимум три последовательные попытки с задержками 2 и 4 секунды. Остальные ошибки завершают событие. Очередь ограничена 64 ожидающими событиями; каждое живёт не более 30 секунд с постановки, включая ожидание и запросы. При смене сессии попытки прекращаются. Очередь только в памяти, без восстановления после перезапуска и без фоновых запросов проверки результата.
- Сбой истории не останавливает видео и не меняет разметку. В отладочных сообщениях допустима только фаза операции, без cookie, тела ответа и видеоссылок.

### Кэш и отображение

- Только после успешной записи повышать отдельную ревизию истории. Она не является ревизией постоянных отметок: не обновляет новинки, «Топ», «Хочу посмотреть» и другие независимые списки.
- При возврате в приложение обрабатывать накопившуюся ревизию: помечать историю и «Продолжить» устаревшими. Во время видео запрос обновления этих экранов не требуется. Если раздел уже открыт, обновлять его при возврате; иначе ждать следующего открытия.
- Сохранять прежние карточки и существующие состояния прокрутки/фокуса во время загрузки, согласно [ADR-0114](0114-stable-async-layout.md). Если выбранная запись исчезла, применяется штатный выбор оставшейся карточки. При сетевой ошибке прежние данные остаются видимыми, а список остаётся устаревшим для следующей попытки.
- Для истории отменять старые запросы, сбрасывать ссылку следующей страницы и множество посещённых страниц. Новая загрузка начинается с первой страницы: добавленная запись могла сдвинуть все границы. Поздние ответы отменённых запросов не дополняют новую историю.
- Для «Продолжить» пересчитывать состав и порядок по актуальной истории и отметкам сайта. Дисковый кэш остаётся временным содержимым на время загрузки, затем заменяется свежим результатом. Не выдумывать локальные записи и даты.
- Домашняя лента Android TV «Продолжить» получает актуальные данные при штатной публикации после выхода из плеера, возврата в приложение или периодического задания. Публикация всегда читает сайт, а не кэш экрана. Если POST завершился позже публикации, результат появится при следующем штатном обновлении. HTTP 200 сам по себе не запускает дополнительное чтение или публикацию остальных лент.

## Альтернативы и последствия

Считать запись успешной только после GET истории — лишний запрос и противоречие ADR-0116. Полностью удалять карточки при сбросе кэша — пустой экран и скачки интерфейса. Обновлять все списки — лишние запросы к независимым данным. Подставлять новую карточку локально — предположение о серверных повторах, дате и сортировке.

Долговечная очередь удобна при офлайне, но в проверенном протоколе нет клиентской даты. Запись вчерашнего события сегодня исказила бы историю. Короткие повторы тоже могут повторить уже принятый сервером запрос при потере ответа: серверное окно объединения неизвестно, безусловная идемпотентность не заявляется. При закрытии процесса неотправленное событие может потеряться; локальная позиция и постоянная отметка работают независимо.

## Проверка

Автономные тесты проверяют извлечение метаданных выбранного листа без лишних запросов, точную форму, успех без GET и без изменения ревизии отметок, однократный запуск, ограниченные повторы, отмену и границы сессии, отложенное обновление кэша и сброс пагинации. Проверки не зависят от личного аккаунта и доступности сайта. В эмуляторе обязательны видимое видео, смена кадров, пауза, перемотка, переход серии и возврат. Живой тест записи истории выполняется отдельно на явно выбранной серии.
