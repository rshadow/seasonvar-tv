# ADR-0065: Исправленная JDOM в инструментарии сборки

Дата: 2026-11-04

Статус: Принято

## Контекст

Dependabot alert №14 обнаружил `org.jdom:jdom2:2.0.6`, транзитивную зависимость AGP 9.5.0. CVE-2021-33813 позволяет вызвать отказ в обслуживании при обработке XML с внешними сущностями. Исправленный выпуск — 2.0.6.1. Dependabot не может автоматически обновить зависимость, отсутствующую среди прямых объявлений проекта.

Полный граф на 2026-11-04 показывает JDOM только в корневом `classpath` инструментов сборки. В конфигурациях приложения и Android Lint эта библиотека не обнаружена. Зелёный Dependency review не исключает старых предупреждений: он проверяет изменения зависимостей относительно базы PR.

## Решение

Задать `buildJdomVersion=2.0.6.1` в `gradle.properties` и ограничение `org.jdom:jdom2` в корневом `buildscript.dependencies.constraints`. Закрепить POM и JAR официального Maven Central в `toolchain.lock.json` с контрольными суммами. Ограничение относится к инструментам сборки и не добавляет JDOM в зависимости APK.

Добавить JDOM в `make check-resolved-dependencies`, уже входящий в `make check`. Проверять все записи полного графа: исправленный корневой classpath не должен скрывать старую версию в другой конфигурации. Регрессионные тесты воспроизводят уязвимую версию в AGP и независимой конфигурации. При проверке исправления сначала подтвердить отказ на реальном старом графе, затем успешную проверку заново разрешённого графа с 2.0.6.1.

Выполнить `make check`, `make ci-lint`, `make codeql-build` и `make build BUILD_TYPE=release`. После слияния повторная публикация графа default branch должна подтвердить обновление. До чтения актуального состояния предупреждения не объявлять alert закрытым.

## Альтернативы

- Закрыть предупреждение вручную. Оставляет уязвимую версию в инструментарии.
- Вызывать `SAXBuilder.setExpandEntities(false)` в приложении. Наш код не создаёт используемый AGP парсер и не управляет его настройкой.
- Обновить весь AGP ради одной транзитивной зависимости. Расширяет изменение при наличии исправленного совместимого выпуска JDOM.

## Последствия

Проверка полного графа не позволит вернуть старую JDOM незаметно при будущих обновлениях сборки. Когда AGP сам начнёт выбирать исправленную версию, явное ограничение можно удалить после проверки графа. Локальные минимальные версии дополняют обновляемые предупреждения GitHub и не заменяют их.
