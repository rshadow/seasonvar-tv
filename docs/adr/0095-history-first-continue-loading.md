# ADR-0095: Загрузка «Продолжить» от истории с общей параллельностью

Дата: 2026-11-06

Статус: Принято

Пересматривает порядок загрузки из [ADR-0091](0091-smart-continue-account-marks.md), сохраняя отбор и сортировку [ADR-0092](0092-personal-continue-history-only.md).

## Контекст

Первоначальная реализация запрашивала страницы всех отмеченных сезонов аккаунта, затем искала продолжение и лишь в конце отбрасывала сериалы без истории. Ради нескольких итоговых карточек выполнялись сотни запросов. Только первая фаза была параллельной; обход следующих сезонов разных сериалов шёл последовательно.

Пользователь выбрал загрузку от истории и параллельное выполнение независимых запросов.

## Решение

- Одновременно запрашиваем `/resume` и первую страницу истории аккаунта. Общий список отметок нужен одним запросом; страницы всех его записей не загружаются.
- История определяет набор сериалов. Для каждого уникального сезона из истории читаем его страницу, получаем `serialId` и точные ссылки всех сезонов. Сопоставляем с отметками аккаунта по этим ID. История старого сезона может вести к продолжению нового; прямого пересечения ID истории и отметок недостаточно.
- В связанном сериале начинаем с самого позднего отмеченного сезона и уточняем только нужные отметки. Затем используем прежний выбор недосмотренной серии или следующей доступной, с правильной озвучкой и серверным временем. Ошибка чтения позднего сезона не подменяет его более старым.
- Независимые сериалы обрабатываются параллельно. После получения очередной страницы истории сразу запускаем чтение следующей и обработку уже полученных записей. Следующая ссылка неизвестна до ответа предыдущей страницы; номера страниц не угадываются.
- Один общий лимит — четыре одновременно выполняемых запроса. Он распространяется на отметки, историю, определение сериалов, уточнение отметок и поиск следующих сезонов. Внутри цепочки одного сериала сохраняются необходимые зависимости.
- На время одного обновления используем общий кэш выполняемых и завершённых запросов по ID сезона. Страница запрашивается один раз, даже если нужна для истории, отметки и следующего сезона. Расчёт результата одного `serialId` тоже выполняется один раз. Запоздалые и ошибочные ответы не создают повторных запросов в том же обновлении.
- Сортировка задаётся первым появлением любого сезона сериала в истории, независимо от порядка завершения запросов. Итог содержит одну карточку на сериал. Сериалы без истории и без доступного продолжения скрываются.
- Сохраняем показ прежнего кэша с фоновым обновлением, разделение аккаунтов, отмену запросов при смене сессии, обработку частичных сбоев и очистку устаревших карточек после полного успешного ответа. Кэш запросов действует только в текущем обновлении и не заменяет свежие отметки данными прошлого просмотра.
- Незавершённая или зацикленная пагинация истории считается ошибкой. Отмена обновления отменяет общие запросы и расчёты; ошибка отдельного сезона не отменяет другие сериалы.
- Оригинальные списки сайта, запись отметок и плеер не меняются. Локальные даты активности не добавляются.

## Альтернативы

- Увеличить параллельность старого обхода: сохраняет сотни лишних запросов и повышает нагрузку на сайт.
- Отфильтровать отметки только по ID сезонов в истории: потеряет новые сезоны сериала, если история содержит старый.
- Сохранять полученные отметки на длительное время: мешает подхватывать просмотр на сайте и других устройствах.

## Последствия и проверка

Число чтений: один `/resume`, страницы истории и уникальные действительно запрошенные страницы связанных сезонов. Оно больше не растёт с количеством посторонних отметок аккаунта. Большая многостраничная история по-прежнему требует чтения своих страниц; её обработка пересекается с загрузкой сезонов.

`make check` проверяет отбор на фоне 200 посторонних отметок, историю старого и отметку нового сезона, порядок ответов, параллельность обеих фаз и пагинации, общий лимит, дедупликацию и отмену.

`make smart-continue-probe DEVICE=emulator-5554` измеряет число запросов, максимальную параллельность и время без записи отметок. Восстановление авторизации перед измерением, постеры, описания карточек и возможные транспортные редиректы в эти счётчики не входят. Вывод — только количества и признаки результата. После проверки вернуть обычную тестовую сборку через `make run-profile DEVICE=emulator-5554`.

Проверка 2026-11-06 в локальном эмуляторе: 189 уникальных отметок аккаунта, одна страница истории, четыре уникальных сезона истории. Итог — три карточки без частичных ошибок; семь чтений (один `/resume`, одна история, пять страниц сезонов), пик четыре одновременно, 6,3–6,9 секунды в двух успешных замерах. Для тех же исходных данных прежний алгоритм потребовал бы не менее 191 чтения; это расчёт, а не повторный замер старой реализации. Время зависит от ответа сайта и сети.
