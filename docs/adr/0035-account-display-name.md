# ADR-0035: Имя аккаунта из видимого текста меню

Дата: 2026-11-03

Статус: Принято. Пересматривает правило имени из [ADR-0034](0034-resume-current-markup.md).

## Контекст

После реального входа в эмуляторе вместо имени появилась надпись `avatar`: это значение `alt` картинки в шапке сайта. Оно описывает изображение и не подтверждает имя пользователя. Пояснение страницы аккаунта также было привязано к одному личному списку, хотя личных разделов станет больше.

## Решение

Имя берём из видимого пункта раскрывающегося меню `[data-menur]`, не являющегося ссылкой или кнопкой. Для старой разметки допустим собственный профиль с явным именем в тексте ссылки. Служебные подписи «Профиль»/«Мой профиль» и значение `alt` аватара не используются как имя. Если имя не найдено, показываем «Аккаунт Seasonvar»; аватар продолжает загружаться независимо от имени.

Пояснение авторизованного состояния общее: «Вы вошли в Seasonvar. Личные разделы доступны в меню». Оно не перечисляет разделы и не требует правки при добавлении новых списков.

## Альтернативы и последствия

`alt` может содержать `avatar` или другое описание картинки. Дополнительный запрос страницы профиля для имени добавлял бы сетевую задержку; текущая шапка уже содержит видимое имя. Нейтральная подпись остаётся безопасным вариантом при изменении разметки.

## Проверка

Синтетическая разметка содержит видимое имя и `alt="avatar"`. Регрессии проверяют чтение имени из меню, игнорирование описания картинки и нейтральную подпись при отсутствии имени без потери аватара.

В эмуляторе на реальном аккаунте подтверждены видимое имя вместо `avatar`, общее пояснение и сохранение входа после обновления. `make check` прошёл: 138 JVM-тестов, 17 Python-тестов и Lint.
