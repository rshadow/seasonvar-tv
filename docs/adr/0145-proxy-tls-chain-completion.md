# ADR-0145: дополнение цепочки сертификата HTTPS-прокси

Статус: принято. Дата: 2026-11-11. Дополняет [ADR-0143](0143-antizapret-pac-proxy.md).

## Контекст

HTTPS-прокси из оригинального PAC отдаёт сертификат ZeroSSL с цепочкой к Sectigo Public Server Authentication Root R46. В эмуляторе Android TV API 34 проверка заканчивается `Trust anchor for certification path not found`; резервный HTTP-прокси позволяет запросу пройти и скрывает проблему при проверке только итогового HTTP 200.

## Решение

TLS-клиент прокси сначала проверяет исходную цепочку системным X509TrustManager. При ошибке он повторяет ту же системную проверку, дополнив цепочку официальным перекрёстным сертификатом R46, подписанным USERTrust RSA Certification Authority. Новый доверенный корень не добавляется. Неверная цепочка, отсутствие доверенного системного корня и несовпадение имени прокси остаются ошибками. TLS сайта внутри CONNECT использует свой прежний транспорт и закреплённые сертификаты.

Перекрёстный сертификат поставляется как публичный ресурс приложения. Его ключ сверяется с константой `TlsPinSettings.SECTIGO_ROOT_R46`; срок действия — до 2038-01-18. Источник — [официальная схема Sectigo](https://support.sectigo.com/Com_KnowledgeDetailPage?Id=kA0Uj0000004IrB), файл `http://crt.sectigo.com/SectigoPublicServerAuthenticationRootR46_USERTrust.crt`. У раздачи сертификата нет рабочего HTTPS на дату проверки; при получении проверены закреплённый SPKI и подпись по доверенному корню локальным OpenSSL. HTTP-раздача не является основанием доверять содержимому без криптографической проверки.

## Альтернативы и последствия

Добавление R46 в доверенные корни расширило бы хранилище доверия приложения. Отключение проверки сертификата неприемлемо. Ожидание обновления системных корней не помогает старым приставкам; дополнение недостающей цепочки сохраняет проверку через их существующие доверенные корни.

Проверки включают неполную цепочку, неизвестный корень, неверное имя прокси и два независимых слоя TLS. Живой сценарий отдельно сверяет успешно использованный маршрут с первым HTTPS-маршрутом PAC: одного успешного ответа через резерв недостаточно.
