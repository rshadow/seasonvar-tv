# ADR-0129: Общий кэш данных карточек и HTML выдачи

Дата: 2026-11-09

Статус: Принято, реализовано

Расширяет [ADR-0127](0127-shared-list-preparation-window.md) и [ADR-0128](0128-description-preparation-window.md): подготовленные данные карточек переиспользуются между списками. Пересматривает ограничение дискового кэша гостевым режимом из [ADR-0033](0033-account-and-resume.md); разделение публичной и приватной выдачи сохраняется.

## Контекст

Текущий движок хранит разобранные описания только в активном окне и очищает их при смене списка. После авторизации дисковый кэш HTML отключён, поэтому возвращение к списку запускает новые запросы данных карточек.

Пользователь выбрал сохранение HTML на диске, один механизм кэша публичных и личных выдач и общее хранилище нативных данных карточек в памяти. Начальный размер — 5000 сезонов. Хранение персональных данных нескольких аккаунтов отклонено: перелогин редок. Последнее уточнение пользователя: при выходе очищать только приватную часть памяти, сохраняя общую.

## Решение

### Термины и границы

- Списки и карточки — элементы приложения. Данные или выдача списка и карточки — ответы сайта. Постеры имеют отдельный общий кэш Coil.
- Полученные лёгкие записи списков остаются в памяти согласно ADR-0127. Список сохраняет порядок, собственные ключи и контекст каждой записи: серию, озвучку и дату из истории. Разные записи одного сезона не объединять и не подменять общей записью кэша. Модель `SeriesEntry` и правила открытия из ADR-0040/0041 сохраняются.

### HTML на диске

- Сохранять исходную выдачу списков и карточек как HTML. Существующая JSON-обёртка HTML-фрагментов «Лучших сериалов» остаётся допустимой; разобранные данные отдельным JSON-кэшем на диск не переносить.
- Использовать один механизм чтения, записи, сроков хранения и отмены для публичной и приватной выдачи. Адаптеры сохраняют свои запросы, парсеры и проверки авторизации. Ключ учитывает область доступа, метод, адрес, параметры фильтрации и страницу. Одинаковые запросы нескольких списков могут использовать один снимок, например GET `/resume`.
- Публичность кэша определяется условиями получения ответа, а не названием списка в меню. HTML публичного списка, полученный после входа и содержащий данные аккаунта, относится к приватному кэшу. Приватный HTML не записывать в публичный раздел.
- Приватный раздел принадлежит только текущему аккаунту; параллельные разделы нескольких аккаунтов не поддерживать. При выходе, истечении сессии или прямой смене аккаунта удалять приватный HTML. Публичный HTML и постеры сохранять. Сохранённую выдачу не использовать как подтверждение действующей авторизации. После перезапуска приватный HTML становится доступен после сетевого подтверждения устойчивого ID аккаунта; при неизвестном ID не читать и не записывать его.
- Существующие сроки и условия обновления сохранять: для «Сегодня» — текущий день, для остальных сохраняемых выдач и данных карточек — сутки; личные снимки получают тот же механизм хранения. Кэш не отменяет уже предусмотренное фоновое обновление и проверки сессии. Изменения отметок и истории инвалидируют соответствующие личные выдачи по действующим правилам.

### Нативные данные карточек в памяти

- Создать одно хранилище данных карточек на приложение, общее для всех списков и открытой карточки. Ключ — точный ID сезона Seasonvar, текущий `SeriesEntry.id`, а не номер сезона, название или ключ строки списка.
- Хранить нативные Kotlin-объекты, без JSON-строк, HTML-деревьев, элементов Compose и bitmap. В каждой записи разделять общие данные сезона и приватные данные только текущего аккаунта. Общие поля включают название, описание и справочные сведения; прогресс, отметки и прочие зависящие от сессии поля относятся к приватной части.
- Выдача после входа может дополнить и обновить общие поля. Приватные поля не переносятся в общую часть. Различать ещё не загруженное поле и подтверждённое пустое значение; краткая выдача списка не должна затирать более полные известные данные карточки отсутствующими полями.
- Размер задавать единственной служебной константой `CacheSettings.CARD_DATA_CAPACITY` в `data/settings/CacheSettings.kt`. Кэш, проверки и замеры используют её; пользовательскую настройку в интерфейс не добавлять.
- Ввести вытесняющий кэш с начальным лимитом 5000 сезонов. Активное окно удерживает нужные данные, давно неиспользуемые записи вытесняются первыми. Фактический расход памяти измерить на больших списках и сезонах с большим числом серий; постеры учитываются отдельно. Наличие записи в выдаче не запускает получение данных всех карточек.
- Готовые данные карточек сохранять при переключении списков и листании за пределами прежнего окна. При нехватке или истечении данных использовать подходящий HTML-кэш, затем сайт по прежним правилам. Вытеснение нативной записи само по себе не удаляет HTML.
- При выходе очищать приватную часть всех записей, разобранные личные списки и контекст аккаунта в интерфейсе. Общие данные карточек в памяти сохранять. При входе заполнять приватную часть для нового текущего аккаунта; историю приватных частей прежних аккаунтов не хранить.

### Общая загрузка и отрисовка

- Списки и открытая карточка читают данные одного сезона из общего хранилища. Готовность общих и приватных данных учитывать отдельно: доступное описание не ждёт обновления прогресса. Карточка приложения объединяет общие данные, актуальную приватную часть и контекст своей записи списка.
- Одновременные запросы одних данных объединять; нескольким потребителям предоставлять один результат. Сохранить общий лимит трёх загрузок описаний и фоновых изображений по ADR-0128.
- Окно движка управляет отрисовкой и дополнительной работой, а не сроком жизни общего кэша. При уходе из окна отменять только ненужные всем потребителям задачи, сохраняя уже полученные данные. Галочка предзагрузки сохраняет действие на видимую область и окно двух экранов.
- При выходе и смене аккаунта отменять приватные запросы и менять поколение кэша. Проверять поколение перед записью на диск и публикацией результата: поздний ответ не восстанавливает удалённую приватную часть и не применяется к новому аккаунту. Неуспешная попытка входа не заменяет действующую сессию.

## Альтернативы и последствия

Хранение только активного окна повторяет текущую проблему при возвращении к списку. Отдельные кэши на каждый список дублируют данные сезонов. Приватные части нескольких аккаунтов усложняют хранение ради редкого перелогина. Полный сброс памяти при выходе безопасен, но без необходимости удаляет общие описания; пользователь выбрал очистку только приватной части.

Общий кэш увеличивает расход памяти и требует явного разделения общих, приватных и относящихся к записи списка полей. Лимит 5000 — начальная настройка; замер описанной в инструкции разработки синтетической нагрузки дал около 30,42 МиБ на 5000 сезонов, отдельно от постеров. Это не верхняя граница для любых данных сайта. После завершения процесса нативное хранилище исчезает; HTML остаётся источником восстановления в пределах своего срока и области доступа.

## Проверка реализации

Проверить гостя и авторизованного пользователя, переходы А → Б → А, повторные записи одного сезона в истории, общий запрос нескольких потребителей, дополнение неполных данных и вытеснение. После выхода общие описания должны сохраниться, приватные данные и HTML — исчезнуть; поздние ответы не должны восстановить их. Проверить вход другого аккаунта, истечение сессии, перезапуск процесса, фоновое обновление, отметки и очистку истории. Для большого кэша измерить память и отзывчивость, сохраняя геометрию и фокус по ADR-0114; эмулятор не заменяет замер на Ugoos.

Проверено 2026-11-10: автономные тесты кэшей и личных списков, `make shared-card-cache-probe` с 33 000 записями и заполнением 5000 сезонов, `make ui-screens-probe`, сборка profile и реальное открытие карточки из личного списка в эмуляторе. Переходы А → Б → А сохраняют объект описания без повторного запроса, очистка приватных данных не удаляет общие, поздний приватный ответ отклоняется. Команды и условия замера памяти — в [инструкции разработки](../development.md#общий-движок-списков-и-предзагрузка).
