# ADR-0113: Короткие системные уведомления

Дата: 2026-11-07

Статус: Принято

## Контекст

Ошибки фонового обновления, выбора статуса и другие временные сообщения вставлялись между элементами экрана. Их появление сдвигало содержимое. Пользователь попросил короткие стандартные уведомления снизу и убрать предупреждение о несопоставленной серии.

## Решение

Системный текстовый Toast — стандартный способ показа всех коротких всплывающих уведомлений в проекте. Новые экраны и действия используют тот же общий механизм; отдельные строки, Snackbar и собственные всплывающие окна для таких сообщений не добавляются.

Временные сообщения показывать системным текстовым `Toast.LENGTH_SHORT` через общий `showShortMessage` и `ShortMessageEffect`: снизу поверх экрана, с автоматическим исчезновением через несколько секунд. Android определяет точное оформление, положение и длительность с учётом доступности. Не создавать для них строки в содержимом, точки фокуса и собственные окна. Новое уведомление отменяет предыдущее, чтобы сообщения не образовывали очередь.

В обработчиках действий показывать уведомление при каждой неудачной попытке. Для асинхронного состояния эффект реагирует на изменение текста, а обычная рекомпозиция не повторяет показ. Ошибки обновления непустого каталога, истории поиска, голосового поиска, входа, статусов списка, лент, обновлений приложения и синхронизации прогресса используют этот механизм.

Убрать предупреждение «Не удалось выбрать серию … в этой озвучке» полностью. Несопоставленный диапазон подборки не требует уведомления: кнопка «Выбрать серию» и переход к доступному списку по [ADR-0112](0112-episode-focus-without-selection.md) дают необходимое действие. Автоматически подменять выбор для воспроизведения по-прежнему нельзя.

Состояния пустого экрана, загрузки, недоступного контента и ошибки полной загрузки остаются в интерфейсе вместе с повтором. Подтверждения опасных действий и выбор параметров остаются диалогами. Это содержимое экрана и действия пользователя, а не временные уведомления.

## Альтернативы и последствия

Snackbar требует отдельного слоя и оформления для TV. Собственное окно может перехватывать управление. Строки в содержимом меняют геометрию; резервирование места оставляет пустые отступы. Системный Toast не двигает интерфейс, но допускает ограничение длины текста и исчезает автоматически. Возможность повторить операцию сохраняется в исходной кнопке.

В меню отметок больше нет пустых строк под ошибки. Это заменяет соответствующую часть [ADR-0088](0088-stable-mark-menu-loading.md), сохраняя постоянные пункты, блокировку повторных запросов и восстановление фокуса.
