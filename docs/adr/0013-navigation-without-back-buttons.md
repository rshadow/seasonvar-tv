# ADR-0013: Навигация с минимальным числом нажатий

Дата: 2026-11-01

Статус: Принято; возврат из описания уточнён в [ADR-0014](0014-restore-list-focus-after-details.md).

## Контекст

Меню разделов постоянно видно. Пользователь выбрал основной принцип навигации: как можно меньше нажатий. Для этого убираем экранные кнопки «Назад» и показываем раздел сразу при выборе его пункта стрелками.

## Решение

- Минимизировать число нажатий: не требовать отдельного подтверждения для простого просмотра раздела.
- Перемещение фокуса по меню сразу показывает выбранный раздел. Фокус остаётся в меню, чтобы продолжить листание без дополнительных переходов.
- OK или стрелка вправо переводят фокус в содержимое показанного раздела; в «О программе» он остаётся в меню. Клик по пункту меню также открывает его содержимое.
- Сохранять выбранную карточку и позицию ленты при переключении между разделами.
- На текущем этапе показывать все параметры на одном экране «Настройки». «Сеть» — текстовый подзаголовок группы, не кнопка и не отдельный экран. Заголовки групп не получают фокус; вход в настройки сразу фокусирует галочку обхода, затем стрелка вниз выбирает DNS.
- Убрать экранные кнопки «Назад» из «О программе», сетевых настроек и полного описания сериала.
- Менять раздел через меню. Стрелка влево из сетевых настроек переводит фокус на «Настройки» в меню.
- В «О программе» оставить фокус на пункте меню: на информационном экране нет действий.
- При открытии описания сразу фокусировать прокручиваемый текст.
- Смена элементов содержимого не должна случайно выбирать «Сегодня» или менять раздел. Отложенный перенос фокуса отменять, если пользователь уже перешёл в другой раздел.
- Esc на клавиатуре и «Назад» на пульте обрабатываются как одна команда возврата с одинаковым поведением.
- Для описания сериала действует уточнение [ADR-0014](0014-restore-list-focus-after-details.md): закрытие возвращает фокус в ленту на выбранную карточку. Остальные диалоги закрываются с возвратом в главное меню на пункт текущего раздела. Из содержимого раздела фокус также возвращается в меню. Если он уже в меню, одиночное нажатие оставляет его там; автоматически переключать раздел на «Сегодня» не нужно.
- Двойное быстрое нажатие команды «Назад» с интервалом до 500 мс закрывает приложение: первое нажатие выполняет обычный возврат, второе — выход. Это поведение одинаково для Esc и кнопки пульта. Удержание клавиши и её автоповтор не считаются двойным нажатием. Другая клавиша сбрасывает ожидание второго нажатия.
- При возврате в меню сохранять выбранную карточку и позицию ленты, чтобы следующее нажатие вправо или OK продолжало работу с того же места.

Это уточняет управление из [ADR-0006](0006-tv-navigation-and-content-layout.md) и расположение сетевых параметров из [ADR-0011](0011-network-bypass-setting.md) и [ADR-0012](0012-dns-provider-setting.md).

## Альтернативы и последствия

Отдельное подтверждение раздела через OK требует лишнего нажатия. Переключение по фокусу позволяет просматривать разделы только стрелками. Отдельная экранная кнопка возврата дублирует навигацию пульта и меню. После её удаления освобождается место, а дополнительные фокусируемые элементы не нужны. Мышью диалог можно закрыть кликом за его пределами, с пульта — кнопкой «Назад», с клавиатуры — Esc.

Для клавиатуры, пульта и диалогов используется общий обработчик возврата. Интервал двойного нажатия проверяется автономными JVM-тестами; фактическую доставку клавиш и восстановление фокуса проверяем в эмуляторе.

В Android TV API 34 проверены одиночные Esc/Back из настроек, карточки и диалога DNS, возврат в меню текущего раздела, сохранение выбранной карточки, удержание клавиши без выхода и выход по двойному нажатию из главного окна и диалогов. Двойной Esc из DNS повторён трижды для проверки перехода между окнами.

После включения прямой передачи кодов клавиш `-use-keycode-forwarding` и перезапуска эмулятора пользователь сообщил, что физический Esc работает. Параметры запуска закреплены в `toolchain.lock.json` и используются Makefile.
