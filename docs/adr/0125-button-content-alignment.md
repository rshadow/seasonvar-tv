# ADR-0125: Выравнивание содержимого общих кнопок

Дата: 2026-11-09

Статус: Принято

Уточняет [ADR-0023](0023-compact-rectangular-menu.md), [ADR-0111](0111-season-progress-below-controls.md) и [ADR-0119](0119-filter-reset-and-action-buttons.md). Формат строк настроек из [ADR-0015](0015-settings-item-format.md) сохраняется.

## Контекст

Растянутые кнопки нового диалога очистки снова показали текст слева. В общем `ThemeButton` параметр `contentAlignment` имел значение `null`: без явного аргумента текст размещался без контейнера выравнивания. В коммите `60e709c` центрирование добавили для серий как отдельную возможность; затем фильтры явно включили его по ADR-0119. Общий вариант по умолчанию не исправили, поэтому новые вызовы повторяли ошибку.

## Решение

- Обычная текстовая кнопка действия через `ThemeButton` по умолчанию центрирует подпись по обеим осям. Это относится к подтверждению, отмене, применению, сбросу, повтору и другим действиям, включая состояния загрузки и блокировки.
- Выравнивание задаётся общим компонентом; новый экран не должен отдельно включать центрирование или копировать разметку кнопки. У `contentAlignment` нет значения `null` и ветки без выравнивания.
- Компактная кнопка сохраняет размер по содержимому; заданные высота, ширина, `fillMaxWidth` и доля строки сохраняются. Центрирующий контейнер не должен растягивать компактную кнопку на всю доступную площадь. Естественную ширину рассчитывать по полной строке (`IntrinsicSize.Max`): минимальная intrinsic-ширина сжимает подпись из нескольких слов и вызывает многоточие.
- У навигационных пунктов и текстовых строк выбора подпись выравнивается по началу явно через `Alignment.CenterStart`. Строки с галочкой или зарезервированным местом под неё сохраняют общий левый столбец. Не центрировать заголовки, пояснения и содержимое настроек вместе с кнопками действий.
- Квадратные кнопки с иконками используют прежний `IconButton`: центрируется иконка, а подпись доступна средствам доступности.
- Регрессионная проверка в эмуляторе проверяет положение текста в растянутых и компактных кнопках, явное выравнивание навигации слева, строки с галочкой, размещение соседних кнопок и состояния диалога. Проверять сам текст внутри кнопки, а не только геометрию и фокус внешнего прямоугольника.

## Альтернативы и последствия

Явное центрирование в каждом новом диалоге уже приводило к повторению ошибки. Отдельные компоненты для каждого экрана дублировали бы стили и обработку пульта. Единое значение по умолчанию исправляет источник проблемы; исключения для навигации остаются видимыми в вызовах. Обязательное правило и команда проверки закрепляются в AGENTS.md.

## Проверка

Команды `make button-layout-probe`, `make ui-screens-probe`, `make mark-menu-probe` и `make player-probe` разделяют проверку геометрии общей кнопки, реальных экранов и диалогов, состояний меню отметок и реального видео. Для измерения текста используется Android Accessibility с координатами символов. Синтетические сценарии не меняют аккаунт; видеопроверка выполняется гостем. Результат автоматической проверки дополняется просмотром сохранённых кадров.
