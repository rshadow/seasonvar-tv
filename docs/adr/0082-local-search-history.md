# ADR-0082: Локальная история поисковых запросов

Дата: 2026-11-05

Статус: Принято

Уточняет [ADR-0024](0024-search-and-system-input.md): появляется дисковая история и меняется начальный фокус при её наличии. Протокол поиска, системный ввод и лента результатов сохраняются.

## Контекст

Пользователь выбрал пункт TODO «История поисковых запросов»: недавние запросы при открытии поиска, повтор одним нажатием и очистка. Поиск автоматически обновляется во время набора, поэтому сохранять каждый отправленный префикс нельзя.

## Решение

- Хранить на устройстве до 20 последних запросов, новые сверху. Убирать пробелы по краям и схлопывать повторяющиеся пробелы; считать регистр несущественным для дублей. Повтор перемещает запрос наверх и сохраняет последнее написание. Пустые строки и запросы длиннее 200 символов в историю не записывать; сам поиск этим не ограничивать.
- Сохранять явный поиск, распознанный голосовой запрос, запрос при открытии найденного сериала и последний завершённый автоматический поиск при уходе с экрана или в фон. Автоматические обновления при смене сети/аккаунта/отметок не добавляют историю. Промежуточные ответы во время набора не создают отдельные записи. Явный запрос сохраняется и при сетевой ошибке, чтобы его можно было повторить.
- Если история есть, при открытии поиска показывать «Недавние запросы» под полем и ставить фокус на первую строку. Клавиатура не перекрывает историю; поле можно выбрать для обычного системного ввода. При пустой истории сохранять прежнее открытие с фокусом в поле и системной клавиатурой. Текущий текст запроса остаётся в поле, выдача в памяти не очищается одним открытием истории. При стирании запроса история снова показывается под полем, сохраняя фокус ввода и открытую клавиатуру. Переход вниз к запросам выполняется только по действию пользователя.
- История — вертикальный ленивый список, одна точка фокуса на строку. OK немедленно повторяет запрос без задержки набора, скрывает историю и переводит фокус в результаты после их загрузки. При пустой выдаче или ошибке фокус находится на обновлении. Новый текст начинает обычный поиск. Возврат из сериала сохраняет выбор в ленте.
- Вверх из первой строки ведёт к полю; вправо — к текстовой кнопке «Очистить историю поиска», влево — к лупе. С кнопки очистки возвращать фокус на последнюю выбранную строку. Внизу списка фокус останавливается.
- Очистка удаляет только сохранённые запросы, оставляет текущий текст и выдачу. После очистки показывать пустое состояние и возвращать фокус в поле. Старые ожидающие операции и автоматическое обновление не должны вернуть очищенную историю. Новый явный поиск снова сохраняется.
- Использовать отдельные закрытые SharedPreferences search-history, чтение/запись и JSON выполнять вне потока интерфейса. Загружать один раз на процесс, порядок операций защищать mutex. Ошибка записи не выдаётся за успешное сохранение/очистку и не превращает успешный поиск в сетевую ошибку. Повреждённый JSON читается как пустая история.
- История общая для приложения на устройстве, доступна без входа и сохраняется между перезапусками. Её список отдельно никуда не отправляется, запросы не пишутся в логи. Повтор использует прежний запрос autocomplete.php к оригинальному сайту.
- Цвета, размеры строк, кнопок и отступы брать из общей темы. Надписи запросов выравнивать слева с обычным внутренним отступом, по вертикали — по центру полной области кнопки. Кнопка очистки имеет естественную ширину подписи с симметричными внутренними отступами и вертикальным центрированием. История использует интервалы между кнопками, без внешних отступов карточек; края строк и поля совпадают по правому краю. Не добавлять запросы к сайту ради показа истории или описаний скрытых результатов.

## Альтернативы

Запись каждого автоматического запроса засоряет историю частями слова. Только явная кнопка поиска не учитывает обычный сценарий выбора результата без подтверждения на клавиатуре. Синхронизация с аккаунтом потребовала бы отдельного подтверждённого протокола и не нужна для этой функции.

## Последствия

Популярный запрос повторяется одним OK. История ограничена по объёму и не меняет поведение сетевого поиска. Проверять нормализацию, дубли, лимит, перезапуск, очистку и гонки, независимость ошибок, начальный фокус, скрытую клавиатуру и возврат к результатам. Обычные команды — make check и make run-profile.
