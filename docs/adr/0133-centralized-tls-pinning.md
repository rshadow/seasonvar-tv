# ADR-0133: Централизованный TLS pinning

Дата: 2026-11-10

Статус: Принято

## Контекст

Приложение передаёт данные аккаунта Seasonvar и получает обновления с GitHub. Стандартная проверка TLS допускает любой системный доверенный центр. CodeQL сообщает об отсутствии certificate pinning. Нужно ограничить доверенные ключи без настройки в интерфейсе и без нарушения обновления сертификатов серверов.

## Решение

- Хранить SHA-256 SPKI публичных ключей и соответствие доменам в `data/settings/TlsPinSettings.kt`. Не загружать pins с сервера, не добавлять срок автоматического отключения и не предлагать обход ошибки пользователю.
- Закрепить ключи корневых центров проверенных цепочек: ISRG Root YR/YE для Seasonvar, его CDN `svstat.net` и `githubusercontent.com`; Sectigo E46/R46 для `github.com`; DigiCert G3/G2 для Quad9 DoH. Закрепляется любой из разрешённых ключей в проверенной цепочке; это не отпечаток короткоживущего сертификата сервера.
- Для перечисленных доменов и их одноуровневых поддоменов использовать один `CertificatePinner`. Строки доменов передавать в `Builder.add` явно, чтобы CodeQL распознавал настроенные доверенные домены. Для Quad9 достаточно точного имени `dns.quad9.net`.
- Подключать политику к общему транспорту сайта, входа, личных списков, записи отметок, плейлистов, постеров и Media3, включая DNS/DPI-варианты и производные клиенты с cookie. Отдельно подключать к независимым клиентам GitHub и DoH. Cookies Seasonvar не передавать GitHub.
- Проверять GitHub API, первоначальный адрес APK и каждый переход к `objects.githubusercontent.com` / `release-assets.githubusercontent.com`. Сохранять разрешённые домены, лимит переходов и проверку размера, SHA-256 и подписи APK.
- Сохранять системное доверие, проверку имени сервера и запрет перехода HTTPS → HTTP. Для приложения явно запретить cleartext traffic. Несовпадение pin завершает запрос ошибкой TLS, без повторения через клиент без pinning.
- Произвольные сторонние видеохосты из плейлистов сохраняют обычную проверку TLS: их ключи заранее неизвестны. Приложение не считает их частью закреплённых доменов Seasonvar. Ссылка «Проект на GitHub», открытая внешним браузером, использует транспорт браузера. Скрипты разработки и внешние `git`/`gh` не являются транспортом Android-приложения; загрузки инструментов дополнительно проверяются по закреплённым контрольным суммам.

## Альтернативы и последствия

Закрепление ключа сервера строже, но обновление его ключа третьей стороной отключит установленные приложения. Выбраны известные основные и резервные ключи удостоверяющих центров: выпуск нового сертификата или переход RSA ↔ EC внутри этих центров не требует смены pins. Другой доверенный центр, даже системный, не принимается. При смене центра потребуется обновить конфигурацию и выпустить приложение; резервные ключи не гарантируют доступность при произвольной смене поставщика TLS.

XML Network Security Config дублировал бы политику и не покрывал бы одинаково пользовательский TLS-транспорт DPI. Выбран штатный OkHttp `CertificatePinner`, который проверяет цепочку после обычной TLS-проверки. Публичные сертификаты для тестов не добавляются в доверенные центры приложения.

Проверки: положительные и отрицательные локальные TLS-сценарии, наследование политики всеми сетевыми конфигурациями, `make tls-pins-probe`, `make update-probe` и видимое воспроизведение через `make player-probe`. Источники и актуальные цепочки — в [описании доступа](../api/access.md#закрепление-ключей-tls-в-приложении).
