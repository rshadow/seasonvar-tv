# ADR-0099: Сохранять сессию при ошибке чтения хранилища

Дата: 2026-11-07

Статус: Принято

Уточняет восстановление входа из [ADR-0033](0033-account-and-resume.md). Не меняет протокол сайта, формат cookie и ключ релизной подписи.

## Контекст

`SessionManager.current()` перехватывал любое исключение через `runCatching`, очищал хранилище и запоминал гостевую сессию. Временная ошибка чтения или расшифровки могла уничтожить сохранённый вход. Исключение отмены также попадало в эту ветку. Неизвестное состояние ошибочно открывало доступ к обычному кэшу каталога как для гостя.

При чтении зашифрованного файла также допускалось создание нового ключа, если существующий не найден. Чтение не должно изменять ключи или сохранённые данные.

## Решение

- Чтение сессии не вызывает `SessionStore.clear()` и не записывает замену. Ошибочный или временно недоступный сохранённый файл остаётся на месте.
- `CancellationException` передаётся вызывающему коду без изменения. Другие исключения чтения передаются как `SessionStorageException` с исходной причиной; уже типизированное исключение не оборачивается повторно. Ошибки уровня `Error` не перехватываются как обычный сбой чтения.
- Инициализируем текущий cookie jar и признак приватной сессии только после успешного чтения. Не запоминаем гостевой jar после ошибки: следующая проверка снова читает хранилище и может восстановить исходный вход без пароля.
- `cacheToken()` при ошибке хранилища возвращает `null`, сохраняя запрет обычного кэша каталога при неизвестном состоянии аккаунта. Отмену он также передаёт дальше. Это позволяет безопасно пропустить чтение кэша до обработки ошибки, а не выбрасывать исключение в незавершённую подготовку экрана.
- Во время расшифровки используем только существующий ключ Android Keystore. Отсутствующий ключ даёт ошибку хранилища; новый разрешено создавать при сохранении сессии.
- Ошибка хранилища отображается отдельно от истёкшей сессии и неправильного пароля. В разделе «Аккаунт» для неё доступна существующая кнопка повторной проверки. Сообщение не требует заново входить после временного сбоя.
- Явный выход, подтверждённый гостевой ответ сайта и успешный новый вход сохраняют прежние правила очистки или замены сессии. Ошибка чтения сама по себе не доказывает, что серверная сессия истекла.
- Не выводим cookie, зашифрованный файл, ключи или причины криптографических исключений в интерфейс и диагностику пользователя.

## Альтернативы

- Исключить только отмену, оставив очистку при остальных ошибках: временная ошибка хранилища всё ещё уничтожала бы вход.
- При ошибке запомнить гостя без удаления файла: повторная проверка в том же процессе не прочитает сохранённый вход и состояние будет ошибочно считаться публичным.
- Автоматически пересоздать ключ или сбросить файл: лишает возможности повторить чтение и не подтверждает истечение сессии на сайте.

## Последствия и проверка

Неисправный файл может сохраняться до явного нового входа или выхода. Это безопаснее автоматического удаления: временная недоступность больше не уничтожает восстановимые данные. Если ошибка устраняется, повторная проверка восстанавливает вход без отправки логина и пароля.

Пять регрессионных тестов сначала упали на прежней реализации. Они проверяют сохранение cookie при ошибке чтения и расшифровки, неизменную передачу отмены, отсутствие гостевой подмены, запрет публичного кэша и возможность повторить чтение. Дополнительные тесты репозитория и модели экрана проверяют восстановление после сбоя без нового входа, отсутствие очистки и отличимое состояние ошибки хранилища. Все данные синтетические; реальные учётные записи и сессии для проверки не используются.
