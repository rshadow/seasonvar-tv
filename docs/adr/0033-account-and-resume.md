# ADR-0033: Аккаунт Seasonvar и личный список «На чём остановились»

Дата: 2026-11-03

Статус: Принято. Источник личного списка уточнён в [ADR-0034](0034-resume-current-markup.md).

[ADR-0129](0129-shared-card-data-cache.md) пересматривает ограничение дискового кэша гостевыми ответами: принят отдельный приватный HTML-кэш с очисткой при выходе. Решение реализовано; ниже сохранены первоначальные правила.

## Контекст

Пользователь попросил вход по логину/паролю, кнопку человека рядом с поиском, аватар после входа и личный список для демонстрации авторизации. Ранее работали только публичные каталоги и локальная позиция просмотра по ADR-0031.

Анонимно проверены форма `GET /?mod=login` с полями `login`/`password` и страница `/resume`. Гостю `/resume` тоже возвращает HTTP 200 и пустые личные разделы. Договорённости из открытого клиента проверяются отдельно от реального входа, см. [web-api.md](../api/web-api.md).

## Решение

- В верхней строке меню расположены две одинаковые квадратные кнопки: поиск слева, аккаунт справа. Стиль, размеры и скругления берутся из темы. У гостя — иконка человека, у вошедшего пользователя — аватар сайта. При отсутствии или ошибке загрузки аватара остаётся иконка человека. Аватар не кешируется на диск.
- По нажатию открывается страница «Аккаунт» справа от меню. У гостя есть логин/e-mail, скрытый пароль и «Войти»; используется системная клавиатура Android. На форме работает D-pad, Next/Done клавиатуры, Esc/«Назад». Первый возврат закрывает клавиатуру, следующий возвращает фокус на кнопку аккаунта. После входа страница показывает имя и действие выхода.
- Пароль живёт только в памяти формы/запроса, очищается при отправке и закрытии формы, не попадает в сохранённое состояние, файлы, Intent, логи или аналитику. Логин также не сохраняется.
- Вход идёт непосредственно на оригинальный HTTPS-сайт, с выбранными DNS и обходом. Отдельная временная cookie-сессия получает форму, отправляет POST, затем читает `/resume`. Только признак своего аккаунта в последнем ответе подтверждает вход. Ответ 200 или тело POST не считаются подтверждением. Неуспешная попытка не подменяет текущую сессию.
- HTTP-клиент хранит cookie с исходными domain/path/hostOnly/secure/expiry. Cookie разрешены только оригинальным доменам `seasonvar.ru` и `www.seasonvar.ru` по HTTPS. На CDN и произвольные внешние домены они не отправляются. Медиа-транспорт остаётся без cookie, а страницы сезона и плейлист используют сессию сайта.
- Подтверждённая сессия сохраняется в приватных SharedPreferences `account-session` одним AES-GCM блоком. Ключ создаётся Android Keystore, пароль не нужен для следующего запуска. Криптография и диск работают вне UI-потока; резервное копирование приложения выключено. Источник — [Android Keystore](https://developer.android.com/privacy-and-security/keystore).
- При старте сохранённая сессия проверяется на сайте. Сетевая ошибка не удаляет cookie: можно повторить проверку. Подтверждённый гостевой ответ очищает истёкшую сессию и предлагает войти снова. Истёкшая сессия отличается от пустого списка.
- «На чём остановились» появляется после «Сегодня» только после подтверждения аккаунта. Успешный вход переводит в этот раздел. Список читается из `div.pgs-marks-bn` на `/resume` в порядке сайта; другие вкладки личных списков не смешиваются с ним. Карточки, описание, фокус и возврат используют общую механику каталога. Кнопка обновления повторно запрашивает список.
- Личный список и профиль хранятся в памяти. Авторизованные HTML-ответы не читаются из общего публичного кэша и не записываются туда. Версия сессии запрещает запоздалым ответам прежнего аккаунта менять список или публичный кэш. При смене аккаунта очищаются личные выбор/позиция и данные экранов; публичный дисковый кэш остаётся доступным гостю.
- Выход сразу удаляет локальные cookie и личное состояние, затем пытается завершить сессию на сайте через `GET /?mod=logout`. Сетевой сбой не восстанавливает локальный вход. Запоздалый `Set-Cookie` прежнего запроса не может заново сохранить удалённую сессию.

```text
[ Поиск ][ Человек / аватар ]
Сегодня                       Аккаунт гостя:
На чём остановились *         Логин / e-mail [____________]
Обновления                    Пароль        [••••••••••••]
…                             [ Войти ]

* Только после подтверждения входа; справа — обычная лента каталога.
```

## Границы этапа и альтернативы

Веб-форма в WebView позволила бы показать дополнительные способы входа сайта, но потребовала бы отдельной клавиатурной навигации и обмена cookie с нативным клиентом. Нативная форма соответствует текущим двум полям сайта. CAPTCHA, соцсети и двухфакторный вход пока не реализованы.

В этот этап входят чтение личного списка и сессия. Автоматическая запись отметок в аккаунт и восстановление точного времени с сайта не добавляются: их контракт ещё не проверен. Локальная позиция из ADR-0031 остаётся отдельной функцией устройства. Открытие карточки из личного списка не создаёт новых отметок аккаунта.

## Проверка

Автономные тесты проверяют профиль/аватар, порядок и границы личного списка, гостевую/пустую/невалидную страницу, подтверждение входа повторным запросом, восстановление без пароля, истечение сессии и выход без сети. Отдельно проверяются область cookie, сериализация атрибутов, защита от запоздалого ответа и изоляция дискового кэша. Реальный вход и аватар требуют проверки пользователем на его устройстве; пароль не передаётся агенту.

Прошли `make check` (131 JVM-тест, 17 Python-тестов и Lint) и `make build-profile` с R8. В эмуляторе проверены форма с системной IME, очистка пароля и реальный отказ сайта для вымышленной учётной записи. Положительный сценарий на аккаунте пользователя пока ожидает подтверждения.

В profile-сборке эмулятора проверен путь с «Сегодня» вверх к поиску, вправо к аккаунту, открытие формы и переход вниз в пароль после закрытия IME. Ввод попадает в скрытое поле пароля; Esc возвращает фокус на кнопку аккаунта.

2026-11-03 пользователь подтвердил вход на Ugoos. Агент проверил наличие аккаунта и восстановление сессии после обновления приложения без повторного пароля. Проверка обнаружила отличие реальной разметки списка; оно описано и исправлено в ADR-0034.

Ошибки чтения локального хранилища и отмена восстановления уточнены в [ADR-0099](0099-preserve-session-on-storage-failure.md): они не удаляют cookie и позволяют повторить проверку входа.
