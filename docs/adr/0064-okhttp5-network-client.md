# ADR-0064: Сетевой клиент OkHttp 5

Дата: 2026-11-04

Статус: Принято

## Контекст

Обновление Dependabot в PR №2 переводит HTTP-клиент и DNS-over-HTTPS с OkHttp 4.12.0 на 5.5.1. Android-вариант требует compile SDK 37; совместимый инструментарий принят в ADR-0061. Транспорт используется сайтом, постерами и Media3, поэтому успешной компиляции недостаточно для проверки просмотра.

## Решение

Обновлять `okhttp` и `okhttp-dnsoverhttps` совместно до 5.5.1. Android-вариант основного клиента выбирается из официальных Gradle-метаданных; JRE-вариант не подменяет его в APK. Закрепить проверяемые артефакты OkHttp и транзитивного Okio 3.18.1 в `toolchain.lock.json`.

Сохранить независимый выбор DNS и обхода из ADR-0011/0012, проверку сертификатов и имени узла, ограничения редиректов и отдельный клиент Media3 без общего таймаута на полное видео. Новые сетевые возможности библиотеки не включать автоматически вместо существующего пользовательского выбора.

Перед слиянием выполнить `make check` (включая все комбинации DNS/обхода), `make codeql-build`, `make build-profile` и обязательные GitHub-проверки. В эмуляторе проверить загрузку каталога и реальное видео: смену кадров, паузу, перемотку, переход серии и возврат. Проверки не используют личные cookie как тестовые данные.

## Альтернативы

- Оставить OkHttp 4. Откладывает запрошенное обновление и исправления транспорта.
- Заменить Android-вариант на JVM для старого SDK. Обходит требования через смену платформенного варианта вместо согласованного обновления инструментов.

## Последствия

Сетевые настройки и протокол сайта сохраняются. При будущих обновлениях транспорта требуется повторная проверка воспроизведения и TLS, включая работу пользовательского обхода.
