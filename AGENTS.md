# Правила работы над Seasonvar для Android TV

## Назначение проекта

Здесь разрабатывается клиент оригинального `seasonvar.ru` для Android TV, Google TV и Android-приставок с пультом. Целевое устройство пользователя — Ugoos X5M с Android 14.

Главный сценарий: войти в свою учётку Seasonvar, найти сериал, выбрать сезон/озвучку/серию, посмотреть видео и продолжить просмотр с сохранённой отметки.

В корневом [README.md](README.md) отражать текущее состояние проекта. Не представлять запланированные функции или примеры из сторонних исходников как уже работающий код.

## Перед изменениями

- Прочитать [docs/api/README.md](docs/api/README.md) и относящийся к задаче раздел документации.
- Различать старое API с ключом, запросы оригинального сайта и собственные маршруты сторонних прокси.
- Проверить текущие файлы и сохранить изменения пользователя. Не перезаписывать чужую работу.
- Выполнять запрошенную задачу до проверяемого результата; не начинать разработку приложения, если запрос касается только документации.

## Скиллы проекта

Любые скиллы, подключаемые для проекта, устанавливать локально в [.agents/skills](.agents/skills/README.md), согласно [ADR-0004](docs/adr/0004-project-local-skills.md). Не устанавливать проектные скиллы глобально. Источники, версии и текущий набор вести в README этого каталога.

Текущие используемые скиллы:

- [android-cli](.agents/skills/android-cli/SKILL.md) — применять при настройке SDK, работе с эмулятором, сборке, запуске и отладке приложения.
- [jetpack-compose-performance](.agents/skills/jetpack-compose-performance/SKILL.md) — применять при анализе производительности Compose и устранении задержек интерфейса.
- [leanback-to-compose-tv-migration](.agents/skills/leanback-to-compose-tv-migration/SKILL.md) — применять при миграции существующего Leanback-кода. Не добавлять Leanback в новый проект ради этого скилла.
- Читать только относящиеся к текущей задаче инструкции и ссылки скилла. Требования пользователя и принятые ADR сохраняют приоритет.

## Принятые решения

- Все принятые решения о проекте записывать в [docs/adr](docs/adr/README.md), по одной записи на решение.
- Перед работой учитывать действующие ADR. Новое принятое решение сопровождать записью с контекстом, альтернативами и последствиями и добавлять в реестр.
- Отличать предложения от принятых решений. При пересмотре создавать новый ADR и связывать его с прежним, сохраняя историю.

## Проверка протокола Seasonvar

- Наличие эндпоинта в стороннем коде подтверждает реализацию клиента, но не актуальную работоспособность сервиса.
- Для новых сведений сохранять источник, дату и статус: исходник, проверка агентом или ответ пользователя.
- Обновлять [docs/api](docs/api/README.md) при установлении или изменении контракта. Примеры очищать от секретов и персональных данных.
- Точный путь страницы брать из ответа сайта. Различать ID сериала, ID сезона, ID озвучки, ID контента и номер эпизода.
- Учитывать HTML в текстовых полях JSON, строковые ID и параллельные массивы. Реальный пример поиска находится в [docs/api/examples](docs/api/examples/autocomplete-game-of-thrones.json).
- Сохранять cookie в рамках их domain/path/expiry. Не передавать сессию Seasonvar произвольным внешним доменам.
- Не объявлять пустой ответ признаком отсутствия закладок, пока не проверена авторизация.
- Для записи отметки проверять не только ответ POST, но и последующее чтение состояния.
- Не заменять оригинальный сайт одноимёнными клонами и чужими каталогами без явного изменения задачи пользователем.

## ТВ-интерфейс

- Пункты настроек оформлять по [ADR-0015](docs/adr/0015-settings-item-format.md): название и пояснение слева, галочка или выбранное значение справа, одна точка фокуса на строку. Опции выбирать в диалоге с радиокнопками.

- Общую палитру, интервалы и размеры компонентов хранить в [themes.xml](app/src/main/res/values/themes.xml); в Compose использовать MaterialTheme и [SeasonvarTheme](app/src/main/java/ru/seasonvar/tv/ui/theme/SeasonvarTheme.kt) согласно [ADR-0008](docs/adr/0008-centralized-ui-theme.md). Новые экраны не должны дублировать эти значения.

- Все основные действия доступны с D-pad, OK и «Назад». Сенсорный экран и мышь не должны быть обязательными.
- У каждого интерактивного элемента есть заметный фокус и предсказуемый переход к соседним элементам.
- Размер текста, отступы и плотность карточек рассчитаны на чтение с дивана.
- Сохранять позицию списка и фокус при возврате из карточки или плеера.
- Явно показывать загрузку, ошибку, пустой результат и истёкшую сессию.
- Проверять паузу, перемотку, возврат из плеера и продолжение просмотра пультом.
- Не считать WebView с веб-плеером подтверждением наличия нативного видеопотока.

## Реализация и проверка

- Все штатные команды подготовки инструментов, загрузки зависимостей, сборки, тестирования, запуска и отладки фиксировать в Makefile согласно [ADR-0005](docs/adr/0005-reproducible-local-development.md). Не оставлять необходимые команды только в переписке.
- При изменении инструментария обновлять toolchain.lock.json и [docs/development.md](docs/development.md).

- Модель карточки любого списка — `SeriesEntry` и вложенный `EntrySelection` в [CatalogModels.kt](app/src/main/java/ru/seasonvar/tv/data/CatalogModels.kt), согласно [ADR-0041](docs/adr/0041-shared-catalog-entry.md). Парсеры заранее заполняют известные поля; интерфейс не извлекает параметры из подписей. Общий выбор при открытии следует [ADR-0040](docs/adr/0040-details-entry-context.md).
- Использовать принятый стек Kotlin + Compose for TV + Media3 ExoPlayer согласно [ADR-0002](docs/adr/0002-native-kotlin-compose-media3.md). Протокол сайта и парсеры отделять от интерфейса и плеера.
- Соблюдать [ADR-0003](docs/adr/0003-performance-principles.md): каталог из кэша с фоновым обновлением, кеширование постеров под размер карточек, фоновая обработка данных, ленивые списки, восстановление позиции и фокуса, управление ресурсами плеера и проверка release-сборки на Ugoos.
- Совместимые версии зависимостей и SDK выбирать при реализации по официальным требованиям; выбор стека уже зафиксирован в ADR.
- При переключении разделов сохранять отзывчивость меню по [ADR-0025](docs/adr/0025-responsive-section-switching.md): не пересоздавать всё дерево каталога, распределять появление карточек по кадрам, сохранять раздельные ключи фокуса и позиции. Проверять на приставке через `make run-profile` и `make profile-navigation`; debug и эмулятор не заменяют замер производительности.
- При появлении проекта добавить в README фактические команды сборки и проверки. Не указывать вымышленные команды и не сообщать о незапущенных тестах как о пройденных.
- Использовать сохранённые обезличенные ответы для проверки парсеров; автоматические тесты не должны зависеть от личного аккаунта или доступности сайта.
- Сетевые ошибки, HTTP-ошибки, невалидную разметку и ошибки авторизации различать.
- Перед установкой APK определять устройство через `adb devices -l`; не хардкодить IP приставки. Установку и изменение настроек устройства выполнять в рамках запроса пользователя.
- Проверка клиентского кода не заменяет проверку запуска, воспроизведения и управления на телевизоре.
- После любых изменений плеера обязательно запускать реальное видео и визуально проверять видимые кадры, их смену во времени, паузу, перемотку и возврат. При изменении переходов проверять изображение после смены серии. События `STATE_READY` и `first-frame` сами по себе не подтверждают видимое изображение; снимок с чёрным экраном не считать успешной проверкой. Основная проверка — в локальном эмуляторе. Приставку использовать в рамках запроса пользователя; просьба её не трогать имеет приоритет.

## Релизы GitHub

- Описание релиза — короткий список предложений для пользователей, максимально кратко, без технических подробностей; около 10 слов в пункте — ориентир, а не жёсткий лимит. Хранить в `docs/releases/<version>.md` по [ADR-0069](docs/adr/0069-short-release-notes.md).

- Создавать и отправлять релизный тег **только по явной команде пользователя**, согласно [ADR-0053](docs/adr/0053-explicit-release-tag-command.md).
- Просьба закоммитить, отправить изменения, настроить или проверить автосборку не разрешает создавать тег или выпускать новую версию. Для проверки CI использовать запуск по ветке без релизного тега.
- После явно запрошенной отправки тега GitHub Actions автоматически собирает и публикует релиз по ADR-0050.

## Секреты и сетевой доступ

- Для локальных инструментов источник секретов — `~/secrets.env`. Исключение по решению пользователя: секреты Seasonvar, включая ключ и пароли Android-подписи, хранятся в корневом `secrets.env` проекта, исключённом из Git; см. [ADR-0049](docs/adr/0049-project-local-secrets.md). Не искать токены в других файлах, Keychain, истории, конфигурациях или окружении целиком.
- Не добавлять секреты в исходники, документацию, команды-примеры или фикстуры. Единственный разрешённый файл секретов в проекте — корневой `secrets.env`; он не должен попадать в Git.
- Не выводить пароли, токены, cookie и подписанные видеоссылки в stdout, логи или ответы чата. Проверки наличия должны выводить только булево значение.
- Не использовать `env`, `printenv`, дампы `os.environ` и команды, печатающие содержимое файла секретов.
- Не передавать пароль или ключ в query-параметрах URL. В примерах использовать заполнители.
- Не собирать широкие логи устройства, пока пользователь вводит учётные данные; ограничивать диагностику необходимыми событиями.
- Не отключать проверку TLS ради успешного запроса. Страницу блокировки или редирект оператора не считать ответом Seasonvar.
- При проблемах DNS разрешено проверить имя через Quad9. По возможности использовать DNS-over-HTTPS и сохранять проверку TLS; системный DNS менять только по явному запросу.
- Временные файлы размещать в каталоге текущей сессии, не в проекте. Не сохранять туда секреты.

## Безопасность GitHub и защищённые ветки

- Учитывать [ADR-0058](docs/adr/0058-github-security-checks.md) и [инструкцию настройки](docs/github-security.md). После импорта правил main изменения проходят через PR с обязательными проверками; не обходить защиту прямым push или снятием правил. Наличие JSON-файлов само по себе не подтверждает включение правил на сервере.
- Workflow публикации графа зависимостей не должен делать checkout или исполнять код PR: он использует write-доступ только для отправки готовых данных. Сохранять разделение прав и закрепление Actions полными SHA.
- Релизный тег по-прежнему разрешён только по явной команде пользователя. Настройка проверок, PR и их слияние не разрешают выпуск релиза.

- Готовые PR владельца могут автоматически сливаться после всех проверок по [ADR-0059](docs/adr/0059-owner-pull-request-auto-merge.md). До обязательной визуальной проверки изменений плеера держать PR в Draft. PR Dependabot и других авторов не включать в автослияние.
