# Правила работы над Seasonvar для Android TV

## Назначение проекта

Здесь разрабатывается клиент оригинального `seasonvar.ru` для Android TV, Google TV и Android-приставок с пультом. Целевое устройство пользователя — Ugoos X5M с Android 14.

Главный сценарий: войти в свою учётку Seasonvar, найти сериал, выбрать сезон/озвучку/серию, посмотреть видео и продолжить просмотр с сохранённой отметки.

В корневом [README.md](README.md) отражать текущее состояние проекта. Не представлять запланированные функции или примеры из сторонних исходников как уже работающий код.

## Перед изменениями

- Прочитать [docs/api/README.md](docs/api/README.md) и относящийся к задаче раздел документации.
- Различать старое API с ключом, запросы оригинального сайта и собственные маршруты сторонних прокси.
- Проверить текущие файлы и сохранить изменения пользователя. Не перезаписывать чужую работу.
- Выполнять запрошенную задачу до проверяемого результата; не начинать разработку приложения, если запрос касается только документации.

## Принятые решения

- Все принятые решения о проекте записывать в [docs/adr](docs/adr/README.md), по одной записи на решение.
- Перед работой учитывать действующие ADR. Новое принятое решение сопровождать записью с контекстом, альтернативами и последствиями и добавлять в реестр.
- Отличать предложения от принятых решений. При пересмотре создавать новый ADR и связывать его с прежним, сохраняя историю.

## Проверка протокола Seasonvar

- Наличие эндпоинта в стороннем коде подтверждает реализацию клиента, но не актуальную работоспособность сервиса.
- Для новых сведений сохранять источник, дату и статус: исходник, проверка агентом или ответ пользователя.
- Обновлять [docs/api](docs/api/README.md) при установлении или изменении контракта. Примеры очищать от секретов и персональных данных.
- Точный путь страницы брать из ответа сайта. Различать ID сериала, ID сезона, ID озвучки, ID контента и номер эпизода.
- Учитывать HTML в текстовых полях JSON, строковые ID и параллельные массивы. Реальный пример поиска находится в [docs/api/examples](docs/api/examples/autocomplete-game-of-thrones.json).
- Сохранять cookie в рамках их domain/path/expiry. Не передавать сессию Seasonvar произвольным внешним доменам.
- Не объявлять пустой ответ признаком отсутствия закладок, пока не проверена авторизация.
- Для записи отметки проверять не только ответ POST, но и последующее чтение состояния.
- Не заменять оригинальный сайт одноимёнными клонами и чужими каталогами без явного изменения задачи пользователем.

## ТВ-интерфейс

- Все основные действия доступны с D-pad, OK и «Назад». Сенсорный экран и мышь не должны быть обязательными.
- У каждого интерактивного элемента есть заметный фокус и предсказуемый переход к соседним элементам.
- Размер текста, отступы и плотность карточек рассчитаны на чтение с дивана.
- Сохранять позицию списка и фокус при возврате из карточки или плеера.
- Явно показывать загрузку, ошибку, пустой результат и истёкшую сессию.
- Проверять паузу, перемотку, возврат из плеера и продолжение просмотра пультом.
- Не считать WebView с веб-плеером подтверждением наличия нативного видеопотока.

## Реализация и проверка

- Предпочитать нативный Android-клиент на Kotlin. Протокол сайта и парсеры отделять от интерфейса и плеера.
- Не фиксировать стек UI, версии зависимостей и SDK по памяти: выбирать их при реализации, проверяя официальные требования совместимости.
- При появлении проекта добавить в README фактические команды сборки и проверки. Не указывать вымышленные команды и не сообщать о незапущенных тестах как о пройденных.
- Использовать сохранённые обезличенные ответы для проверки парсеров; автоматические тесты не должны зависеть от личного аккаунта или доступности сайта.
- Сетевые ошибки, HTTP-ошибки, невалидную разметку и ошибки авторизации различать.
- Перед установкой APK определять устройство через `adb devices -l`; не хардкодить IP приставки. Установку и изменение настроек устройства выполнять в рамках запроса пользователя.
- Проверка клиентского кода не заменяет проверку запуска, воспроизведения и управления на телевизоре.

## Секреты и сетевой доступ

- Для локальных инструментов единственный источник секретов — `~/secrets.env`. Не искать токены в других файлах, Keychain, истории, конфигурациях или окружении целиком.
- Не добавлять секреты в исходники, документацию, команды-примеры, фикстуры или новые `.env` в проекте.
- Не выводить пароли, токены, cookie и подписанные видеоссылки в stdout, логи или ответы чата. Проверки наличия должны выводить только булево значение.
- Не использовать `env`, `printenv`, дампы `os.environ` и команды, печатающие содержимое файла секретов.
- Не передавать пароль или ключ в query-параметрах URL. В примерах использовать заполнители.
- Не собирать широкие логи устройства, пока пользователь вводит учётные данные; ограничивать диагностику необходимыми событиями.
- Не отключать проверку TLS ради успешного запроса. Страницу блокировки или редирект оператора не считать ответом Seasonvar.
- При проблемах DNS разрешено проверить имя через Quad9. По возможности использовать DNS-over-HTTPS и сохранять проверку TLS; системный DNS менять только по явному запросу.
- Временные файлы размещать в каталоге текущей сессии, не в проекте. Не сохранять туда секреты.
